## Summary

The problem (verbatim from the recovered page): "Is there a finite set of unit line
segments (rotated and translated copies of $(0,1)$) in the unit square, no two of which
intersect, which are maximal with respect to this property? Is there a region $R$ with a
maximal set of disjoint unit line segments that is countably infinite?" — a question of
Erdős and Tóth [Er87b, p.173], status **PROVED (LEAN)** ("solved in the affirmative and
the proof verified in Lean", \$10 prize). The first question was answered yes by Danzer
(Erdős paid him the \$10); Alexeev proved in the site comments that the unit square
itself admits a countably infinite maximal set. The Lean file encodes open unit segments
as pairs (basepoint, unit direction) with point set $\{p + t\,d : 0 < t < 1\}$ in
`EuclideanSpace ℝ (Fin 2)`, defines a four-clause maximal-pairwise-disjoint-family
predicate, and asserts (a) a finite such family exists in the closed unit square and
(b) a countably infinite such family exists in the unit square. Read back independently,
(a) is exactly the yes-direction of the first question and (b) is Alexeev's form of the
second — the right choice, since the literal "∃ region" reading over arbitrary subsets
of the plane is degenerately true (see A1). No semantic defects; the findings are
scholarship-level (a module docstring with the [Er87b] definition and page remarks was
dropped in a session rewrite — restored by this review's fix).

## A. Semantic fidelity

Line numbers refer to the post-fix file; pre-fix numbers in parentheses where they
differ (the fix inserted a 44-line module docstring after the imports).

**A1. Statement fidelity — pass (source-verified).**

- Independent back-translation of `erdos_problem_1071a` (line 86, pre-fix 43): "there
  is a family $S$ of (basepoint, direction) pairs, finite, such that all directions are
  unit vectors, every open segment $\{p+td : 0<t<1\}$ lies in the closed unit square,
  distinct members have disjoint open segments, and every open unit segment contained
  in the square meets some member." This is precisely "a finite set of open unit
  segments in the unit square, no two of which intersect, maximal with respect to this
  property" — the yes-direction of the first question, which is the solved direction
  (Danzer).
- `OpenUnitSegment p d` with `‖d‖ = 1`: the map $t \mapsto p + t\,d$ is an isometry of
  $(0,1)$ onto the segment (in the Euclidean metric of `EuclideanSpace ℝ (Fin 2)`), so
  the point set is exactly a rotated and translated copy of the open interval $(0,1)$ —
  matching the source's parenthetical definition. Endpoints $p$ and $p+d$ are excluded,
  as the source's "$(0,1)$" requires; two segments sharing only an endpoint therefore do
  not "intersect", which is the intended reading for the open-segment question (the
  closed-$[0,1]$, touch-at-endpoints variant is a separate further question in [Er87b],
  see B2).
- Maximality clause (4) (lines 74–75, pre-fix 31–32) quantifies over *all* unit
  segments contained in $R$, including members of $S$ themselves. This is harmless and
  exactly equivalent to inclusion-maximality: each member meets itself (segments are
  nonempty — take $t = 1/2$), and if some unit segment in $R$ were disjoint from every
  member, the family could be properly enlarged, violating (4); conversely if (4) holds,
  adding any new pair to $S$ breaks pairwise disjointness (3). Term-by-term correct.
- Representation redundancy checked: each geometric segment has exactly two encodings,
  $(p, d)$ and $(p+d, -d)$. Clause (3) (distinct *pairs* have disjoint point sets)
  forbids $S$ from containing both encodings of one segment (equal nonempty sets are
  not disjoint), so on any admissible $S$ the pair-to-segment map is injective and
  `S.Finite` / `S.Countable ∧ S.Infinite` measure the *geometric* family's cardinality
  exactly. No cardinality distortion.
- `erdos_problem_1071b` (line 100, pre-fix 57): asserts a countably infinite maximal
  family **in the unit square** — Alexeev's form, strictly stronger than the source's
  literal "is there a region $R$" phrasing. This instantiation is not merely
  acceptable but necessary for a substantive statement: with "region" read as an
  arbitrary `Set (EuclideanSpace ℝ (Fin 2))`, the literal `∃ R, ∃ S, …` form is
  **degenerately true** — take $R$ to be the union of countably many pairwise
  far-separated open unit segments (e.g. from $(3n,0)$ to $(3n+1,0)$); any unit segment
  contained in $R$ is connected, hence lies in a single separated component, hence
  *equals* that component (an open length-1 subsegment of an open length-1 segment),
  so the family of components is maximal and countably infinite. "Region" informally
  means a connected planar domain, which has no canonical Lean rendering; pinning $R$
  to the unit square is the page-confirmed solved statement. (The superseded
  2026-02-22 draft of this file *did* use the degenerate `∃ R` form — see Part D.) The
  choice is now documented in the module docstring (fix 1).
- Not vacuous / not trivially false: the empty family fails clause (4) since unit
  segments exist in the unit square (e.g. the open bottom edge, $p = (0,0)$,
  $d = (1,0)$); uncountable maximal families exist (all vertical segments
  $\{x\}\times(0,1)$ plus the two horizontal open edges), so `S.Countable` in (b) is a
  genuine constraint, and finiteness in (a) is Danzer's nontrivial theorem.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction, no division, no `Finset.range`, no filter/liminf encodings, no
  `StrictMono` anywhere — the statements are purely set-theoretic over ℝ². None of the
  trap classes can arise.
- `EuclideanSpace ℝ (Fin 2)` carries the L² norm, so `‖pd.2‖ = 1` is Euclidean unit
  length — the geometrically correct choice (a bare `ℝ × ℝ` would have given the sup
  norm; the superseded draft avoided that pitfall differently, via an explicit
  squared-distance predicate).
- `Disjoint` on `Set` is `s ∩ t ⊆ ∅`, i.e. genuine set disjointness; `(… ∩ …).Nonempty`
  in clause (4) is its exact complement for the intended reading.
- Strict inequalities `0 < t ∧ t < 1` give the open segment (endpoints excluded) —
  matches "$(0,1)$" exactly. The degenerate direction $d = 0$ (point set would collapse
  to $\{p\}$) is excluded by `‖d‖ = 1`.
- `S.Countable ∧ S.Infinite` is the standard, correct encoding of "countably infinite".

**A3. Definitions — pass.**

- `OpenUnitSegment` (line 53, pre-fix 10) matches its docstring
  $\{p + t\,d \mid 0 < t < 1\}$ exactly. `UnitSquare` (line 57, pre-fix 14) is the
  closed square $[0,1]^2$ via `∀ i, 0 ≤ x i ∧ x i ≤ 1` — the standard reading of "in
  the unit square" (and the same encoding the upstream corpus uses, cf. its 1124
  `unitSquare`). `IsMaximalDisjointFamily` (line 67, pre-fix 24) has exactly the four
  clauses its docstring enumerates, in order.
- No `sorry` in any `def`; the only `sorry`s are the two theorem proof bodies.
- No drift between definitions and theorem usage: both theorems apply the predicate to
  `UnitSquare` with the same pair encoding.

**A4. Question form and answer polarity — pass for raw style.**

  (no `answer()` elaborator exists in this repo); the pipeline instructions state that
  direct-assertion form for a solved problem is acceptable raw style *if the polarity is

  theorem docstrings (and, post-fix, in the module docstring), so no information is
