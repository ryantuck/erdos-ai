## Summary

The problem (recovered verbatim from the archived page): "For any prime $p$, let
$f(p)$ be the least integer such that $f(p)!+1\equiv 0\pmod{p}$. Is it true that there
are infinitely many $p$ for which $f(p)=p-1$? Is it true that $f(p)/p\to 0$ for almost
all $p$?" Both questions were formulated by Erdős, Hardy, and Subbarao [HaSu02] and
are OPEN. The Lean file defines $f(p)$ via `Nat.find` on the (Wilson-guaranteed)
existence of a positive $m$ with $p \mid m!+1$, states part (a) as
`Set.Infinite {p | ∃ hp : p.Prime, f p hp = p - 1}`, and part (b) as: for every real
$\varepsilon > 0$, the proportion of primes $p \le N$ with $f(p) \ge \varepsilon p$
tends to 0 — the standard "convergence in relative density" unfolding of "for almost
all $p$", equivalent to the upstream file's density-1-subset encoding. Read back
independently, both theorems assert exactly the questions' "yes" directions (the raw
convention for open yes/no questions). No semantic defects; the nits were
scholarship-level (bare citation keys with no bibliographic data; a belief
misattributed to "Hardy and Subbarao" where the page credits Erdős, Hardy, and
Subbarao; missing OPEN status/OEIS/remarks). All fixed.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Independent back-translation of `conjectures/1072.lean`: (lemma) every prime $p$ has
  a positive $m$ with $p \mid m!+1$; (def) $f(p)$ is the least such positive $m$;
  (thm a) the set of primes with $f(p) = p-1$ is infinite; (thm b) for every
  $\varepsilon > 0$, $\#\{p \le N \text{ prime} : f(p) \ge \varepsilon p\} / \pi(N)
  \to 0$. These are exactly questions (a) and (b) as asked.
- **"Least integer" vs "least positive integer":** the page says "least integer"; the
  file requires $0 < m$. The readings differ only at $p = 2$ ($0! + 1 = 2$, so a
  reading admitting $m=0$ gives $f(2)=0$; the positive reading gives
  $f(2) = 1 = 2-1$). Membership of the single prime 2 affects neither the infinitude
  question (a) nor the density question (b). The positive reading is the natural one
  (Guy A2 and OEIS convention); the divergence is now documented in the module
  docstring. Not a defect.
- **"Almost all $p$"** (site convention: relative density 1 among primes): the
  $\forall \varepsilon$ exceptional-density-to-zero form is equivalent to "there is a
  set $P$ of primes of relative density 1 with $f(p)/p \to 0$ along $P$" (classical
  diagonal argument, valid since $\pi(N) \to \infty$); the upstream file uses the
  latter form (`… ↔ ∃ (P : Set ℕ), P ⊆ {p | p.Prime} ∧ P.HasDensity 1 {p | p.Prime}
  ∧ …`, recovered from logs). Both encodings are faithful.
- Indexing/counting: `range (N + 1)` = $\{0, \dots, N\}$ correctly realizes
  "$p \le N$"; term-by-term exact, no off-by-one.
- Not vacuous/trivial: $f$ is well-defined and $\le p-1$ by Wilson; both statements
  are substantive open claims. In (a), the set-builder `∃ hp : Nat.Prime p, …`
  confines the set to primes, so `Set.Infinite` says exactly "infinitely many primes
  with $f(p)=p-1$".

**A2. Lean semantics traps — pass.**

- ℕ subtraction: `p - 1` appears in the lemma's witness and in both `f p hp = p - 1`
  sites; $p \ge 2$ from primality, so no truncation ever occurs (`Nat.sub_pos_of_lt
  hp.one_lt` even proves positivity of the witness).
- Division: the only division is `(count : ℝ) / (count : ℝ)`; the denominator
  $\pi(N)$ is 0 only for $N < 2$, where Lean's field convention gives $0/0 = 0$ —
  invisible under `atTop`. No ℕ division anywhere.
- `Finset.range (N+1)` off-by-one: checked above; exact.
- Vacuous quantifiers: none. The inner `∃ hp : Nat.Prime p, …` inside the filter
  duplicates the filter's own `Nat.Prime p` conjunct — redundant but harmless (proof
  irrelevance; any two primality proofs give the same `Nat.find` value).
- "Infinitely many" via `Set.Infinite`: correct. "Almost all" via density: correct
  (see A1). `Tendsto _ atTop (nhds 0)` is the standard encoding of the limit.
- $\ge \varepsilon p$ vs $> \varepsilon p$ in the exceptional set: immaterial under
  the $\forall \varepsilon > 0$ quantifier ($\{f \ge \varepsilon p\} \subseteq
  \{f > \varepsilon p/2\} \subseteq \{f \ge \varepsilon p /2\}$), and $\ge$ is the
  natural complement of $f(p)/p < \varepsilon$.
- Decidability for `Nat.find` and `Finset.filter`: `open Classical` (line 9) supplies
  instances; `noncomputable` markers are consistent. The originating session's
  `lake build conjectures/1072.lean` succeeded (3 expected `sorry` warnings), so this
  is compile-verified historically.
- No `StrictMono`/`Monotone` or interval-endpoint issues arise.

**A3. Definitions — pass, one load-bearing caveat (deferred).**

- `erdos1072_f` matches its docstring ("least positive integer m such that
  p ∣ m! + 1") exactly; `countPrimesSat1072`/`countPrimes1072` match theirs,
  including the degenerate `N = 0` case (both count over $\{0\}$, giving 0).
- No `sorry` occurs inside any `def`/`abbrev`/`structure`. **However**, the def
  `erdos1072_f` is `Nat.find` applied to the private lemma `exists_factorial_mod`,
  whose divisibility component is `by sorry` (line 59). This is a *lemma proof body*
  (permitted), but it is load-bearing for a definition — a soundness-sensitive
  pattern. It is safe here for two independent reasons: (1) the lemma's statement is
  **true** (Wilson's theorem: $(p-1)! \equiv -1 \pmod p$; witness $m = p-1 > 0$), and
  (2) the *value* of `Nat.find H` depends only on the predicate, not on the proof
  term `H` (proof irrelevance), so $f$ denotes the intended function regardless.
  Discharging the sorry via Mathlib's `ZMod.wilsons_lemma` needs a new import and a
  compiler: **DEFERRED** (see refinement 5).

**A4. Question form and answer polarity — pass for raw style (noted for styling).**

- Both parts are **yes/no questions**, OPEN. The raw file states each question's
  conjectured "yes" direction as a direct assertion with `sorry` proof — the uniform
  convention of this repo's `conjectures/` raw files (cf. `conjectures/1073.lean`,
  `conjectures/1074.lean` and the fable-review/1073 precedent); the raw imports
  cannot provide the `answer()` elaborator. Per the review protocol, raw files are
  judged on soundness, not styled `answer()` form; **no defect**. The theorem
  docstrings now preserve the question form explicitly (pre-fix they stated bare
  assertions — the 1005-style question-dropping pattern; fixed).
- Any future restyling to `deepmind/` form should use `answer(sorry) ↔ P` for each
  part, as the upstream file indeed does (its recovered line 41 for part (b) begins
  `answer(sorry) ↔ ∃ (P : Set ℕ), …`).
- Polarity by hand: asserting "the set is infinite" / "the density limit is 0" is
  precisely the "yes" reading of each question as asked. No binders sit before the
  colon on either theorem (both are binder-free; the `∀ ε` in (b) is part of the
  asserted proposition, correct for a direct assertion).

**A5. Solution status — pass (source-verified).**
