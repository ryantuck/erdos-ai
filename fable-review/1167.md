## Summary

The problem (OPEN, Erdős–Hajnal–Rado): let $r \ge 2$ be finite, $\lambda$ an
infinite cardinal, and $\kappa_\alpha$ cardinals for all $\alpha < \gamma$.
Is it true that $2^\lambda \to (\kappa_\alpha + 1)_{\alpha<\gamma}^{r+1}$
implies $\lambda \to (\kappa_\alpha)_{\alpha<\gamma}^{r}$? (Here $+$ is
cardinal addition, so $\kappa_\alpha + 1 = \kappa_\alpha$ for infinite
$\kappa_\alpha$.) The Lean file defines a general cardinal partition relation
`CardinalPartitionRel κ targets r` (`conjectures/1167.lean:26-30`) — every
coloring of the finite subsets of a $\kappa$-sized type admits a color $i$
and a set $H$ of cardinality $\ge$ `targets i` all of whose $r$-element
subsets get color $i$ — and asserts the implication
`CardinalPartitionRel (2 ^ lam) (fun α => κ α + 1) (r + 1) →
CardinalPartitionRel lam κ r` for all `ι`, `κ : ι → Cardinal`, `lam ≥ ℵ₀`,
`r ≥ 2` (`conjectures/1167.lean:34-39`). Read back independently, the Lean
and the recovered source statement agree; the only defect is scholarship
(the page's `[Va99, 7.79]` citation is missing entirely).

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Let $r\geq 2$ be
  finite and $\lambda$ be an infinite cardinal. Let $\kappa_\alpha$ be
  cardinals for all $\alpha<\gamma$. Is it true that
  $2^\lambda \to (\kappa_\alpha+1)_{\alpha<\gamma}^{r+1}$ implies
  $\lambda \to (\kappa_\alpha)_{\alpha<\gamma}^{r}$? Here $+$ means cardinal
  addition, so that $\kappa_\alpha+1=\kappa_\alpha$ if $\kappa_\alpha$ is
  infinite." The module docstring (lines 8-21) reproduces this essentially
  verbatim.
- Independent back-translation of lines 34-39: "for every index type ι,
  family κ : ι → Cardinal, infinite cardinal lam, and finite r ≥ 2: if
  $2^{\text{lam}} \to (\kappa_\alpha + 1)_{\alpha:\iota}^{r+1}$ then
  $\text{lam} \to (\kappa_\alpha)_{\alpha:\iota}^{r}$." This is exactly the
  question's content, universally quantified over the stated parameters as
  the source's "Let … be …" preamble requires.
- Index family: the source indexes colors by an ordinal ($\alpha < \gamma$,
  $\gamma$ arbitrary); the Lean uses an arbitrary type `ι`, the **same** `ι`
  in hypothesis and conclusion, matching the source's use of the same family
  in both relations. A cardinal partition relation depends only on the
  indexed family of targets up to a bijection of the index set, and every
  type is equinumerous with (the type of ordinals below) some ordinal, so
  the type-indexed form is an equivalent, standard generalization — arbitrary
  $\gamma$ is genuinely covered, including $\gamma = 0$ (empty `ι`), where
  both readings are vacuously true (no coloring into an empty type exists
  from the nonempty type `Finset S`; no coloring of $[S]^r \ne \emptyset$
  with 0 colors exists).
- `CardinalPartitionRel` against the standard Erdős–Hajnal–Rado definition
  ($\kappa \to (\kappa_\alpha)^r_{\alpha<\gamma}$: every partition of
  $[S]^r$, $|S| = \kappa$, into $\gamma$ cells has a cell $\alpha$ and
  $H \subseteq S$, $|H| = \kappa_\alpha$, with $[H]^r$ inside that cell):
  - Quantifying over **all** `S : Type*` with `#S = κ` (rather than one
    representative) is equivalent: the property is invariant under
    bijections, and the quantifier is never vacuous since every cardinal is
    attained (`Quotient.out κ`).
  - `c : Finset S → ι` colors finsets of *every* size, with homogeneity
    demanded only on `s.card = r`. Equivalent to coloring $[S]^r$: a
    coloring of all finsets restricts; conversely, for nonempty `ι` a
    coloring of the r-sets extends arbitrarily, and for empty `ι` both sides
    are vacuous (previous bullet). No drift.
  - `#H ≥ targets i` (written `Cardinal.mk H ≥ targets i` in the input)
    versus the source's "cardinality $\kappa_\alpha$": equivalent, since any
    set of cardinality $\ge \kappa_\alpha$ contains a subset of cardinality
    exactly $\kappa_\alpha$, and subsets of homogeneous sets are homogeneous.
  - Homogeneity `∀ s : Finset S, s.card = r → ↑s ⊆ H → c s = i` is exactly
    "$[H]^r$ monochromatic of color $i$": for finite $r$ the $r$-element
    subsets of $H$ are precisely the $r$-element finsets contained in $H$.
- The $+1$ on targets: `fun α => κ α + 1` is Mathlib cardinal addition, and
  `κ + 1 = κ` for infinite `κ` holds in `Cardinal` — precisely the page's
  parenthetical. The exponents `r + 1` (hypothesis) and `r` (conclusion) and
  the bases `2 ^ lam` and `lam` all match the source display term-by-term.
- Not vacuous/trivial: the hypothesis relation is satisfiable and the
  conclusion is a substantive constraint; no degenerate instantiation makes
  the implication trivially true across all parameters (the empty-`ι` and
  `targets i = 0` degeneracies make single instances trivial — matching the
  informal convention that a homogeneous set of size 0 always exists — not
  the quantified statement). The known mathematical content (the classical
  Erdős–Rado stepping-up direction passes from exponent $r$ to $r+1$; the
  problem asks a converse-type "stepping-down") confirms this is a genuine
  open question, not an artifact.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction, no division, no `Finset.range` anywhere; `r : ℕ` with
  `r + 1` only. The arities live in ℕ, targets and bases in `Cardinal` — the
  intended types.
- `(2 : Cardinal) ^ lam` is cardinal exponentiation, the correct reading of
  $2^\lambda$.
- Vacuous-quantifier audit: `∀ (S : Type*) … (_ : #S = κ)` is never vacuous
  (cardinals are attained); empty `ι` handled above and consistent with the
  source's convention; a color with `targets i = 0` is witnessed by
  `H = ∅` (`#∅ = 0 ≥ 0`, homogeneity vacuous since no `s` with
  `s.card = r ≥ 2` has `↑s ⊆ ∅`) — again the standard convention.
- `[DecidableEq S]` in a `∀` inside a `Prop`: classically every type has
  such an instance and the body (`Finset S`, `s.card`, `⊆`, `=`) does not
  depend on it, so the binder neither restricts nor multiplies the
  quantification meaningfully. Superfluous but harmless (and it compiled in
  the original pipeline session).
- Universes: `S : Type*` inside the def is forced to `Cardinal`'s universe
  by `#S = κ`, with `ι` in its own universe — the standard single-universe
  reading of a cardinal partition relation. The originating session log
  records a successful `lake build`, so the elaboration is not in question.
- No `StrictMono`/`Monotone`, intervals, or filter encodings arise; `≥` on
  `Cardinal` is the intended non-strict comparison.

**A3. Definitions — pass.**
