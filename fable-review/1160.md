## Summary

The problem (OPEN): let $g(n)$ denote the number of groups of order $n$ (up to
isomorphism); the conjecture is that if $n \le 2^m$ then $g(n) \le g(2^m)$ —
powers of two have the most groups of any order up to that point. The Lean
(`conjectures/1160.lean:42-44`) defines $g$ from first principles — group
structures on `Fin n` quotiented by `MulEquiv`-isomorphism, counted with
`Nat.card` — and asserts `∀ n m, n ≤ 2^m → numGroupsOfOrder n ≤
numGroupsOfOrder (2^m)`. The source states the problem as a direct conjecture
(not a question), so the bare-assertion form with `sorry` is the correct
encoding, and the asserted direction is the conjectured one. Read back
independently, the Lean and the recovered source statement agree, including at
the degenerate index $n = 0$; the only defect-class finding is bibliographic
(citation keys used but never defined). The prior review's central "subtle
concern" about `Nat.card` is a wrong claim about Mathlib semantics (see
Part E).

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Let $g(n)$ denote the
  number of groups of order $n$. If $n\leq 2^m$ then $g(n)\leq g(2^m)$." The
  theorem docstring (lines 31-41) reproduces this verbatim.
- Independent back-translation of lines 42-44: "for all naturals $n, m$ with
  $n \le 2^m$, the number of isomorphism classes of group structures on
  `Fin n` is at most the number of isomorphism classes of group structures on
  `Fin (2^m)`." For $n \ge 1$, isomorphism classes of group structures on
  `Fin n` biject with isomorphism classes of groups of order $n$ (every group
  of order $n$ transports along a bijection to `Fin n`; `MulEquiv` between
  groups is exactly group isomorphism, since a multiplicative bijection
  automatically preserves identity and inverses). So `numGroupsOfOrder n`
  $= g(n)$ for $n \ge 1$, and the statement is the conjecture, universally
  quantified exactly as the source's "if $n \le 2^m$".
- Quantifier structure: both $n$ and $m$ universal, hypothesis `n ≤ 2 ^ m` —
  matches. Non-strict `≤` in both hypothesis and conclusion matches the
  source's $\leq$ twice.
- Types: everything in ℕ; `2 ^ m : ℕ` is exact (no coercion subtleties);
  counting in ℕ via `Nat.card` is appropriate.
- Degenerate index: the source's $g$ is implicitly defined for $n \ge 1$; the
  Lean hypothesis admits $n = 0$, where `Fin 0` carries no group structure
  (no identity element), the quotient is empty, and `numGroupsOfOrder 0 = 0`.
  The extra instance of the theorem at $n = 0$ says $0 \le g(2^m)$ — true and
  harmless, and consistent with OEIS A000001's $a(0) = 0$. No distortion.
- Not vacuous/trivial: `numGroupsOfOrder` takes the true values ($g(1) = 1$,
  $g(4) = 2$, $g(8) = 5$, $g(16) = 14$, …), so the statement is the genuine
  open conjecture, not degenerately provable (see A3 on finiteness).

**A3. Definitions — pass.**

- `GroupStructIso` (lines 11-12) matches its docstring: `Nonempty` of a
  `MulEquiv` between the two `Mul` structures extracted from the group
  structures — the right notion (mul-preserving bijection = group iso for
  groups).
- `groupStructSetoid` (lines 15-24) proves the equivalence-relation
  obligations with genuine proofs via `MulEquiv.refl`/`.symm`/`.trans` — no
  `sorry` in any `def`/`instance`. The symmetry step correctly produces an
  equiv with the instance arguments swapped (`symm e : G₂ ≃* G₁`).
- `numGroupsOfOrder` (lines 28-29): `Nat.card` of the quotient. Key semantic
  point (contra the prior review, see Part E): `Nat.card α =
  (Cardinal.mk α).toNat` depends only on the *actual* cardinality of `α`, not
  on whether a `Finite` instance is derivable by typeclass search. And
  `Group (Fin n)` is genuinely finite: its data fields beyond
  `(mul, one, inv)` — `div`, `npow`, `zpow` — are pinned down by the
  propositional axioms (`div_eq_mul_inv`, `npow_zero`/`npow_succ`,
  `zpow_zero`/`zpow_succ'`/`zpow_neg'`), so by proof irrelevance and structure
  eta the map `G ↦ (G.mul, G.one, G.inv)` into the finite type
  `(Fin n → Fin n → Fin n) × Fin n × (Fin n → Fin n)` is injective. Hence the
  quotient is finite and `numGroupsOfOrder n` is the true $g(n)$ for all $n$.
  There is no vacuous-proof channel through `Nat.card = 0`.
- Definitions are used consistently: the theorem consumes `numGroupsOfOrder`
  exactly as defined; no drift.
- Compile-sensitive detail (out of scope, noted for the compile pass):
  `G₁.toMul` relies on Lean resolving a projection to the indirect ancestor
  `Mul` of `Group`; if generalized field notation does not resolve it, the
  spelling `Group.toDivInvMonoid.toMonoid.toSemigroup.toMul` or
  `(inferInstanceAs (Mul (Fin n)))`-style rewiring would be needed. The
  intent is unambiguous either way. `compile_status: pending`.

## E. Prior-review audit (`deepmind/ai-review/1160.md`)

Accurate on the core encoding and on scholarship gaps, but its central
technical concern is wrong, and its citation verification endorsed a
hallucination:

1. **Wrong claim about Mathlib semantics (the recurring 1002-class
   failure).** §6 "Subtle concern": "If Lean cannot derive
   `Finite (Quotient (groupStructSetoid n))`, then `Nat.card` returns 0 on
   both sides, making the theorem **trivially provable** as 0 ≤ 0." This is
   false. `Nat.card` is `(Cardinal.mk α).toNat`; its value is determined by
   the actual cardinality of the type, not by what typeclass search can
   derive. `Group (Fin n)` is genuinely finite (the `div`/`npow`/`zpow` data
   is pinned by the propositional axioms, so the structure injects into the
   finite `(mul, one, inv)` data — see A3), hence the quotient is finite and
   both sides are the true values of $g$; no vacuous proof exists, whether or
   not any `Finite` instance is registered. What *is* true is merely that a
   prover must establish finiteness to compute with `Nat.card` — a proof
   obligation, not a statement defect. Its suggested fix (a hypothesis
   `[Finite (Quotient (groupStructSetoid n))]`) would be a semantic no-op
   satisfied by every instantiation, added complexity for nothing.
2. **Citation verification endorsed a fabrication.** §2 states the references
   "[Va99] (Vaughan, 1999)" and [BNV07] "match the website." The recovered
   page shows only the bare key `[Va99,5.71]`; the recovered `/latex`
   extraction lists no Va99 bibliographic details at all (and the page-fetch
   extraction explicitly noted "incomplete details provided"); and the
   corroborated identification of [Va99] is the Budapest-1999 booklet by
   various authors, not Vaughan. The "match the website" claim cannot have
   been verified and blessed the styled file's invented "Vaughan, R.C."
   entry. (Same family as 1001's claiming-unrecoverable/unverifiable data and
   1005's endorsing an encoding against its own source reading.)
3. **What it got right** (all re-derived and confirmed): the
   `GroupStructIso`/`groupStructSetoid`/`numGroupsOfOrder` correctness
   analysis; the edge cases $n = 0$ (empty `Group (Fin 0)`, count 0) and
   $m = 0$ ($g(1) = 1$); the missing [Pa03] partial result; the missing
   Question 22.18 variant — which it, correctly, quoted *with* the
   "sufficiently large" condition; and the observation that "attributed to
   Erdős and Higman" is more definitive than the source's hedging.
4. **What it missed relative to this review:** the undefined-citation-key
   defect in the raw file (no bibliography anywhere); and its variant
   suggestion, though correctly hedged in prose, was implemented in the
   styled file with the quantifier dropped, yielding a false-at-$m=2$
   statement that its review of that file did not catch (that file is out of
   this review's scope, but the miss is on record).
5. Nothing it flagged for the raw statement went unaddressed: its two
   scholarship flags ([Pa03], Q22.18) are now applied in v2; its `Nat.card`
   flag is refuted rather than applied.
