## Summary

The problem: let $r \ge 2$; a number $n$ is $r$-powerful if $p \mid n$ implies
$p^r \mid n$ for every prime $p$; is every large integer the sum of at most $r+1$ many
$r$-powerful numbers? The status is OPEN (page banner), posed by Erdős and Ivić in the
1986 Oberwolfach problem book; the case $r = 2$ is a theorem of Heath-Brown [He88]
(cf. problem #941). The Lean file defines `IsRPowerful1107 r n` (positivity plus the
prime-power divisibility condition) and `IsSumOfAtMostRPowerful1107 r k m` (a sum of
$j \le k$ such numbers), and states: for every $r \ge 2$ there exists $N_0$ such that
every $n \ge N_0$ is a sum of at most $r+1$ many $r$-powerful numbers. Read back
independently, the Lean asserts exactly the affirmative direction of the question as
asked, with the threshold correctly allowed to depend on $r$. I found no semantic
defects; the findings are scholarship-level nits (citation keys used but never defined;
OPEN status and the direct-assertion convention undocumented) plus one page-confirmed
enrichment variant (the Heath-Brown $r = 2$ case, which the recovered upstream file also
carries), all applied in `conjectures-v2/1107.lean`.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Let $r\geq 2$. A number $n$ is
  $r$-powerful if for every prime $p$ which divides $n$ we have $p^r\mid n$. Is every
  large integer the sum of at most $r+1$ many $r$-powerful numbers?" The module
  docstring (lines 13–15) reproduces this essentially verbatim.
- Independent back-translation of `erdos_problem_1107` (lines 44–46): "for every
  $r \ge 2$ there is a threshold $N_0$ such that every $n \ge N_0$ can be written as
  $\sum_{i<j} f(i)$ with $j \le r+1$ and each $f(i)$ $r$-powerful." This is exactly the
  affirmative content of the question. Quantifier order is right: $r$ is a theorem
  binder (universal), $N_0$ existential *after* $r$, so the threshold may depend on $r$
  — the natural reading of "Let $r \ge 2$. Is every large integer…".
- `IsRPowerful1107` (lines 26–27): `0 < n ∧ ∀ p, p.Prime → p ∣ n → p ^ r ∣ n` is
  precisely the source's definition, restricted to positive $n$ — the standard
  convention for powerful numbers (the source's "number" means a positive integer). See
  A2 for why the positivity conjunct is semantically inert for the sum predicate.
- `IsSumOfAtMostRPowerful1107` (lines 30–33): `∃ j ≤ k` terms indexed by `Fin j` — "at
  most $k$ many" correctly includes representations with fewer than $k$ terms.
- Not vacuous: $1$ is $r$-powerful (vacuously — no prime divides it), so small sums
  exist, but $n = 1 + \cdots + 1$ with at most $r+1$ terms only reaches $n \le r+1$;
  for large $n$ the statement demands genuinely large $r$-powerful summands, whose
  density is $\sim x^{1/r}$ — a substantive open conjecture (proved only for $r = 2$).
  No degenerate witness trivializes it.

**A2. Lean semantics traps — pass on all checklist items.**

- ℕ subtraction: none in the file. The only arithmetic is `r + 1`, addition, and `∑`.
- Division: none.
- `Finset.range`: not used; the sum `∑ i, f i` is over `Fin j` (`Finset.univ`), which
  has exactly $j$ terms — no off-by-one. "Every large integer" is encoded as
  `∃ N₀, ∀ n, N₀ ≤ n → …`, the standard threshold form (equivalent to `∀ᶠ n in atTop`,
  which the recovered upstream file uses — the two encodings agree).
- Vacuous/degenerate cases: with $j = 0$ the empty sum makes $m = 0$ expressible —
  harmless (and consistent with "at most"), invisible behind the threshold anyway.
  `IsRPowerful1107 r 1` holds vacuously ($1$ is $r$-powerful, the standard convention).
  For $r = 0$ or $1$ every positive $n$ is $r$-powerful, but the theorem's `2 ≤ r`
  hypothesis excludes those degenerate parameters, matching the source's "Let
  $r\geq 2$".
- Positivity conjunct check: dropping `0 < n` would admit $0$ as $r$-powerful (every
  prime divides $0$ and $p^r \mid 0$), allowing zero-padding of representations — but
  since `j ≤ k` already permits fewer terms, the sum predicate would be unchanged
  either way. The conjunct is therefore safe, and it keeps the *definition* aligned
  with the standard notion. (The recovered upstream file omits positivity in its
  `Nat.Full`-based encoding; the two files' sum predicates are equivalent, confirming
  this analysis.)
- Filter/threshold encodings, `StrictMono` vs `Monotone`, strict vs non-strict, open
  vs closed intervals: no other such constructs occur; `N₀ ≤ n` is the correct
  non-strict reading of "sufficiently large".
