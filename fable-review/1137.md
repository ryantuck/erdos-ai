## Summary

The problem ([Va99, 1.2], status OPEN): let $d_n = p_{n+1} - p_n$ with $p_n$ the $n$th
prime; is it true that $\max_{n<x} d_n d_{n-1} / (\max_{n<x} d_n)^2 \to 0$ as
$x \to \infty$? The Lean file builds `primeGap`, the running maxima of $d_n$ and of
$d_n d_{n-1}$, and asserts `Tendsto (ratio) atTop (nhds 0)` — the conjectured "yes"
direction, which is this corpus's convention for open yes/no questions. The limit
statement itself is a faithful, term-by-term-exact rendering (a uniform index shift
$x \mapsto x+1$ against the source, invisible to `atTop`). The defect is upstream of the
statement: `nthPrime : ℕ → ℕ := sorry` (line 24) with two `axiom`s (lines 26–27)
asserting only primality and strict monotonicity. Those axioms are satisfied by *any*
increasing enumeration of *any* infinite set of primes, and for some such enumerations
the asserted limit is genuinely false — so the file as written does not state the Erdős
problem at all. The fix (Mathlib's `Nat.nth Nat.Prime`, axioms demoted to theorems) is
exactly what the sibling `conjectures/852.lean` and the upstream formal-conjectures
`primeGap` already do.

## A. Semantic fidelity

**A1. Statement fidelity — pass modulo the A3 defect (source-verified).**

- Recovered verbatim source statement (see Addendum): "Let $d_n=p_{n+1}-p_n$, where
  $p_n$ denotes the $n$th prime. Is it true that
  \[\frac{\max_{n<x}d_{n}d_{n-1}}{(\max_{n<x}d_n)^2}\to 0\] as $x\to \infty$?" The
  module docstring (lines 15–17) reproduces this verbatim.
- Independent back-translation of the theorem (lines 55–60), *assuming `nthPrime` means
  the actual prime enumeration*: "the maximum over $1 \le n < x$ of
  `primeGap n · primeGap (n-1)`, divided by the square of the maximum over $n < x$ of
  `primeGap n`, tends to 0." That assumption is exactly what the file fails to secure —
  see A3.
- Indexing, verified term-by-term (not just "in the limit"): the source is 1-indexed
  ($p_1 = 2$, $d_n$ defined for $n \ge 1$, $d_n d_{n-1}$ for $n \ge 2$); Lean is
  0-indexed (`nthPrime 0 = 2`), so `primeGap n` is the source's $d_{n+1}$. Numerator:
  Lean maxes over filtered $1 \le n \le x-1$, i.e. products $d_{n+1}d_n$ = source pairs
  $d_m d_{m-1}$ for $2 \le m \le x$; the source at $y$ takes $2 \le m \le y-1$. So Lean
  numerator$(x)$ = source numerator$(x+1)$. Denominator: Lean maxes `primeGap n` over
  $0 \le n \le x-1$, i.e. $d_m$ for $1 \le m \le x$ = source denominator$(x+1)$. Both
  components shift by the *same* $+1$, so the Lean ratio at $x$ equals the source ratio
  at $x+1$ exactly, and `Tendsto … atTop` is invariant under that reindexing. No
  off-by-one defect; now documented in the theorem docstring (v2).
- Not vacuous/trivial: gaps are unbounded, so the denominator $\to \infty$; the
  numerator never exceeds the denominator (each $d_m d_{m-1} \le (\max d)^2$), so the
  ratio sits in $[0,1]$ and the convergence claim is the substantive open question.

**A2. Lean semantics traps — one guarded, rest pass.**

- ℕ subtraction in `primeGap` (line 30): `nthPrime (n+1) - nthPrime n` never truncates
  once `nthPrime` is strictly monotone — intended and (post-fix) actual behavior.
- ℕ subtraction in `consecutiveGapProduct` (line 34): at $n = 0$, `n - 1 = 0` truncates
  and the value degenerates to `primeGap 0 ^ 2`. **Guarded**: `maxConsecutiveGapProduct`
  filters to `· ≥ 1` (line 38), so the degenerate value is never consulted. Correct as
  written; the guard is now documented (v2). (Contrast: the upstream formal-conjectures
  file takes the unfiltered `(range x).sup`, silently including the truncated $n=0$
  term `primeGap 0 ^ 2 = 1` — harmless there only because every genuine product is
  $\ge 1$; the filtered version under review is the cleaner encoding.)
- Field division: at $x = 0$ both maxima are `Finset.sup ∅ = 0`, giving $0/0 = 0$ by ℝ
  convention; at $x = 1$ the numerator's filtered range is empty (ratio $0/1$). Both
  harmless under `atTop`; documented (v2).
- `Finset.range x` = $\{0,\dots,x-1\}$: accounted for in the shift analysis above; no
  off-by-one.
- No vacuous quantifiers; `Tendsto _ atTop (nhds 0)` is the standard, correct encoding
  of the limit; `StrictMono` (not `Monotone`) is the right property for the prime
  enumeration.

**A3. Definitions — DEFECT.**

- `nthPrime : ℕ → ℕ := sorry` (line 24) is a `sorry` inside a `def` — the one thing the
  checklist forbids outside proof bodies. The theorem's meaning then rests on an
  unspecified constant (`sorryAx`), so the file does not formally state a proposition
  about the primes.
- The two `axiom` declarations (lines 26–27) do not repair this: `∀ n, Nat.Prime
  (nthPrime n)` and `StrictMono nthPrime` are satisfied by the increasing enumeration
  of **any** infinite set of primes, not just the full one. The underspecification is
  fatal, not cosmetic: for the true enumeration the asserted limit is the open
  conjecture, but for a doctored admissible enumeration it is **false** — e.g. build
  $S$ in blocks: given the largest gap $M$ so far, pick a large prime $q_1$, then
  primes $q_2 \approx q_1 + M'$ and $q_3 \approx q_2 + M'$ with $M' \gg M$ (possible
  for every large $M'$ since prime gaps near $y$ are $O(y^{0.6})$, far below $M'$-sized
  targets chosen with $q_1 \gg M'$... concretely, choose $q_2$ = least prime
  $> q_1 + M'$ and $q_3$ = least prime $> q_2 + M'$, so both new gaps lie in
  $[M', M' + o(M')]$). Then two *consecutive* record-scale gaps occur, the ratio at
  that point is $\approx 1$, and repeating with $M' \to \infty$ gives
  $\limsup = 1 \ne 0$. So the axioms leave the theorem's truth value undetermined —
  the statement is not the Erdős problem. **[defect]**
- Additionally, `axiom` extends the ambient theory globally — a hazardous pattern even
  when (as here) the axioms are jointly satisfiable and hence consistent.
- **Fix applied (v2, not compile-verified):** `nthPrime := Nat.nth Nat.Prime`
  (Mathlib's canonical 0-indexed prime enumeration, `Nat.nth Nat.Prime 0 = 2`,
  matching the docstring), with the two axioms demoted to theorems proved by
  `Nat.prime_nth_prime` and `Nat.nth_strictMono Nat.infinite_setOf_prime`. This is
  precisely the pattern of the sibling `conjectures/852.lean` (`nthPrime852`) and of
  upstream `FormalConjecturesForMathlib/NumberTheory/PrimeGap.lean` (recovered from
  logs, see Addendum).
- The remaining defs (`primeGap`, `consecutiveGapProduct`, `maxConsecutiveGapProduct`,
  `maxPrimeGap`) each match their docstrings and the source, including degenerate
  inputs (A2); no other `sorry` in any def.
