## Summary

The problem ([Va99, 7.87], OPEN; a problem of Erdős and Hajnal): establish
whether, assuming GCH, ω₃ → (ω₂, ω₁+2)², ω₃ → (ω₂+ω₁, ω₂+ω)², and
ω₂ → (ω₁^(ω+2)+2, ω₁+2)²; and whether, assuming CH, ω₂ → (ω₁+ω)²₂. The Lean
file defines initial ordinals ω, ω₁, ω₂, ω₃ as `(aleph n).ord`, the two-color
ordinal partition relation `OrdinalPartitionPair α β γ` via strictly monotone
embeddings of `{x // x < β}` (resp. γ) into `{x // x < α}` with a
monochromaticity condition on increasing pairs, standard `GCH`/`CH`
definitions, and four theorems `erdos_problem_1172a–d`, each taking the
relevant hypothesis and asserting the corresponding relation with a `sorry`
proof — the corpus's direct-assertion convention for open "establish whether"
questions. Read back independently, all four Lean statements match the four
displayed source statements exactly, including the encoding of the balanced
relation ω₂ → (ω₁+ω)²₂ as `OrdinalPartitionPair omega2 (ω₁+ω) (ω₁+ω)`. No
Part A defects. The findings are scholarship/documentation-class: the citation
key [Va99] is used but never defined, the page's [ErRa56] reference and
Erdős–Rado remark are missing entirely, and the truncated-photocopy caveat
sits on Parts 1 and 3 when the page's "first and final statements" means
Parts 1 and 4. A hand-derived mathematical observation sharpens that last
point: Part 1 *as displayed* already follows from the Erdős–Rado theorem under
GCH, corroborating the page's warning that its right-hand side may have been
filled in (too weakly). All fixed in `conjectures-v2/1172.lean`.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Establish whether the
  following are true assuming the generalised continuum hypothesis:
  \[\omega_3 \to (\omega_2,\omega_1+2)^2,\]\[\omega_3\to
  (\omega_2+\omega_1,\omega_2+\omega)^2,\]\[\omega_2\to
  (\omega_1^{\omega+2}+2, \omega_1+2)^2.\] Establish whether the following is
  true assuming the continuum hypothesis: \[\omega_2\to
  (\omega_1+\omega)_2^2.\]" The module docstring reproduces this faithfully.
- Independent back-translation of the four theorems:
  - `erdos_problem_1172a` (lines 67–69): "GCH implies: for every 2-coloring f
    of pairs of ordinals below ω₃, either some strictly monotone
    g : {x < ω₂} → {x < ω₃} has all increasing pairs colored `true`, or some
    strictly monotone g : {x < ω₁+2} → {x < ω₃} has all increasing pairs
    colored `false`" — exactly GCH → ω₃ → (ω₂, ω₁+2)². ✓
  - `erdos_problem_1172b` (lines 79–81): GCH → ω₃ → (ω₂+ω₁, ω₂+ω)². Ordinal
    addition is non-commutative and the operand order (`omega2 + omega1`,
    `omega2 + omega0`) matches the source. ✓
  - `erdos_problem_1172c` (lines 92–94): GCH → ω₂ → (ω₁^(ω+2)+2, ω₁+2)².
    Precedence check: `omega1 ^ (omega0 + 2) + 2` parses as
    (ω₁^(ω+2)) + 2 — correct. ✓
  - `erdos_problem_1172d` (lines 107–109): CH → ω₂ → (ω₁+ω, ω₁+ω)². The
    source's balanced relation ω₂ → (ω₁+ω)²₂ (subscript 2 = two colors, one
    target) is equivalent to the pair relation with both entries equal:
    "homogeneous of type β in some color" ⟺ "type β in `true` or type β in
    `false`". Encoding faithful. ✓
- Quantifier structure: the coloring is universally quantified inside each
  relation; the homogeneous embedding existentially; GCH/CH sit as named
  hypotheses (direct-assertion form — see A4). Nothing that should be inside
  a quantifier leaks outside.
- Not vacuous/trivial: GCH and CH are independent of Lean's foundation
  (CIC + choice, equiconsistent with ZFC), so the hypotheses are neither
  provable nor refutable and the implications are substantive. None of the
  target order types β, γ here is ≤ 2, so the degenerate-embedding
  trivializations that afflicted sibling 1169 (empty/singleton/pair targets)
  cannot arise: every target is ≥ ω₁+2 > 3.
- One *mathematical* caveat, documented rather than "fixed": Part 1 as
  displayed is (modulo the classical Erdős–Rado theorem, quoted in the page's
  own remarks) a GCH-theorem, not an open problem. Derivation, checked by
  hand against the exact Lean encoding: [ErRa56] gives
  (2^κ)⁺ → (κ⁺+1)²_κ for every infinite κ; at κ = ℵ₁ under GCH,
  2^(ℵ₁) = ℵ₂, so ω₃ → (ω₂+1)²_(ℵ₁), hence a fortiori ω₃ → (ω₂+1)²₂ (view a
  Bool-coloring as an ℵ₁-coloring using two values). Given f, a homogeneous
  strictly monotone g : {x < ω₂+1} → {x < ω₃}: if its color is `true`,
  precompose with the inclusion {x < ω₂} ↪ {x < ω₂+1} (strictly monotone,
  well-defined since ω₂ < ω₂+1) to witness the first disjunct of
  `OrdinalPartitionPair omega3 omega2 (omega1+2)`; if `false`, precompose
  with {x < ω₁+2} ↪ {x < ω₂+1} (ω₁+2 < ω₂ < ω₂+1) for the second disjunct.
  This does **not** make the formalization wrong — it faithfully renders what
  the page displays, and the page itself warns the right-hand side of exactly
  this statement "may have been filled in incorrectly" (i.e., plausibly too
  weakly). The v2 file records the observation in the docstrings and adds the
  Erdős–Rado instance as a solved context variant, rather than inventing a
  "corrected" problem statement the source does not display.

**A2. Lean semantics traps — pass (checked exhaustively; no arithmetic
surface).**

- Numerals: `2` in `omega1 + 2` etc. elaborates as `(2 : Ordinal)` (ordinal

- Exponentiation: in `omega1 ^ (omega0 + 2)` the exponent is an `Ordinal`, so

  notion.
