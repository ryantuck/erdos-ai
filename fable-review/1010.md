## Summary

The problem (Erdős–Rademacher): let $t < \lfloor n/2 \rfloor$; **does** every graph on
$n$ vertices with $\lfloor n^2/4 \rfloor + t$ edges contain at least
$t\lfloor n/2 \rfloor$ triangles? The recovered page marks it **PROVED** ("solved in the
affirmative"), independently by Lovász–Simonovits [LoSi76] and
Nikiforov–Khadzhiivanov [NiKh81]; Rademacher had proved the case $t = 1$ and Erdős
[Er62d] the range $t < cn$. The Lean file defines `triangleCount` (unordered 3-cliques
via `Nat.card`) and states the bound with floors as ℕ-division — all of which is
semantically correct and term-by-term faithful. The one Part A defect: the source is a
**yes/no question**, but `erdos_1010` was encoded as a **direct assertion** with theorem
binders, contrary to checklist A4 and the corpus's uniform convention for
solved-affirmative questions (`answer(True) ↔ …`, cf. the direct sibling
`deepmind/1009.lean`, plus `deepmind/1000.lean`, `1001`, `1019`, …). The raw first
pass's module docstring asked the question verbatim; the restyling silently dropped the
question sentence — the same drift mechanism as the 1005 defect.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified), form defect deferred to A4.**

- Recovered verbatim source statement (see Addendum): "Let $t<\lfloor n/2\rfloor$. Does
  every graph on $n$ vertices with $\lfloor n^2/4\rfloor+t$ edges contain at least
  $t\lfloor n/2\rfloor$ triangles?"
- Independent back-translation of the pre-fix theorem: "for all $n, t \in \mathbb{N}$
  with $t < \lfloor n/2 \rfloor$, every simple graph on vertex set `Fin n` with at least
  $\lfloor n^2/4 \rfloor + t$ edges has at least $t\lfloor n/2\rfloor$ triangles." The
  mathematical content matches the question's universally-quantified body exactly.
- **Edge-count `≥` vs the source's "with … edges" (exact count):** equivalent, by a
  two-step argument — delete edges from $G$ to reach a spanning subgraph $H$ with
  *exactly* $\lfloor n^2/4\rfloor + t$ edges, apply the exact-count statement to $H$,
  and note every triangle of $H$ is a triangle of $G$ (triangle count is trivially
  monotone under edge addition). Conversely the exact form is a special case of the `≥`
  form. Standard extremal-graph-theory phrasing; no defect. (See Part E for the prior
  review's garbled version of this argument.)
- Types: all quantities ℕ; `Fin n` for "on $n$ vertices" is the corpus standard;
  `t * (n / 2)` computes $t\lfloor n/2\rfloor$ in ℕ exactly.
- Not vacuous/trivial: tight examples exist ($n = 4$, $t = 1$: $K_4$ minus an edge has
  5 edges and exactly 2 $= t\lfloor n/2\rfloor$ triangles; $n = 5$, $t = 1$: $K_{2,3}$
  plus one edge inside the 3-side has 7 edges and exactly 2 triangles). For $n \le 3$
  the hypothesis forces $t = 0$ and the statement is trivially true there — matching
  the source, whose constraint likewise degenerates for small $n$.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere.
- ℕ division: `n ^ 2 / 4` and `n / 2` floor — exactly the source's explicit
  $\lfloor\cdot\rfloor$; `^` binds tighter than `/`, so `n ^ 2 / 4` parses as
  $\lfloor n^2/4 \rfloor$. Intended, not accidental.
- Degenerate boundary: $n \in \{0, 1\}$ gives `n / 2 = 0`, so `t < n / 2` is
  unsatisfiable and the statement is vacuous there; $n \in \{2, 3\}$ admits only
  $t = 0$ with trivial conclusion `≥ 0`. All consistent with the source's intent.
- No `Finset.range`, no filters/limits, no `StrictMono`/interval issues.

**A3. Definitions — pass.**

- `triangleCount` (`Nat.card {s : Finset (Fin n) // G.IsNClique 3 s}`) matches its
  docstring: it counts *unordered* vertex-triples forming triangles, each once — the
  standard convention the bound $t\lfloor n/2\rfloor$ presupposes. The subtype is
  finite (subtype of the Fintype `Finset (Fin n)`), so `Nat.card` is the genuine
  cardinality, never the junk value 0 from an infinite type. No `sorry` in any def.
- No drift between the def and the theorem's use of it.

**A4. Question form and answer polarity — DEFECT (fixed).**

- The source problem is a **yes/no question** ("Does every graph … contain …?"),
  solved in the affirmative. Per the checklist this requires the shape
  `answer(…) ↔ P` with `P` the question as asked; the corpus convention for
  solved-affirmative questions is `answer(True) ↔ P` — used by the *directly adjacent*
  triangle problem `deepmind/1009.lean` (`answer(True) ↔ ∀ …` with all graph
  quantifiers inside the iff) and by `1000`, `1001`, `1019`, `1021`, etc. `erdos_1010`
  was instead a bare assertion with binders `(n t : ℕ) (ht : t < n / 2) (G : …)` before
  the colon. **[defect]** — fixed to
  `answer(True) ↔ ∀ (n t : ℕ), t < n / 2 → ∀ (G : SimpleGraph (Fin n)) [DecidableRel G.Adj], …`
  (see Addendum; not compile-verified).
- Polarity of the fixed form checked by hand: RHS true ⟺ every such graph has at least
  $t\lfloor n/2\rfloor$ triangles ⟺ the question's answer is "yes". The page says
  "solved in the affirmative", so `answer(True)` is correct.
- Post-fix, no binders sit before the colon on the `answer()` theorem (pre-fix binders
  would have universally quantified an iff — moot then since there was no iff, but the
  fix deliberately places all quantifiers inside the RHS).
- Restyling drift: `conjectures/1010.lean`'s module docstring asked the question
  verbatim ("Does every graph on $n$ vertices … contain at least
  $t \lfloor n/2 \rfloor$ triangles?"); the styled module docstring **dropped the
  question sentence entirely**, leaving "Erdős [Er62d] proved this…" with no antecedent
  and recasting the problem as a statement. The restyling session's own log even
  acknowledged "the original problem is phrased as a question" before choosing the
  assertion form. Same drift class as the 1005 defect. Both drifts fixed.
- Note on the raw file: `conjectures/1010.lean`'s direct-assertion *statement* is
  acceptable raw style (solved problem, polarity is the true direction); the defect is
  in the styled artifact, whose corpus convention is `answer(True) ↔`.

**A5. Solution status — pass (source-verified).**

- Recovered page banner: **PROVED**, tooltip "This has been solved in the affirmative."
  `@[category research solved]` and both docstrings agree, as do the attributions
  (Rademacher $t = 1$; Erdős $t < cn$; Lovász–Simonovits and Nikiforov–Khadzhiivanov in
  general). The formalized statement is the true direction. Page records "Formalised
  statement? No" as of access (2026-02-22).

## E. Prior-review audit (`ai-review/1010.md`)

Accurate on the mechanics (floors, parsing precedence, `Nat.card` finiteness,
triangle-as-unordered-triple, degenerate $t$/$n$ cases all check out), but four
findings:

1. **Missed the A4 defect.** Its own §5 quotes the website's *question* form ("Does
   every graph … contain …?") and its §6 then assesses the direct-assertion encoding as
   "correct and complete" without ever engaging question-form conventions — despite the
   adjacent, structurally identical `deepmind/1009.lean` using `answer(True) ↔`. The
   style review (`reviews/1010.md` §6) compounds it with the factually false "The
   problem asserts a direct bound … This is **Case 3 — direct assertion**" — directly
   contradicted by the recovered source text it never quotes. This is the same
   endorse-an-encoding-that-contradicts-the-source pattern as the 1005 audit.
2. **Garbled monotonicity argument (right conclusion).** On `≥` vs `=` it writes: "the
   result with `≥` follows from the result with `=` by monotonicity of triangle count
   with respect to adding edges — though this monotonicity itself is nontrivial."
   Monotonicity is *trivial* (a triangle of a subgraph is a triangle of the
   supergraph); what the derivation actually needs, and the review omits, is the
   edge-deletion step (pass to a spanning subgraph with exactly
   $\lfloor n^2/4\rfloor + t$ edges, where the exact-count result applies). A
   fabricated "nontrivial" justification of the right conclusion — the same class as
   the invented-then-excused arguments in the 1000/1005 audits.
3. **False convention claim on citations.** "References … are shorthand tags rather
   than full bibliographic entries, but this is the convention used throughout the
   codebase. No issues." The corpus convention is the opposite: sibling files
   (`1000`, `1005`, `1009`, `1011`) define every key in a module-docstring
   bibliography. The missing bibliography was a real B1 gap (now fixed).
4. **Unverifiable claim, plus a capture discrepancy it papers over.** Its parenthetical
   years "(1976)", "(1981)" for the solvers appear on no recovered capture (the page
   remarks give names only; years are implied by the key suffixes) — harmless but
   presented as website content. Separately, the two log captures disagree on one
   trivial datum (raw HTML: "0 comments"; the WebFetch extraction in the
   formal-conjectures log: "1 discussion"), worth recording for provenance honesty.

Nothing the prior review flagged went unfixed (it flagged nothing); everything this
