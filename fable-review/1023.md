## Summary

The problem: let $F(n)$ be the maximal size of a family of subsets of $\{1,\ldots,n\}$
such that no set in the family is the union of other members of the family. **Is it true**
that there is a constant $c > 0$ with $F(n) \sim c \cdot 2^n / n^{1/2}$? The recovered
page marks it SOLVED (LEAN); the answer is yes: Erdős–Kleitman proved
$F(n) \asymp 2^n/\sqrt{n}$ (unpublished), and Hunter observed that Kleitman's solution of
Problem 447 gives $F(n) \sim \binom{n}{\lfloor n/2\rfloor}$, hence $c = \sqrt{2/\pi}$.
The Lean file defines the (general) union-free property and $F(n)$ via `sSup`
correctly, and its limit encoding $F(n)\sqrt{n}/(c\,2^n) \to 1$ is a faithful rendering
of the asymptotic. The one semantic defect: the source asks a **yes/no question**, but
`erdos_1023` was encoded as a **direct assertion** (`∃ c : ℝ, c > 0 ∧ Tendsto …`) with no
`answer(True) ↔` wrapper, contrary to checklist A4 and the corpus's uniform convention for
solved yes/no questions (`deepmind/1000.lean`, `deepmind/1021.lean`, …). The raw first
pass's module docstring even asked the question verbatim ("Is it true that…?"); restyling
drifted it into "conjecturing that…" — the same drift class as the 1005 defect.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified), one form defect deferred to A4.**

- Recovered verbatim source statement (see Addendum): "Let $F(n)$ be the maximal size of
  a family of subsets of $\{1,\ldots,n\}$ such that no set in this family is the union
  of other members of the family. Is it true that there is a constant $c>0$ such
  that\[F(n)\sim c \frac{2^n}{n^{1/2}}?\]"
- Independent back-translation of the pre-fix theorem: "there is a positive real $c$ with
  $F(n)\sqrt{n}/(c\,2^n) \to 1$." Since $c\,2^n > 0$, this is exactly
  $F(n) \sim c \cdot 2^n/\sqrt{n}$ — the *content* of the question matches; only the
  question *form* was wrong (A4).
- `IsUnionFreeFamily` (line 60 post-fix): no member $A$ equals `S.sup id` for any
  nonempty $S \subseteq \mathcal F \setminus \{A\}$. `Finset.sup id` over a nonempty
  finset of finsets is precisely the union. Singleton $S = \{B\}$ gives $B \ne A$
  automatically (as $B \in \mathcal F.erase\ A$), so the singleton case adds no
  constraint — exactly matching the informal "union of *other* members" (a single other
  member trivially cannot equal $A$). The empty set as a member is harmless in both
  readings (any nonempty union of *other* members differs from $\varnothing$). This is
  the general interpretation, the natural reading of the source; the page's third remark
  confirms the pairwise interpretation is a *different* problem (447).
- `unionFreeMax`: `sSup {k | ∃ 𝓕, IsUnionFreeFamily 𝓕 ∧ 𝓕.card = k}`. The set contains
  $0$ (empty family, vacuously union-free) and is bounded above by $2^n$ (all families
  are subsets of the $2^n$-element powerset of `Fin n`), so ℕ's `sSup` is the achieved
  maximum. Well-defined and equal to $F(n)$.
- Indexing: subsets of $\{1,\ldots,n\}$ ↔ subsets of `Fin n` is a clean bijection; no
  sequence indexing arises. No off-by-one.
- Not vacuous: the statement is a substantive asymptotic; no degenerate witness makes the
  RHS trivially true (any $c$ must match the true growth rate $\sqrt{2/\pi}$).

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere.
- `Nat.choose n (n / 2)`: ℕ floor division is *intended* here ($\lfloor n/2 \rfloor$);
  `choose n (n/2) ≥ 1` for all $n$, so the real division in the central-binomial variant
  never divides by zero.
- Main theorem at $n = 0$: `Real.sqrt 0 = 0` makes the term
  $F(0)\cdot 0/(c\cdot 1) = 0$ — note the *denominator* $c\,2^0 = c$ is nonzero; there is
  no division by zero at all (contra the prior review, see Part E). A single deviant
  initial term is invisible to `atTop`.
- No `Finset.range`; no vacuous bounded quantifiers with semantic weight (the vacuity of
  `IsUnionFreeFamily` on the empty family is correct: the empty family *is* union-free).
- `Tendsto _ atTop (nhds 1)` is the standard, correct encoding of the ratio tending
  to 1, and hence of $\sim$ (for $n \ge 1$ the comparison functions are nonzero).
- No `StrictMono`/`Monotone` or interval-endpoint issues.

**A3. Definitions — pass.**

- Both defs match their docstrings and the source, including degenerate inputs (empty
  family, empty-set member, $n = 0$: `unionFreeMax 0 = 1`, achieved by $\{\varnothing\}$).
  No `sorry` in any `def`. No drift between the defs and their use in the theorems.
- `noncomputable` on `unionFreeMax` is genuinely required (`Nat`'s `sSup` instance);
  do not remove.

**A4. Question form and answer polarity — DEFECT (fixed).**

- The source is a **yes/no question** ("Is it true that there is a constant $c>0$…?").
  Per checklist A4 this requires the shape `answer(…) ↔ P`; the corpus convention for
  solved-yes questions is `answer(True) ↔ P` (`deepmind/1000.lean:71`,
  `deepmind/1021.lean:96`). `erdos_1023` was instead a bare assertion
  `∃ c : ℝ, c > 0 ∧ Tendsto …`. **[defect]** — fixed to `answer(True) ↔ ∃ c : ℝ, …`
  (see Addendum; not compile-verified).
- Polarity verified by hand: RHS true ⟺ such a $c$ exists ⟺ the question's answer is
  "yes". The answer *is* yes ($c = \sqrt{2/\pi}$ via Hunter/Kleitman), so
  `answer(True)` is correct.
- No binders before the colon (`theorem erdos_1023 : answer(True) ↔ …` is binder-free);
  the existential correctly sits inside the iff.
- Raw-vs-styled drift: `conjectures/1023.lean`'s module docstring asked "Is it true
  that there is a constant c > 0 such that F(n) ~ c · 2^n / √n?"; the styled module
  docstring rewrote this as "conjecturing that it is asymptotic to…" and the theorem
  docstring as "There exists a constant…" — the question form was silently dropped
  during restyling, exactly the 1005 drift pattern. Both restored.

## E. Prior-review audit (`ai-review/1023.md`)

Mostly sound on the definitions and the mathematics; three findings:

1. **The A4 defect was missed, twice over.** The ai-review's §5 describes the problem as
   "a precise asymptotic claim" and §6 endorses the `∃ c` encoding without ever noting
   that the source *asks a question* ("Is it true that…?") — despite the recovered page
   (and even the raw file's own docstring) phrasing it as one. The style review
   (`reviews/1023.md` §6) compounds it with a factually false claim: "The problem states
   an assertion: 'There exists a constant c > 0 …' This is **Case 3** (direct
   assertion)." — the same misclassification as `reviews/1005.md`, contradicted by the
   source text. This is the recurring "endorsing an encoding that contradicts the
   source" failure pattern.
2. **Invented non-issue, excused harmlessly.** §6 claims "division by zero at n = 0
   (where √n = 0) produces 0 in ℝ". False in detail: at $n=0$ the *denominator* is
   $c \cdot 2^0 = c \ne 0$; no division by zero occurs anywhere in the main theorem.
   The term is 0 because the *numerator* contains the factor $\sqrt{0} = 0$. The
   conclusion (harmless under `atTop`) stands, but the justification fabricates a
   mechanism — the same class as the 1000 audit's invented off-by-one.
3. **What it got right (verified by re-derivation):** 1023's union-free notion is
   strictly stronger than 447's (a 447-violation $A\cup B = C$ yields the 1023-violation
   $S=\{A,B\}$; strictness via $\{\{a\},\{b\},\{c\},\{a,b,c\}\}$); `sSup`
   well-definedness (nonempty via the empty family, bounded by $2^n$) — here the
   boundedness argument is actually sound, unlike 1005's; and the sandwich
   $\binom{n}{\lfloor n/2\rfloor} \le F_{1023}(n) \le F_{447}(n) \sim
   \binom{n}{\lfloor n/2\rfloor}$ (middle layer is union-free since a union of $\ge 2$
   distinct $k$-sets has size $> k$; singleton subcollections are constraint-free). Its
   citation suggestions (typo note, [Kl71], "Zach Hunter") were all subsequently applied
   in `deepmind/1023.lean`, and its proposed stronger variant was added as the
   central-binomial theorem — nothing it flagged went unfixed.
4. **Minor omission:** it never mentions the page's SOLVED (LEAN) status (Lean
   verification), and its description of the page's Kleitman remark ("unpublished") is
   accurate but it did not flag that [Kl71]'s bibliographic details in the repo trace to
   sibling files rather than this problem's page.
