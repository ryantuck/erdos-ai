## Summary

The problem (erdosproblems.com/15, **OPEN**): *"Is it true that
$\sum_{n=1}^\infty(-1)^n\frac{n}{p_n}$ converges, where $p_n$ is the sequence of
primes?"* Erdős suggested only computational exploration; Tao [Ta23] proved
convergence conditionally on a strong form of the Hardy–Littlewood prime tuples
conjecture. The Lean statement (`conjectures/15.lean:31-37`) asserts
`∃ L : ℝ, Tendsto (fun N => ∑ n ∈ Finset.range N, (-1)^(n+1) * ((n+1)/(Nat.nth
Nat.Prime n : ℝ))) atTop (nhds L)` — read back independently: "the sequence of
partial sums of the series whose (1-indexed) $k$-th term is $(-1)^k k/p_k$ converges
to a real limit." This is exactly the series asked about, term-by-term, and the
assertion takes the conjectured direction (convergence), which is this raw corpus's
convention for open yes/no questions. I found **no semantic defects** — only
scholarship/polish nits (no citation keys, missing page-confirmed variants), all

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Is it true
  that\[\sum_{n=1}^\infty(-1)^n\frac{n}{p_n}\]converges, where $p_n$ is the sequence
  of primes?" The module docstring (lines 14-29) reproduces it faithfully and
  documents the indexing convention accurately.
- Independent back-translation of lines 31-37, term-by-term: `Nat.nth Nat.Prime` is
  the 0-indexed enumeration of an infinite predicate, so `Nat.nth Nat.Prime 0 = 2
  = p_1` and generally `Nat.nth Nat.Prime n = p_{n+1}`. The Lean summand at index
  `n` is $(-1)^{n+1}(n+1)/p_{n+1}$ — exactly the 1-indexed source term at $k = n+1$
  ($(-1)^k k/p_k$). First-index check (not just "in the limit"): Lean $n=0$ gives
  $(-1)^1 \cdot 1/2 = -1/2$; source $k=1$ gives $(-1)^1 \cdot 1/p_1 = -1/2$. ✓
- `Finset.range N` sums Lean indices $0,\dots,N-1$ = source terms $1,\dots,N$, so
  the function of $N$ is precisely the source's $N$-th partial sum $S_N$;
  `Tendsto _ atTop (nhds L)` with `∃ L : ℝ` is the standard encoding of "the series
  converges". Types are right: all arithmetic in ℝ after casting.
- Crucially, the **ordered-partial-sums** formulation (rather than `Summable`) is
  not merely stylistic — it is load-bearing. Mathlib's `Summable` is unconditional
  summability, equivalent over ℝ to absolute convergence, and this series is
  certainly not absolutely convergent ($\sum n/p_n \asymp \sum 1/\log n$ diverges by
  the prime number theorem), so a `Summable` encoding would be provably false and
  would degenerate the open question. The file avoids this trap; the current
  upstream formal-conjectures file does not (see E and Addendum).
- Not vacuous or trivially false: the terms $n/p_n \sim 1/\log n \to 0$ but not
  monotonically (prime gaps fluctuate), so neither divergence-by-terms nor the
  alternating series test settles it — the statement is the genuine open question.

## E. Prior-review audit (`deepmind/ai-review/15.md`)

The prior review was written against the styled copy (`deepmind/deepmind/15.lean`,
which wraps the same statement in `answer(sorry) ↔`). Mostly accurate; one
substantive error, one dated claim, and one prescient-but-unheeded pointer:

1. **Wrong Mathlib-semantics claim (the recurring failure class, cf. the 1002
   audit).** §6 states: "This is equivalent to `Summable` for the terms, but the
   partial-sum formulation is more appropriate here since … the series is not
   absolutely convergent." This is **self-contradictory and the first half is
   false**. Mathlib's `Summable` is unconditional (net-over-finite-subsets)
   summability, which for ℝ-valued series is equivalent to *absolute* convergence —
   for this series *provably false* ($\sum n/p_n \asymp \sum 1/\log n$ diverges),
   while ordered-partial-sums convergence is the genuinely open question. The two
   are inequivalent precisely when the series fails absolute convergence — the very
   situation the review itself invokes. The conclusion ("partial-sum formulation
   appropriate") survives; the equivalence claim would have waved through a
   formalization that trivializes the problem. **This is not hypothetical: the
   current upstream google-deepmind/formal-conjectures `ErdosProblems/15.lean`
   (fresh sparse clone, current main) encodes exactly this bug** — `answer(sorry) ↔
   Summable (fun k : ℕ => (-1 : ℚ)^(k+1) * (k+1) / (k.nth Nat.Prime))`, over ℚ no
   less (summability in ℚ additionally forces a rational limit; via the continuous
   coercion it implies `Summable` in ℝ, hence absolute convergence, hence is
   provably false — the iff decides an open question to "no" by encoding error).
2. **Dated (not wrong at the time): "None of these [three variants] are formalized
   anywhere in the codebase."** True when written; the styled
   `deepmind/deepmind/15.lean` has since added all three (and upstream has a TODO).
   Note that the styled variants pair sign `(-1)^(n+1)` and weight `(n+1)` with
   `primeGap (n+1)`; with the recovered definition `primeGap m = p_{m+2} - p_{m+1}`
   (1-indexed), the faithful factor for source index $k=n+1$ is `primeGap n`, so
   the styled gap factor is one step ahead of the weight — and its docstring's
   stated rationale ("to avoid division by zero at n = 0") is factually wrong
   (`primeGap 0 = 3 - 2 = 1`). The shift is *convergence-equivalent* (the
   difference series after reindexing is dominated by $\sum 1/(j(j-1)g_j)$,
   absolutely convergent), so the styled variants pose equivalent questions, but
   they are not term-faithful translations and the false rationale masks the
   discrepancy. The v2 variants here use the term-faithful indexing.
3. **Citations (§2): accurate and verified.** The key list ([Er97, p.158], [Er97e,
   p.535], [Er98], [Ta23], [Zh14]) and the Weisenberg/Nathanson/Sawhney
   attributions match the recovered page exactly. Its recommendation to add the
   keys was never applied to `conjectures/15.lean` (flagged-but-unfixed) — now
   applied in v2.
4. **Correctness table (§6): verified.** Its three-row index-translation table
   ($-1/2, 2/3, -3/5$) matches my independent computation, and its division-safety
