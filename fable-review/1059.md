## Summary

The problem (erdosproblems.com/1059, status **OPEN**, cited to [Gu04], problem A2 of
Guy's collection): *Are there infinitely many primes $p$ such that $p - k!$ is
composite for each $k$ such that $1 \leq k! < p$?* Examples are $p = 101$ and
$p = 211$. The Lean artifact asserts `Set.Infinite {p | p.Prime ∧ ∀ k, 1 ≤ k! →
k! < p → ¬(p - k!).Prime}`. Read back independently, this says "$p - k!$ is **not
prime**" — which is weaker than "composite", because $1$ is neither prime nor
composite. The two readings genuinely diverge (e.g. $p = 2$ satisfies the Lean
condition but not the source's; every factorial prime $p = k! + 1$ trivially passes
the Lean test at $d = p - 1$ but can never satisfy the source's), and since the
infinitude of factorial primes is itself open, the artifact was a strictly weaker
open statement, not an equivalent rephrasing. The recovered upstream formalization
uses `Nat.Composite` (defined in `FormalConjecturesForMathlib` as `1 < n ∧
¬n.Prime`), confirming the intended reading. This is a Part A defect; fixed in place.

## A. Semantic fidelity

**A1. Statement fidelity — one [defect], otherwise pass (source-verified).**

- Recovered verbatim source statement: "Are there infinitely many primes $p$ such that
  $p-k!$ is composite for each $k$ such that $1\leq k!<p$?" The docstring reproduces it
  exactly.
- Independent back-translation of the pre-fix Lean: "the set of primes $p$ such that
  for every $k$ with $1 \le k!$ and $k! < p$, the number $p - k!$ is **not prime**, is
  infinite."
- **[defect] "composite" ≠ "not prime" at the value 1.** Since $k! < p$, we always
  have $p - k! \ge 1$; the value $1$ (neither prime nor composite) occurs exactly when
  $p = k! + 1$, i.e. $p$ is a factorial prime. Concretely:
  - $p = 2$: the only factorial $< 2$ is $1$, and $2 - 1 = 1$ is not prime, so $2$
    **is** in the pre-fix Lean set; but $1$ is not composite, so $2$ is **not** in the
    source's set (consistent with the page giving $101$ as the first example).
  - For any factorial prime $p = k! + 1$ (e.g. $2$, $3$, $7$, $11! + 1 = 39916801$, …),
    the source's condition *must fail* at the factorial $p - 1$, whereas the pre-fix
    Lean condition is *trivially satisfied* there. So the pre-fix set ⊇ source set,
    with the difference supported on factorial primes.
  - The two `Set.Infinite` statements are **not** known to be equivalent: whether
    infinitely many factorial primes exist is open, so the pre-fix (weaker) statement
    could in principle hold while the answer to the source's question is "no". This is
    a semantic weakening, not a harmless paraphrase. **Fixed** to
    `1 < p - k.factorial ∧ ¬ (p - k.factorial).Prime` (see Addendum; not
    compile-verified), which matches the upstream `Nat.Composite` semantics exactly.
- Quantifiers: "$\forall k$ with $1 \le k! < p$" is rendered as `∀ k : ℕ,
  1 ≤ k.factorial → k.factorial < p → …` — correct; $k = 0$ and $k = 1$ both give
  $k! = 1$, a harmless duplicate that matches the source's quantification over $k$
  (not over factorial values).
- Types: everything in ℕ; `Set.Infinite` over `{p : ℕ | …}` correctly encodes
  "infinitely many primes".
- Not vacuous/trivial (post-fix): $101 \in$ the set ($100, 99, 95, 77$ all composite),
  $211 \in$ the set ($210, 209 = 11\cdot19, 205, 187 = 11\cdot17, 91 = 7\cdot13$); the
  set is not trivially infinite (most small primes fail, e.g. $89 - 3! = 83$ is prime).

**A2. Lean semantics traps — pass (post-fix).**

- ℕ subtraction `p - k.factorial`: guarded by the hypothesis `k.factorial < p`, so no
  truncation at the point of use. (Pre-fix it never truncated either; the defect was
  the value $1$, not truncation.)
- No division anywhere.
- No `Finset.range`; the bounded quantification is by explicit hypotheses, matching
  the source's $1 \le k! < p$ with no off-by-one.
- Vacuous quantifier check: for $p = 2$ the quantifier is *not* vacuous ($k! = 1 < 2$),
  and post-fix $2$ is correctly excluded ($1 < 2 - 1$ is false). The hypothesis
  `1 ≤ k.factorial` is itself vacuously true for all $k$ (`Nat.factorial_pos`) — kept
  deliberately as it mirrors the source phrasing; documented in the docstring.
- "Infinitely many" via `Set.Infinite` is the standard correct encoding; no filters
  needed.
- No `StrictMono`/`Monotone` or interval-endpoint issues arise.

**A3. Definitions — pass.**

- The file has no helper `def`/`abbrev`/`structure` (raw style, everything inline), so
  there is nothing to drift and no `sorry` outside proof bodies. The upstream file
  factors the statement through `IsFactorial`/`factorialsLessThanN`/
  `AllFactorialSubtractionsComposite`; the inline form here is logically equivalent
  post-fix (quantifying over $k$ with $k! < p$ ⟺ quantifying over factorial values
  $d < p$, since $1 \le k!$ always holds).

**A4. Question form and answer polarity — acceptable raw style, noted.**

- No binders before the colon; nothing is spuriously universally quantified.

**A5. Solution status — pass (source-verified).**
