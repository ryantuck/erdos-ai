## Summary

The problem (verbatim from the recovered page): "Let ε > 0. Is it true that, if k is
sufficiently large, then R(G) > (1−ε)^k R(k) for every graph G with chromatic number
χ(G) = k? Even stronger, is there some c > 0 such that, for all large k,
R(G) > cR(k) for every graph G with chromatic number χ(G) = k?" Status OPEN. The
Lean file defines `containsSubgraph` (injective edge-preserving map), the graph
Ramsey number `graphRamseyNumber H = sInf {N | ∀ G on Fin N, G or Gᶜ contains H}`,
and `diagRamsey k = R(K_k)`, then asserts both questions' affirmative directions:
`∀ ε ∈ (0,1), ∃ K, ∀ k ≥ K, ∀ finite G with χ(G) = k, R(k)·(1−ε)^k < R(G)`
(`conjectures/87.lean:54-60`) and `∃ c > 0, ∃ K, ∀ k ≥ K, …, c·R(k) < R(G)`
(lines 68-74). Read back independently, both Lean statements say exactly what the
page asks, with correct quantifier order (c is an absolute constant), correct strict
inequalities, and definitions that are exact on small cases. No semantic defects;
only polish-level findings.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Back-translation of `erdos_problem_87_weak` (lines 54-60): "for every ε ∈ (0,1)
  there is a K such that for every k ≥ K and every finite graph G with chromatic
  number exactly k, R(k)·(1−ε)^k < R(G)" — precisely question 1 as asked (product
  order swapped across the `<`, mathematically identical). Back-translation of
  `erdos_problem_87_strong` (lines 68-74): "there are c > 0 and K such that for all
  k ≥ K and all finite G with χ(G) = k, c·R(k) < R(G)" — precisely question 2.
- Quantifier structure: "sufficiently large k" = `∃ K, ∀ k ≥ K` — standard and
  correct. In the strong form `∃ c` sits *outside* `∃ K, ∀ k`, so c is the absolute
  constant the source demands (batch problem-55-class check: nothing for c to
  absorb; the reversed order would have been wrong, and is not present).
- The ε < 1 restriction (line 55) against the source's bare "Let ε > 0": faithful
  and in fact necessary. For ε ≥ 2 and even k, (1−ε)^k = (ε−1)^k ≥ 1, and G = K_k
  (which has χ = k and R(G) = R(k)) falsifies R(G) > (ε−1)^k R(k); mixed parities
  then kill `∃ K ∀ k ≥ K`. So the unrestricted literal reading is provably false and
  cannot be the intended question; the page itself notes the problem "is trivial for
  ε ≥ 3/4 since R(k) ≤ 4^k", confirming the intended regime is small ε. Restricting
  to (0,1) loses nothing (smaller ε is the stronger question). Documented in v2.
- Types: ℝ for ε and the inequality (casts on both Ramsey numbers), ℕ for k and the
  Ramsey numbers themselves — arithmetic happens in ℝ where (1−ε)^k lives. `(1-ε)^k`
  is `Monoid.npow` with ℕ exponent — no `rpow` subtleties.
- `G.chromaticNumber = k`: Mathlib's `chromaticNumber : ℕ∞` with `↑k` coercion —
  "chromatic number exactly the finite value k", correct (and finite graphs always
  have finite chromatic number, so no ⊤-junk interaction).
- Indexing: no sequences to reconcile; `Fin N` is the standard N-vertex model.
- Not vacuous / not trivially false: for k ≥ 1 the quantified G are nonempty (χ = k
  ≥ 1), so R(G) ≥ 1 and both inequalities are substantive; K_k itself witnesses that
  the strong form is best-possible at c → 1. The k = 0 degeneracy (empty graph,
  χ = 0, R(G) = 0, making both strict inequalities false at k = 0) is absorbed by
  `∃ K` — checked by hand per the batch degenerate-input warning (problems
  20/78/80/84 class); no small-parameter falsification exists as written.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction, no division anywhere. `1 - ε` is ℝ subtraction — exact.
- No `Finset.range`. The only `sInf` is `Nat.sInf` (see A3); no ℝ-valued
  `liminf`/`limsup`/`sSup` junk (problem-33 class n/a).
- Vacuous quantifiers: `containsSubgraph G H` for H on an empty vertex type holds
  vacuously (any f from the empty type works), giving R(K_0) = 0 — a degenerate
  value the theorems never touch (χ(G) = k ≥ K ≥ 1 in any true instantiation).
- "For all sufficiently large k" encoded as `∃ K, ∀ k, K ≤ k → …` — the standard
  unfolding of `∀ᶠ k in atTop`; correct.
- Strictness: both `<` match the source's `>` exactly (strict). ε bounds `0 < ε`,
  `ε < 1` are strict, matching "(0, 1)" intent.
- Instance/implicit binders: `∀ {V : Type*} [Fintype V] (G : SimpleGraph V)` — the
  universal over all finite vertex types in an auto-bound universe; standard and
  semantically what "every finite graph" means (every finite graph is isomorphic to
  one on some Fintype in any universe, and the ∀ ranges over all of them; no
  degenerate instantiation escapes it).

**A3. Definitions — pass (small-case verified).**

- `containsSubgraph G H` (lines 33-34): injective f with `H.Adj u v → G.Adj (f u)
  (f v)` — exactly "G contains a copy of H as a not-necessarily-induced subgraph",
  the correct containment notion for Ramsey numbers (induced containment would have
  been a defect; it is not used). Argument order (G contains H) is used consistently.
- `graphRamseyNumber` (lines 40-42): the defining set is **upward closed** (a
  witness colouring on N + 1 vertices restricts to the first N vertices; complement
  of an induced subgraph = induced subgraph of the complement), so `sInf` is the
  genuine minimum, not a spurious infimum. **Nonempty for finite H** by Ramsey's
  theorem (contains H's vertex count ≤ some R), so no `Nat.sInf ∅ = 0` junk in any
  instantiation the theorems make: `[Fintype V]` on the theorems excludes the one
  junk case (infinite H, empty set, value 0 — which, unguarded, would have
  *falsified* the statements; the guard is load-bearing and present).
- Small-case hand-verification (batch checklist; computed from the Lean text, not
  the docstring): R(K_0) = 0 (vacuous containment puts 0 in the set); R(K_1) = 1
  (N = 0 fails — no map Fin 1 → Fin 0; N = 1 succeeds); R(K_2) = 2 (N = 1 fails —
  ⊥ and ⊥ᶜ = ⊥ on one vertex contain no edge; N = 2: any G on two vertices has an
  edge in G or Gᶜ). All match the true diagonal Ramsey values R(0)=0, R(1)=1,
  R(2)=2.
- `diagRamsey k = graphRamseyNumber (⊤ : SimpleGraph (Fin k))` — `⊤` on `Fin k` is
  K_k; correct.
- Each def matches its docstring; no `sorry` in any def (the file's two `sorry`s
  are theorem proof bodies, lines 60 and 74).
