## Summary

The problem (DISPROVED on the source page): "Do there exist infinitely many $n$ such
that $n-2x^2$ is prime for all $x$ with $2x^2<n$?" The known such $n$ are
$2, 5, 7, 13, 31, 61, 181, 199$, and by Epure–Gica [EpGi10] (Theorem 4.1, for
$n \equiv 1 \pmod 4$) coupled with Mollin–Williams [MoWi89] (for
$n \equiv 3 \pmod 4$, with at most one further exception) this list is complete up to
at most one exception — so the set is finite and the answer is "no". The Lean
(`conjectures/1140.lean:25-27`) asserts `Set.Finite {n : ℕ | AllShiftsArePrime n}`
with `AllShiftsArePrime n := ∀ x : ℕ, 2 * x ^ 2 < n → Nat.Prime (n - 2 * x ^ 2)`
(lines 9–10). Read back independently, this is exactly the true ("no") direction of
the question, stated as a direct assertion — acceptable for a solved problem under
this pipeline's rules, with correct polarity. The mathematics is sound; the defects
are bibliographic: the file uses `[Va99, 1.5]` and `[EpGi10]` without defining either
key, and omits `[MoWi89]` entirely while silently folding its contribution into the
`[EpGi10]` attribution. (The styled archive's definition of `[Va99]` as Vaughan's
*Hardy-Littlewood Method* is a hallucination — the key is the Budapest 1999 booklet
*Some of Paul's favorite problems*, §1.5 — and was deliberately not imported when
rebuilding the bibliography in v2.)

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified + computationally corroborated).**

- Recovered verbatim source statement (see Addendum): "Do there exist infinitely many
  $n$ such that $n-2x^2$ is prime for all $x$ with $2x^2<n$?" — status banner
  **DISPROVED**, tooltip "This has been solved in the negative."
- Independent back-translation of lines 25–27: "the set of natural numbers $n$ such
  that $n - 2x^2$ is prime for every natural $x$ with $2x^2 < n$ is finite." Finiteness
  is precisely the negation of the infinitude asked about (for subsets of ℕ,
  `Set.Finite ↔ ¬ Set.Infinite` via `Set.not_infinite`), i.e. the proven direction.
- Quantifier domain verified against the page's own data, not just read off: brute
  force to $2\times 10^5$ under the Lean encoding (`x : ℕ` from 0, strict `<`) yields
  exactly $\{0\} \cup \{2, 5, 7, 13, 31, 61, 181, 199\}$ — the page's known list plus
  the vacuous $n = 0$ (below). Both encoding choices are **load-bearing**:
  - starting `x` at 1 instead of 0 would admit $4, 15, 21, 25, 49, 55, 91, \ldots$
    (e.g. $4 - 2 = 2$ is prime), contradicting the page's list — so including
    `x = 0` (which forces $n$ itself prime) is correct;
  - non-strict `2x^2 ≤ n` would demand `Nat.Prime 0` at $n = 2x^2$ and wrongly
    exclude $n = 2$ — so strict `<` is correct.
- Indexing: no sequences, no index shifts to reconcile.
- Not vacuous/trivial: finiteness of this set is a genuine theorem resting on
  Epure–Gica's class-field-flavored work plus Mollin–Williams; the statement has real
  content.

**A2. Lean semantics traps — pass, one documented blemish.**

- **ℕ subtraction** `n - 2 * x ^ 2` (line 10) is guarded by `2 * x ^ 2 < n`, so it
  never truncates and the argument of `Nat.Prime` is positive. Correct.
- No division anywhere.
- No `Finset.range`, no filters, no `StrictMono`/`Monotone`.
- **Vacuous quantifier at `n = 0`:** no `x : ℕ` satisfies `2 * x ^ 2 < 0`, so
  `AllShiftsArePrime 0` holds vacuously and `0` is a spurious member of the set
  (confirmed by the brute-force run). The source's list does not contain 0. This does
  **not** affect the truth value or meaning of the finiteness assertion (the sets
  differ by one element), so it is a [polish]-level blemish, not a defect — now
  documented in the v2 definition docstring, and excluded by a `0 < n` guard in the
  completeness variant where it *would* matter (it would otherwise consume the "at
  most one exception" slot).
- $n = 1$ is correctly excluded (`x = 0` demands `Nat.Prime 1`, false); $n = 3$
  correctly excluded ($3 - 2 = 1$ not prime); $n = 4$ correctly excluded ($4$ not
  prime at `x = 0`).

**A3. Definitions — pass.**

- `AllShiftsArePrime` (lines 9–10) matches its docstring and the source's defining
  property, including the degenerate `n = 0` behavior discussed above. No `sorry` in
  any definition. No drift between the def and the theorem's use of it.

**A4. Question form and answer polarity — pass.**

- The source is a yes/no question ("Do there exist infinitely many…?"), solved in the
  negative. The file states the **true direction as a direct assertion**
  (`Set.Finite …`), which this pipeline explicitly accepts for solved problems when
  the polarity is the true direction — and it is: finite ⟺ not infinitely many ⟺ the
  answer "no".
- Polarity cross-checked against the styled encoding: the upstream formal-conjectures
  file (recovered from the logs, and it compiled there) states
  `answer(False) ↔ Set.Infinite {n : ℕ | AllShiftsArePrime n}` — logically equivalent
  to the assertion here (`False ↔ P` ⟺ `¬P`, and `¬ Set.Infinite s ↔ s.Finite`).
- No binders before the colon (line 25: `theorem erdos_problem_1140 :` is
  binder-free); no `answer()` in this raw file, so the binder rule is moot.

**A5. Solution status — pass (source-verified).**

- Recovered banner: **DISPROVED** — "This has been solved in the negative." The
  docstring's "(Disproved)" heading (line 13) and its closing remark ("with at most
  one exception, the list above is complete") agree with the page. The docstring's
  inference chain is sound: the two odd congruence classes are covered by
  [EpGi10] (+[MoWi89]), and even $n$ must be prime (take $x = 0$), hence $n = 2$; so
  the whole set is the 8-element list plus at most one exception — finite. (The v2
  docstring now spells out the even case, which the input left implicit.)
- Attribution nuance fixed in v2: the input credits both congruence classes wholly to
  Epure–Gica; the page attributes the $n \equiv 3 \pmod 4$ case to Epure–Gica's
  method *coupled with* Mollin–Williams [MoWi89] (see B1).
