## Summary

The problem: let $f(n,k)$ be such that every graph on $n$ vertices and $k$ edges can be
partitioned into at most $f(n,k)$ edge-disjoint complete graphs (the *clique partition
number*); estimate $f(n,k)$ for $k > n^2/4$. Erdős–Goodman–Pósa proved
$f(n,k) \le \lfloor n^2/4\rfloor$ for all $k$ (edges and triangles suffice), best possible
via complete bipartite graphs; in [Er71] Erdős asks "vaguely" whether this can be
'sharpened' for $k > n^2/4$. Status on the recovered page: **OPEN**. The Lean
(`deepmind/1017.lean:66`, pre-fix numbering) encodes the weakest nontrivial reading as an
open yes/no question: `answer(sorry) ↔ ∀ᶠ n in atTop, ∀ G` with more than
$\lfloor n^2/4\rfloor$ edges, there is a partition of the edge set into fewer than
$\lfloor n^2/4\rfloor$ edge-disjoint clique edge-sets. Read back independently, the Lean
and the English agree; the strict/floor arithmetic is term-by-term exact; I found no
semantic defects, only enrichment-level nits (now applied — see Addendum).

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement: "Let $f(n,k)$ be such that every graph on $n$
  vertices and $k$ edges can be partitioned into at most $f(n,k)$ edge-disjoint complete
  graphs. Estimate $f(n,k)$ for $k>n^2/4$." Remarks add: EGP66 proved
  $f(n,k)\leq n^2/4$, best possible in general; "In [Er71] Erdő [sic] asks vaguely
  whether this result can be 'sharpened' for $k>n^2/4$."
- Independent back-translation of the main theorem: "for all sufficiently large $n$,
  every graph $G$ on $n$ labelled vertices with more than $\lfloor n^2/4\rfloor$ edges
  admits $k < \lfloor n^2/4\rfloor$ pairwise-disjoint sets of unordered pairs whose union
  is exactly the edge set of $G$, each set being the complete edge set on some clique of
  $G$." This is precisely "$f(n,k) < \lfloor n^2/4\rfloor$ whenever $k > n^2/4$ ($n$
  large)" — the qualitative core of "can the bound be sharpened". Since "estimate" is
  deliberately vague (the page's own word), the weakest-nontrivial-question reading with
  `answer(sorry)` is the right formalization scope; the prior review's three-way reading
  analysis (qualitative/quantitative/asymptotic) is sound and the qualitative choice is
  appropriate.
- The clique-part encoding `parts i = S.offDiag.image (Quot.mk _)` with
  `G.IsClique ↑S` is exactly the edge set of the complete graph on $S$: `offDiag`
  excludes the diagonal (no loops), the `Sym2` quotient dedups orientations, and
  `IsClique` puts every such pair in `G.edgeFinset`. Coverage
  `∀ e, e ∈ G.edgeFinset ↔ ∃ i, e ∈ parts i` plus pairwise `Disjoint` makes the union an
  exact partition of the edge set.
- Not vacuous: for large $n$ graphs with more than $\lfloor n^2/4\rfloor$ edges abound,
  and whether all of them beat the EGP bound is a substantive open question (the
  $K_4$-free case needed Győri–Keszegh's Combinatorica paper). RHS true ⟺ answer "yes";
  RHS false ⟺ answer "no"; neither degenerate.
- Empty parts are permitted (a singleton or empty $S$ gives `parts i = ∅`); this is
  *logically equivalent* to a nonemptiness-requiring version, since empty parts can
  always be dropped from a witness (see E for the prior review's slightly-off claim
  here). No defect.

**A2. Lean semantics traps — pass.**

- ℕ division `n ^ 2 / 4` floors, i.e. computes $\lfloor n^2/4\rfloor$ — and both uses
  are term-by-term exact against the source's real-number thresholds, not merely
  asymptotically: for integer $c$, $c > n^2/4 \iff c \ge \lfloor n^2/4\rfloor + 1 \iff$
  `c > n^2/4` in ℕ (for odd $n$, $n^2/4 = \lfloor n^2/4\rfloor + 1/4$, and there is no
  integer in $(\lfloor n^2/4\rfloor, n^2/4]$). Likewise "sharpened below the bound
  $\lfloor n^2/4\rfloor$" is exactly `k < n ^ 2 / 4` in ℕ.
- No ℕ subtraction in the pre-fix file. The new Lovász variant introduces
  `n.choose 2 - G.edgeFinset.card` and `t ^ 2 - t`; both are truncation-safe
  ($k \le \binom n2$ always; $t \le t^2$ always) and this is documented in its
  docstring.
- Vacuous small cases: for $n \le 2$ no graph has more than $\lfloor n^2/4\rfloor$
  edges, so the inner implication is vacuous there; `∀ᶠ n in atTop` makes this
  irrelevant anyway. `Fin k` with `k = 0` cannot satisfy coverage for a graph that has
  edges, and a graph beyond the threshold always has edges — no degenerate witness.
- `∀ᶠ n in atTop` is the standard "for all sufficiently large $n$" encoding. The source
  does not literally restrict to large $n$; for a vague "estimate"-type asymptotic
  question this guard is a defensible (arguably preferable) choice that avoids
  small-$n$ accidents, and the theorem docstring now states it explicitly (Addendum
  fix 2). Not a defect.
- No `StrictMono`/`Monotone` or interval-endpoint issues arise. `haveI := dG` binding a
  quantified `DecidableRel G.Adj` is the standard pattern for `edgeFinset` on `Fin n`.

## E. Prior-review audit (`ai-review/1017.md`)

Substantially accurate — the best of the prior reviews audited in this series. Findings:

1. **"Slightly weaker than it could be" is slightly wrong (empty parts).** §6 says
   allowing empty parts means "the bound $k < n^2/4$ is slightly weaker than it could
   be", with nonemptiness as a strengthening. In fact the two formulations are
   *logically equivalent*: from any witness one deletes the empty parts and reindexes,
   getting $k' \le k$ nonempty parts, so requiring nonemptiness changes nothing. Calling
   it a weakening is the familiar invent-a-discrepancy-then-excuse-it pattern (cf. the
   1000 audit) in miniature; harmless here, but the correct statement is equivalence,
   not harmless weakness.
2. **Exactness of the floor threshold asserted without derivation.** §6 says
   `card > n ^ 2 / 4` "correctly captures $k > n^2/4$" — true, but the odd-$n$ case
   (where $n^2/4$ is not an integer and the claim needs there to be no integer in
   $(\lfloor n^2/4\rfloor, n^2/4]$) is never checked. Re-derived here: exact (A2).
3. **"Exact partition" attributed to the wrong conjunct.** §6 credits the coverage
   biconditional with requiring "every edge in exactly one part"; the ↔ alone gives *at
   least* one part — exactly-one needs the disjointness conjunct as well. The
   formalization does have both, so the conclusion stands.
4. **Code-reuse claims verified.** The descriptions of 81 (vertex-set approach), 807
   (`IsBicliqueCover`), and 1009 (`HasEdgeDisjointTriangles`) all check out against this
   repo's `deepmind/` siblings.
5. **What it flagged vs what got fixed.** Its citation suggestion (mention Lovász and
   Győri–Keszegh in the docstring) *was* implemented by the upstream fix session
   (log-verified, including the `lake build`). Its suggested GyKe variant was **not**
   implemented upstream — done now (Addendum fix 3). Its readability suggestions
   (comments on `haveI`/`offDiag`) remain unapplied — [polish], compile-sensitive
   region left alone.
6. **Omission:** it never mentions the page's cross-references ([184], [583], [81]) or
   the framing that the $K_4$-free special case "was also asked about by Erdős", and it
   does not note that the GyKe17 volume number it implicitly blesses is absent from the
   site's own `/latex` source.

Also audited: `reviews/1017.md` (style review) had flagged the raw file's two blocking
defects (wrong theorem formalized; wrong category) — both were correctly fixed in
`deepmind/1017.lean` exactly as it prescribed, and its factual claims about the page
