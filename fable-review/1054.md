## Summary

The problem (erdosproblems.com/1054, verbatim from the recovered page): "Let $f(n)$ be
the minimal integer $m$ such that $n$ is the sum of the $k$ smallest divisors of $m$ for
some $k\geq 1$. Is it true that $f(n)=o(n)$? Or is this true only for almost all $n$,
and $\limsup f(n)/n=\infty$?" A question of Erdős from problem B2 of Guy's collection
[Gu04]; page status OPEN; the remarks record that Tao, in the comments to problem
[468], disproved the strong claim by proving the upper density of
$\{n : f(n)\leq \delta n\}$ is $\ll \delta^2$. The Lean file defines the sorted divisor
list, prefix sums, the attainable-sums set $S(m)$, and $f(n) = \mathrm{sInf}\,\{m : n \in
S(m)\}$ — all correct, including degenerate cases. The two pre-fix theorems, however,
got the solution status wrong in both directions: `erdos_problem_1054_strong` asserted
the Tao-disproved statement positively, and `erdos_problem_1054` asserted the
almost-all form as "the remaining open question" although Tao's quoted bound refutes
that too (a density-1 set with $f(n) \le \delta n$ would contradict upper density
$\le C\delta^2 < 1$ at small $\delta$). Both were fixed by negation; the genuinely open
residue ($\limsup f(n)/n = \infty$) and Tao's quantitative bound were added.

## A. Semantic fidelity

**A1. Statement fidelity — definitions pass (source-verified); theorem-level status
defects deferred to A4/A5.**

- The module docstring reproduces the site's problem statement essentially verbatim
  (checked word-for-word against the recovered `problem-text` div).
- `erdos1054_sortedDivisors` (sorted ascending via `Finset.sort (· ≤ ·)`) and
  `erdos1054_prefixSums` (accumulator prefix sums) together enumerate exactly the sums
  of the $k$ smallest divisors of $m$ for $k = 1, \dots, d(m)$: the empty-list case
  returns `[]`, so the degenerate $k = 0$ sum (the bare accumulator 0) is *not*
  included — the source's $k \ge 1$ is enforced structurally. Term-by-term check at the
  first index: the head is $\mathrm{acc} + d_1 = 0 + 1 = 1$ for every $m \ge 1$
  (smallest divisor is 1), matching $k = 1$.
- `erdos1054_S` deduplicates via `toFinset` (harmless — prefix sums of positive
  divisors are strictly increasing, so there are no duplicates); `erdos1054_S 0 = ∅`
  since `Nat.divisors 0 = ∅`, so $m = 0$ can never be a witness and genuine values of
  $f$ are $\ge 1$.
- `erdos1054_f` is the source's "minimal integer $m$" when a witness exists. When none
  exists, `sInf ∅ = 0` is a junk value. The source itself flags this: $f$ is undefined
  at $n = 2$ and $n = 5$ (verified by hand: $1 + d_2 = 2$ forces $d_2 = 1$; for $n = 5$,
  $1 + d_2 = 5$ forces $d_2 = 4$, impossible since $4$ composite would put $2$ below it,
  and $k \ge 3$ sums are $\ge 6$), and well-definedness for all $n \ge 6$ is itself open
  (follows from a strong form of Goldbach). The junk convention silently counts
  undefined $n$ as having $f(n) = 0$, i.e. as satisfying "$f(n) < \varepsilon n$" — a
  fidelity nuance that interacts with the negated statements (see A2/A4); now documented
  in the docstrings.
- Not vacuous: with genuine values $\ge 1$ and witnesses like $f(4) = 3$
  ($S(3) = \{1, 4\}$), the statements are substantive.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere.
- Division: only real division `card / (x : ℝ)`, returning 0 at $x = 0$ — harmless
  under `atTop`. No ℕ division.
- Interval: `Finset.Icc 1 x` has exactly $x$ elements, so `card/x` is a genuine
  proportion; $n = 0$ (junk $f(0) = 0$) is correctly excluded from the count.
- Vacuous/degenerate cases: the $k = 0$ prefix sum is structurally excluded (above);
  `erdos1054_S 0 = ∅` prevents a spurious $m = 0$ witness.
- Junk values: `sInf ∅ = 0` at $n \in \{2, 5\}$ (and any other $n$ with no
  representation — a set now known to have density 0 by classical almost-all
  Goldbach/Vinogradov arguments, but conjecturally just $\{2, 5\}$ for $n \ge 6$).
  In the pre-fix statements the junk $n$ counted as "$f$ small"; in the fixed
  (negated) statements this means the negations use, in addition to Tao's bound, the
  density-0 fact for the undefined set — documented honestly in the docstrings. The
  added Tao-bound variant is junk-free by construction (guard `0 < erdos1054_f n`),
  and the added limsup statement's witnesses automatically have $f(n) > 0$.
- Filter encodings: `Tendsto _ atTop (nhds 0)` for density → 0 is standard and
  correct; the boundary choice `≥ ε·n` (vs `>`) in the filtered set is immaterial
  since $\varepsilon$ is universally quantified.
- No `StrictMono`/`Monotone` or open/closed-interval issues.

**A3. Definitions — pass.**

- All four defs match their docstrings and the source's definition, including
  degenerate inputs (`divisors 0 = ∅`, empty prefix sums, `sInf ∅ = 0` now
  documented). No `sorry` in any def.
- No drift between what the defs compute and what the theorems need.

**A4. Question form and answer polarity — DEFECT (fixed).**

- The source is a compound yes/no question. Raw-file style permits direct assertions
  *in the true direction*; wrong polarity is a defect.
- **[defect 1]** `erdos_problem_1054_strong` asserted $f(n) = o(n)$ *positively*
  (`∀ ε > 0, ∃ n₀, ∀ n ≥ n₀, f(n) < εn` with proof `sorry`) while its own docstring
  said "(DISPROVED by Tao)". Formalizing the refuted direction is exactly the
  wrong-polarity failure the checklist targets. **Fixed** by negation (¬ wrapped around
  the unchanged body); not compile-verified.
- **[defect 2]** `erdos_problem_1054` asserted the almost-all form positively, with
  docstrings (module and theorem) declaring it "the remaining open question"/"OPEN".
  This is refuted by the page's own quoted Tao bound: if $f(n) \le \varepsilon n$ held
  on a density-1 set, $\{n : f(n) \le \varepsilon n\}$ would have upper density 1 for
  each $\varepsilon$, contradicting $\le C\varepsilon^2 < 1$ for
  $\varepsilon < 1/\sqrt{C}$. (The refutation is robust: *any* upper-density bound
  $< 1$ for *any single* $\delta$ suffices; and under either reading of "almost all" —
  density 1 or cofinite — the claim dies.) **Fixed** by negation, with the docstring
  recording the derivation and the junk-value caveat; not compile-verified.
- The genuinely open residue of the source's question — $\limsup f(n)/n = \infty$ —
  was entirely missing. **Added** as `erdos_problem_1054_limsup` (raw direct-assertion
  style in the direction the source's phrasing suggests, with a note that styled form
  would be `answer(sorry) ↔ …`).

**A5. Solution status — DEFECT (same root cause as A4; fixed).**

- The recovered page banner is **OPEN** (tooltip: "This is open, and cannot be resolved
  with a finite computation."), with the owner's standard disclaimer. But the page's
  remarks record Tao's disproof of the strong claim, and — as derived above — the
  quoted quantitative bound settles the almost-all alternative negatively as well. The
  pre-fix module docstring's sentence "The remaining open question is whether
  $f(n) = o(n)$ for almost all $n$" was therefore wrong on the page's own evidence.
  The open banner is faithfully explained in the fixed docstring as attaching to the
  final alternative ($\limsup f(n)/n = \infty$) and the well-definedness question.
- Note the tension is present upstream too: the recovered skeleton of
  google-deepmind/formal-conjectures' `1054.lean` encodes even part (i), the strong
  form, as `answer(sorry)` — i.e. unresolved — despite the page remark (the upstream
  file may predate the 06 Dec 2025 page edit). Out of scope to fix, but recorded.
