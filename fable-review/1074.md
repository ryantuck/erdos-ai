## Summary

The problem (OPEN, page edition 04 October 2025): let $S$ be the set of
$m \ge 1$ such that some prime $p \not\equiv 1 \pmod m$ divides $m!+1$ ("EHS
numbers", OEIS A064164, beginning $8, 9, 13, \dots$), and let $P$ be the set of
primes $p$ such that some $m$ (intended $m \ge 1$) has $p \not\equiv 1 \pmod m$
and $p \mid m!+1$ ("Pillai primes", OEIS A063980, beginning $23, 29, 59,
\dots$). Does $\lim |S \cap [1,x]|/x$ exist, and what is it? Does
$\lim |P \cap [1,x]|/\pi(x)$ exist, and what is it? The Lean file defines both
predicates and the three counting functions, and asserts as `sorry`'d theorems
the conjectured answers: both limits exist and equal 1 (the belief recorded in
[HaSu02] — firm for $S$, where Erdős "later agreed", tentative for $P$). The
encodings of counting, density, modular non-congruence, and the limits are all
correct; the one semantic defect is that `IsPillaiPrime` omitted the `m ≥ 1`
guard, under which `m = 0` (where `¬(p % 0 = 1 % 0)` means `p ≠ 1` and
`0! + 1 = 2`) makes 2 a Pillai prime — contradicting the source sequence, the
file's own docstring, and the upstream artifact, which both guards `m ≥ 1` and
proves `¬ 2 ∈ Nat.PillaiPrimes` as a test theorem.

## A. Semantic fidelity

**A1. Statement fidelity — pass after fix (source-verified).**

- Recovered verbatim source statement (see Addendum) matches the two-part
  question. Independent back-translation of `erdos_problem_1074a`
  (lines 103–107 pre-fix): "the number of EHS numbers in $[0,N]$, divided by
  $N$, tends to 1 as $N \to \infty$ over ℕ". Since `IsEHSNumber` requires
  `1 ≤ m`, the `range (N+1) = {0,…,N}` count is exactly $|S \cap [1,N]|$ —
  no off-by-one. Likewise `pillaiPrimeCount`/`primeCount1074` count exactly
  $|P \cap [1,N]|$ and $\pi(N)$ (0 and 1 are not prime).
- The source's limit variable is a real $x \to \infty$; the Lean limit is over
  ℕ. Standard and harmless: the counting functions are constant on $[N, N+1)$
  and $x/\lfloor x \rfloor \to 1$, so the ℕ-limit and ℝ-limit statements are
  equivalent for both quotients. This is the corpus's usual encoding.
- Question form vs assertion: the source asks "does the limit exist? what is
  it?" (twice) — the file asserts the *conjectured* resolutions
  (limit exists and $= 1$). For a raw plain-Mathlib file (no `answer()`
  elaborator available), asserting the page-documented conjectured direction is
  acceptable raw style; the docstrings now state explicitly which part is the
  question and which the conjectured answer, and companion `..._exists`
  theorems state the literal existence questions (Addendum fixes 3–4). For
  part (a) the conjectured value 1 is firmly page-backed ("makes us believe
  that their asymptotic density exists and is unity. Erdős … later agreed");
  for part (b) it is [HaSu02]'s hedged extrapolation ("no reason why the ratio
  should not tend to 1"), now flagged as tentative in the docstring.
- Not vacuous: both limits are genuine open questions; the density-1 claims are
  falsifiable (e.g. part (a) fails if $S$ misses a positive proportion of ℕ).

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere.
- Division is field division in ℝ after casts: at `N = 0`, `0/0 = 0`; for
  `N < 2`, `primeCount1074 N = 0` and the part (b) quotient is 0 by the
  division-by-zero convention — both invisible to `atTop`. ℕ division never
  occurs.
- `range (N + 1)` is $\{0,…,N\}$; combined with `1 ≤ m` (resp. primality) this
  realizes $[1,N]$ exactly (see A1). No off-by-one.
- `¬(p % m = 1 % m)` is definitionally `¬ p ≡ 1 [MOD m]` (`Nat.ModEq n a b` is
  `a % n = b % n`), and writing `1 % m` rather than `1` is exactly right at
  `m = 1`: `p % 1 = 0 = 1 % 1`, so every prime is $\equiv 1 \pmod 1$ and
  `m = 1` can never witness either predicate — matching the source ($1 \notin
  S$; no Pillai witness from $m = 1$). **At `m = 0`, however, `p % 0 = p` and
  `1 % 0 = 1`, so the condition is `p ≠ 1`** — the root of the A3 defect below.
- `Tendsto _ atTop (nhds 1)` is the standard, correct encoding of the limits;
  `∃ c, Tendsto _ atTop (nhds c)` (the added variants) is the standard encoding
  of "the limit exists".
- No `StrictMono`/`Monotone` or interval-endpoint issues arise.

**A3. Definitions — one [defect], fixed.**

- `IsEHSNumber` (line 74): matches its docstring and the source, including the
  `1 ≤ m` guard; degenerate `m = 0` correctly excluded; `m = 1, 2` correctly
  fail via the mod condition / tiny factorials (sequence starts at 8; spot
  check: $8! + 1 = 40321 = 61 \cdot 661$ with $61 \equiv 5 \pmod 8$, so
  $8 \in S$).
- **`IsPillaiPrime` (pre-fix line 38–39): [defect].** The existential ranged
  over all `m : ℕ` with no `1 ≤ m` guard. Take `m = 0`: `0! + 1 = 2`, so
  `p ∣ 2` forces `p = 2`, and `¬(2 % 0 = 1 % 0)` is `2 ≠ 1`, true. Hence
  `IsPillaiPrime 2` held, contradicting (i) the source sequence
  $P = 23, 29, 59, \dots$ quoted in the file's own module docstring, (ii) OEIS
  A063980, and (iii) the upstream formal-conjectures artifact, which defines
  `Nat.PillaiPrimes` with `∃ m ≥ 1, …` and *proves* `¬ 2 ∈ Nat.PillaiPrimes`
  as a `@[category test]` theorem. No prime other than 2 is affected (only
  `p ∣ 2` can use `m = 0`), so `pillaiPrimeCount` was inflated by exactly 1 for
  `N ≥ 2` and the part (b) *limit* statement's truth value was unchanged — but
  the definition contradicted its docstring and the source, which is a defect
  regardless of asymptotic harmlessness. **Fixed** by adding `1 ≤ m ∧` (not
  compile-verified). Provenance twist: the earlier 2026-02-22 pipeline session
  wrote this file *with* the `1 ≤ m` guard (`∃ m, 1 ≤ m ∧ …`); the 2026-03-09
  session's rewrite (which produced the current repo file) dropped it.
- No `sorry` in any `def`; the three counting `def`s match their docstrings
  (after the fix) and are used consistently by the theorems.

**A4. Question form and answer polarity — acceptable for raw style (see A1).**

- Both source questions are value requests wrapped in existence questions. The
  checklist's `answer()` machinery is unavailable in a plain-Mathlib raw file;
  per the pipeline's raw-file guidance the test is soundness/direction, not
  form. The asserted direction (exists, $= 1$) is the page-documented
  conjecture for (a) and the page-documented tentative expectation for (b) —
  not a wrong polarity. The upstream artifact splits each part into
  `answer(sorry) ↔ ∃ c, HasDensity c` (existence) plus
  `HasDensity answer(sorry)` (value); the added `..._exists` companions mirror
  that split within this file's vocabulary.
- No binders before the colon on any theorem (all are binder-free).

**A5. Solution status — pass (source-verified).**

- Page banner **OPEN** (tooltip: "This is open, and cannot be resolved with a
  finite computation."), with the owner's standard disclaimer. The file (raw
  style, no category attributes) now records OPEN and the page edition in the
  module docstring; nothing in the file claims the problem solved. The solved
  side results (S, P infinite — [HaSu02]; existence of Pillai primes — Chowla)
  are attributed exactly as on the page.

## E. Prior-review audit

`ai-review/1074.md` and `reviews/1074.md` do not exist (formalized upstream
before this project), so Part E is adapted per the pipeline instructions: audit
the file's docstring claims against the recovered source, plus the recovered
upstream artifact as an informal "prior formalization" to audit.

1. **File docstring vs source — one misframing (fixed), one contradiction
   (the A3 defect).** The pre-fix docstring rendered both parts as "Does the
   … density … exist, and is it equal to 1?" The source questions never
   mention 1 — the value 1 is the *conjectured* answer from the remarks, not
   part of the question. Docstring reframed to quote the source verbatim and
   attribute the value-1 belief to [HaSu02]. And the docstring's own "sequence
   begins 23, 29, …" contradicted the pre-fix `IsPillaiPrime` (which put 2 in
   P) — an internal inconsistency neither earlier pipeline pass caught.
2. **Upstream audit — the guard and the test theorems are right; one variant is
   dubious.** Upstream's `Nat.PillaiPrimes` guards `m ≥ 1` and proves
   `¬ 2 ∈ Nat.PillaiPrimes` and `23 ∈ Nat.PillaiPrimes` as test theorems —
   both check out by hand (for `m ≥ 1`, `2 ∣ m! + 1` forces `m! ` odd, so
   `m = 1`, where every prime is `≡ 1 [MOD 1]`; and `14! + 1 ≡ 0 (mod 23)`
   with `23 % 14 = 9`). However, upstream's
   `erdos_1074.variants.EHSNumbers_one_half : EHSNumbers.HasDensity (1/2)`
   (`@[category research open]`) formalizes the superseded first half of the
   [HaSu02] quotation as if it were a live conjecture, while the same page
   paragraph replaces it with the density-1 belief; it also flatly contradicts
   upstream's own implicit density-1 reading. This review did not import that
   variant (see B2). Also noteworthy: the upstream capture of 2026-02-22 names
   the four parts `part8_i_i`/`part_i_ii`/`part_ii_i`/`parts_ii_ii` (typos
   included); by the 2026-03-15 formal-conjectures sessions they appear as
   `erdos_1074.parts.iv` etc. — upstream was revised between captures.
3. **Provenance finding (regression).** The two formalization sessions for 1074
   disagree: session 20d683c9 (2026-02-22) wrote a version whose
   `isPillaiPrime` had `∃ m, 1 ≤ m ∧ …` (correct); session 04a43bb4
   (2026-03-09) rewrote the file from scratch without the guard, and its
   subsequent edits (replacing `≡ 1 [MOD m]` with `% m = 1 % m`) preserved the
   omission. The current repo file is the 04a43bb4 version — i.e. the defect is
   a regression introduced by the later pipeline pass, exactly the class of
   drift this review pipeline exists to catch.
