**Verdict:** NEEDS REVISION (one Part A defect: the equality is false for $n < rk - 1$,
making the stated theorem literally disprovable at tiny parameters — fixed in place, see
Addendum)
**Confidence:** high on the defect itself (the counterexample is a finite computation);
medium overall — no compiler, `/latex/1020` was never captured so several bibliographic

## Summary

The problem (Erdős Matching Conjecture, recovered verbatim from the archived page): let
$f(n;r,k)$ be the maximal number of edges in an $r$-uniform hypergraph [on $n$ vertices]
containing no set of $k$ pairwise disjoint ("independent") edges; for all $r \geq 3$,
$f(n;r,k) = \max\left(\binom{rk-1}{r}, \binom{n}{r}-\binom{n-k+1}{r}\right)$. Status:
OPEN ("FALSIFIABLE"). The Lean file defines `IsRUniform`, `HasMatching`, and
`maxEdgesNoMatching` (an `sSup` over achievable edge counts) — all three are correct —
and asserted the equality for **all** `n` with only `hr : r ≥ 3`, `hk : k ≥ 1`. Read
literally, that proposition is **false**: for $n < rk-1$ no hypergraph on $n$ vertices
can contain a $k$-matching (which needs $rk > n$ vertices), so the LHS is $\binom{n}{r}$
while the RHS contains the strictly larger clique term $\binom{rk-1}{r}$. Concretely
$n=4, r=3, k=2$: LHS $= \binom{4}{3} = 4$, RHS $= \max(\binom{5}{3}, 4-1) = 10$. The
page states the identity without an $n$-constraint too, but its own remark "the
conjecture is trivially true if $n < kr$" shows the intended small-$n$ reading is the
upper bound, under which triviality actually holds. Fixed by adding
`hn : n ≥ r * k - 1` (the exact threshold at and above which the equality is the true
conjecture) plus an all-$n$ upper-bound variant.

## A. Semantic fidelity

**A1. Statement fidelity — one [defect]; otherwise faithful (source-verified).**

- Independent back-translation of the pre-fix `erdos_1020` (old lines 68–71): "for every
  $n$, $r \geq 3$, $k \geq 1$, the largest edge count of an $r$-uniform hypergraph on
  $n$ vertices with no $k$ pairwise-disjoint edges equals
  $\max(\binom{rk-1}{r}, \binom{n}{r}-\binom{n-k+1}{r})$."
- **[defect] Missing $n$-range hypothesis.** The equality fails whenever $n \leq rk-2$:
  a $k$-matching needs $rk$ vertices, so for $n < rk$ every $r$-uniform hypergraph on
  `Fin n` is matching-free and `maxEdgesNoMatching n r k = C(n,r)`; meanwhile
  $\binom{rk-1}{r} > \binom{n}{r}$ exactly when $n < rk-1$ (monotonicity of
  $\binom{\cdot}{r}$, using $rk-1 \geq r$ for $k \geq 2$; $k=1$ is degenerate-but-true,
  see below). Smallest counterexamples: $(n,r,k) = (0,3,2)$ gives $0 \neq 10$;
  $(4,3,2)$ gives $4 \neq 10$. Since the problem is tagged FALSIFIABLE and the theorem
  carries `category research open`, the pre-fix statement was a formally *refutable*
  "open conjecture" — the worst kind of infidelity. The page states the identity with no
  $n$-constraint, but its remark list ("trivially true if $n < kr$", Kleitman "$n=kr$",
  Frankl "$kr \leq n \leq \dots$") shows the equality's intended domain starts where the
  clique construction fits. At $n = rk-1$ the equality holds ($f = \binom{n}{r} =
  \binom{rk-1}{r}$ = term 1 ≥ term 2), so `hn : n ≥ r * k - 1` is the exact corrected
  threshold. **Fixed** (Addendum); the all-$n$ content survives as
  `variants.upper_bound` (LHS ≤ RHS for all $n$), which is what is "trivially true" for
  $n < kr$ and is equivalent to the conjecture given the two constructions.
- Otherwise the translation is faithful: "independent edges" = pairwise disjoint edges =
  `Disjoint` on `Finset (Fin n)` (intersection empty) for distinct members of an
  `M ⊆ H` with `M.card = k`; "maximal number of edges" = `sSup` over achievable
  `H.card`, a genuine maximum (the constraint set is nonempty — `H = ∅` has no
  $k$-matching for $k \geq 1$ — and bounded, as there are finitely many
  `Finset (Finset (Fin n))`).
- The implicit "$n$ vertices" (elided in the page's one-line statement, which names
  $f(n;r,k)$ but never mentions $n$ again) is correctly supplied by `Fin n`: without a
  vertex bound the star construction would give infinitely many edges, so $n$ must bound
  the vertex set.
- Not vacuous/trivial post-fix: for $n \geq rk$ both constructions and genuine
  $k$-matchings exist, and the statement is the substantive open conjecture.

**A2. Lean semantics traps — pass (post-fix); the pre-fix failure was mathematical, not
a truncation artifact.**

- ℕ subtraction: `r * k - 1` is exact ($rk \geq 3$ under `hr`, `hk`). `n - k + 1` parses
  as `(n - k) + 1`; under the added `hn : n ≥ r*k - 1` we get $n \geq rk-1 \geq k$
  (since $r \geq 3$ gives $k(r-1) \geq 1$... precisely $rk - 1 \geq k \iff k(r-1) \geq 1$,
  true), so `n - k` doesn't truncate and `n - k + 1` $= n-(k-1)$ exactly, matching the
  source's $n-k+1$. `Nat.choose n r - Nat.choose (n-k+1) r` doesn't truncate since
  $n \geq n-k+1$. In the *removed* small-$n$ regime the ℕ-truncations were individually
  harmless (as the prior review noted) — the falsity there is genuinely mathematical.
- No division anywhere.
- No `Finset.range`; `M.card = k` and `e.card = r` are exact cardinalities, no
  off-by-one.
- Vacuous quantifiers: `IsRUniform ∅ r` and the disjointness condition on singleton `M`
  are vacuously true — both match the intent (the empty hypergraph is $r$-uniform; a
  single edge is a matching of size 1). `HasMatching H 0` is always true via `M = ∅`,
  so for $k = 0$ the `sSup` set is empty and returns junk 0; excluded by `hk`.
- `sSup` on ℕ: set nonempty (contains 0) and bounded → true maximum. No
  filter/`StrictMono` constructs used.
- Degenerate $k = 1$: "no matching of size 1" = "no edges", LHS 0; RHS
  $\max(\binom{r-1}{r}, \binom{n}{r}-\binom{n}{r}) = 0$. True, and consistent with both
  the fixed theorem and the variants.

**A3. Definitions — pass.**

- `IsRUniform` (line 90), `HasMatching` (line 95), `maxEdgesNoMatching` (line 102) each
  match their docstrings and the source notions, including degenerate inputs (empty

**A4. Question form and answer polarity — pass.**

## E. Prior-review audit (`ai-review/1020.md`)

The prior review's §6.4 verdict "The formalization is correct... All edge cases
verified" is **wrong**, and its supporting analysis contains exactly the failure classes
this pipeline has been flagging:

1. **Unsound degenerate-case argument, false conclusion (its §6.2).** For $n < k$ it
   argues: a $k$-matching is impossible, so the maximum is $\binom{n}{r}$, "and the
   formula should give that too — and it does, since `Nat.choose n r` is the second
   term." This checks only the *second* term of a `max` and forgets the first: for
   $n < rk-1$ the first term $\binom{rk-1}{r}$ strictly exceeds $\binom{n}{r}$, so the
   formula does *not* give $\binom{n}{r}$ (e.g. $n=5,k=6,r=3$: formula $=\binom{17}{3}
   = 680$, truth $= 10$). The same oversight hides the entire false regime
   $k \leq n \leq rk-2$ (e.g. $(4,3,2)$: $4 \neq 10$), which its case split ($n < k$,
   $n < r$, "$n-k+1 \geq r$") never isolates. This is the 1000/1005 pattern again — a
   confident verification narrative that would mask a real bug — except here the bug is
   real and the narrative blessed it.
2. **Citation endorsement of unverifiable (and wrong) data.** Its §2 lists the website's
   references and check-marks both entries, including [Er71] = "Topics in combinatorial
   analysis... (1971), 2–20" as "correctly cited with full bibliographic details" —
   while itself quoting the page's "[Er71], p. 103", which cannot lie in pp. 2–20. The
   internal contradiction went unnoticed; the site's global key resolves to the Oxford
   1969 proceedings paper (97–109). Its website reference list is also incomplete: it
   omits [Kl68], [BDE76], [FLM12], [LuMi14], all cited on the page.
3. **Minor.** Its §6.1 nonemptiness parenthetical "(the empty hypergraph always works
   when $k \geq 2$; for $k=1$, only the empty hypergraph...)" is muddled — the empty
   hypergraph works for every $k \geq 1$ — though the conclusion stands. Its line
   numbers (43/49) match neither the raw nor the styled file.
4. **What it got right:** the `IsRUniform`/`HasMatching` correctness bullets, the $k=1$
   edge case, the `sSup` nonempty/bounded argument, the reuse survey, and the $r=2$
   exclusion rationale all check out. Its §4 readability suggestions were adopted
   upstream (verified in the formal-conjectures logs' review-fix diff `7c6f5be..2166d0a`).
5. `reviews/1020.md` (style review, reference only): its §6 "Note on mathematical
   correctness" asserts the subtraction "is well-behaved in the intended range" and its
   summary calls the formalization correct — it never asks whether the *stated* range
   (all $n$) is the intended range. It also confirms FALSIFIABLE status without noticing
   the statement it passed was, in fact, falsified by $(4,3,2)$.
