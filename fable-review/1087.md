## Summary

The problem (verbatim from the recovered page): "Let $f(n)$ be minimal such that every
set of $n$ points in $\mathbb{R}^2$ contains at most $f(n)$ many sets of four points
which are 'degenerate' in the sense that some pair are the same distance apart. Estimate
$f(n)$ - in particular, is it true that $f(n)\leq n^{3+o(1)}$?" Status **OPEN**; a
question of Erdős and Purdy [ErPu71], who proved $n^3\log n \ll f(n) \ll n^{7/2}$. The
Lean file defines `HasRepeatedDistance` (two distinct unordered pairs at equal distance)
and `degenerateQuadrupleCount` (the number of 4-element subsets with a repeated
distance), and states `answer(sorry) ↔ ∀ ε > 0, ∃ N, ∀ n ≥ N, ∀ P` with $|P| = n$,
count $\le n^{3+\varepsilon}$. Read back independently, this is exactly the "in
particular" yes/no question with the correct open-problem encoding; quantifying directly
over all $P$ is equivalent to bounding the extremal function $f$. The only defect found
is bibliographic: the docstring gave [Er75f] a wrong title ("Problems and results in
combinatorial geometry"); three independently recovered `/latex` extractions identify it
as "On some problems of elementary and combinatorial geometry", Ann. Mat. Pura Appl. (4)
(1975), 99–108 — consistent with the page's "[Er75f, p.104]" pointer.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- The source's elliptical phrase "some pair are the same distance apart" can only
  sensibly mean "some two [distinct] pairs are at the same distance" (a lone pair cannot
  be "the same distance apart" as nothing). This is the classical Erdős–Purdy notion —
  a 4-set determining fewer than $\binom{4}{2} = 6$ distinct distances — and is what the
  docstring's disambiguation ("some two distinct pairs determine the same distance") and
  the Lean encode. Corroborated by the neighboring problems 1088/1089 (same paper
  [Er75f], distinct-distances circle of questions).
- $f(n)$ = minimal bound valid for *every* $n$-set = the maximum count over $n$-sets.
  So $f(n) \le B(n)$ iff every $n$-point $P$ has count $\le B(n)$; the Lean's direct
  quantification `∀ P, P.card = n → count ≤ n^(3+ε)` (`deepmind/1087.lean:68–70`)
  eliminates $f$ correctly, with the bound uniform over sets for each large $n$ —
  exactly what $f(n) \le n^{3+\varepsilon}$ means.
- The $n^{3+o(1)}$ upper bound is rendered as $\forall \varepsilon > 0\, \exists N\,
  \forall n \ge N$: the standard and correct unfolding (the known lower bound
  $n^3 \log n = n^{3+o(1)}$ is consistent with a "yes" answer, so the question is
  substantive).
- Quantifier order ∀ε ∃N ∀n ∀P is right: $N$ may depend on $\varepsilon$ but not on
  $P$ — matching the extremal-function reading.
- Types: points are `EuclideanSpace ℝ (Fin 2)` (genuine Euclidean metric, not sup
  metric — `dist` is the ℓ² distance here, correct); sets are `Finset`, so "n points"
  means n *distinct* points, as intended; the count is cast to ℝ before comparison with
  the real power. No indexing conventions arise.
- Not vacuous: for $n < 4$ the count is 0 and the bound is trivial, but the statement
  bites for all large $n$; the RHS is neither trivially true nor trivially false.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction, no ℕ division anywhere.
- `(n : ℝ) ^ ((3 : ℝ) + ε)` is real rpow. At $n = 0$ (possible only if $N = 0$):
  $0^{3+\varepsilon} = 0$ in Mathlib (positive exponent), and the count is 0, so
  $0 \le 0$ holds — no degenerate failure.
- No `Finset.range`; `powersetCard 4` is the correct "all 4-element subsets" object
  (empty for $|P| < 4$, matching the informal count of 0).
- No liminf/limsup/filter encodings needed; the explicit $\varepsilon$–$N$ unfolding is
  used instead, correctly.
- No `StrictMono`/`Monotone` or interval-endpoint issues. `≤` in the bound matches the
  source's $\le$.

**A3. Definitions — pass.**

- `HasRepeatedDistance` (lines 39–43): the pair-distinctness clause
  `(a ≠ c ∨ b ≠ d) ∧ (a ≠ d ∨ b ≠ c)` is exactly
  $\neg(\{a,b\} = \{c,d\})$ given $a \ne b$, $c \ne d$: I verified both directions by
  hand, including the reversed-order case $c = b, d = a$ (first conjunct true via
  $a \ne b$, second false — correctly excluded) and $c = a, d = b$ (first conjunct
  false — excluded). Pairs sharing one point (isosceles configurations) correctly *do*
  count as degenerate. Sound and complete for the informal notion.
- The predicate is stated for arbitrary `Finset`s but only applied to 4-element subsets;
  the original docstring said "A 4-element point set", a slight mismatch with the def's
  generality — [polish], fixed (docstring now says "a point set … applied below to
  4-element subsets").
- `degenerateQuadrupleCount` (lines 47–48): `((P.powersetCard 4).filter
  HasRepeatedDistance).card` is precisely the number of degenerate 4-element subsets.
  No `sorry` in any definition; no drift between defs and theorem usage.

**A4. Question form and answer polarity — pass.**

- The source's "in particular, is it true that $f(n) \le n^{3+o(1)}$?" is a yes/no
  question → `answer(sorry) ↔ P` with `P` the question as asked, so `True` would mean
  "yes". Polarity checked by hand: RHS true ⟺ every large configuration obeys the
  bound ⟺ $f(n) \le n^{3+o(1)}$ ⟺ answer "yes". With the problem OPEN,
  `answer(sorry)` is correct.
- No binders before the colon (line 67: `theorem erdos_1087 : answer(sorry) ↔ …` is
  binder-free); ε and n are correctly quantified inside the iff. (The raw first pass had
  ε as a theorem binder *and* no `answer()` wrapper — see the drift check below.)
- The soft "Estimate $f(n)$" preamble is the usual framing; formalizing the "in
  particular" question is the right scope (same call as 1005).

**A5. Solution status — pass (source-verified).**

- Recovered page banner: **OPEN**, tooltip "This is open, and cannot be resolved with a
  finite computation.", plus the owner's standard disclaimer. `@[category research
  open]`, `answer(sorry)`, and both docstrings agree. The page attributes the question
  and both known bounds to Erdős–Purdy [ErPu71], as the docstring does.

## E. Prior-review audit (`ai-review/1087.md`)

Substantially accurate — its central correctness analysis holds up — with three
findings:

1. **Unsound variant proposal (small-parameter failure).** §3 proposes the known lower
   bound as "$\exists c > 0, \forall n, f(n) \geq c \cdot n^3 \cdot \log n$". This is
   literally **false**: for $n \in \{2, 3\}$ there are no 4-element subsets, so
   $f(n) = 0$ while $c\,n^3\log n > 0$ for every $c > 0$. The bound needs "for all
   sufficiently large $n$" (or $n \ge 4$… which also fails: e.g. $f(4) \le 1$ but
   $c \cdot 64 \log 4$ can still exceed it only for large $c$ — the eventual form is the
   safe one). Same failure class as 1004's EPS87 bound (a page-stated asymptotic
   transcribed as a universal claim). The variant as applied here uses the corrected
   eventual form and documents the counterexample.
2. **Citation flag correct, but the completion it triggered introduced an error.** §2
   correctly flagged [Er75f] as missing and proposed an honest stub ("Erdős, P. (1975),
   p. 104"). The entry subsequently added to `deepmind/1087.lean` carried a title —
   "Problems and results in combinatorial geometry" — that appears in **no recovered
   source** and is wrong (it names a different, 1985, Erdős paper; the correct 1975
   title was recoverable from the logs all along, cf. the 1001 audit pattern "claiming
   data unavailable that is in fact recoverable" — here data was *invented* rather than
   recovered). Not the ai-review's own claim, but its stub was completed unsoundly
   downstream; the same wrong title also appears in `deepmind/657.lean`,
   `deepmind/1083.lean`, and `deepmind/223.lean` (out of scope here, worth a follow-up).
3. **Verified correct:** its unordered-pair-distinctness derivation (§6) — I re-derived
   $\{a,b\} = \{c,d\} \iff (a{=}c \wedge b{=}d) \vee (a{=}d \wedge b{=}c)$ and the De
   Morgan dual, including the shared-vertex cases — checks out; the $n < 4$ edge case
   (§6) checks out; `powersetCard` equivalence (§1) is real (`powersetCard_eq_filter`)
   and was applied; the $n^{3+o(1)}$ unfolding endorsement (§5) is correct. Nothing it
   flagged went unfixed except insofar as the [Er75f] completion went wrong (point 2).
