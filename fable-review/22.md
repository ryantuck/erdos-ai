## Summary

The problem (PROVED): for every ε > 0 and all sufficiently large n, is there a
graph on n vertices with ≥ n²/8 edges, containing no K₄, whose largest
independent set has size at most εn? Conjectured by Bollobás–Erdős [BoEr76]
(who achieved (1/8 + o(1))n²), proved by Fox–Loh–Zhao [FLZ15] (who got the
sharp n²/8 with independence number ≪ (log log n)^{3/2}/(log n)^{1/2}·n). The
Lean theorem (`conjectures/22.lean:39–46`) asserts: ∀ ε > 0, ∃ N, ∀ n ≥ N,
∃ G : SimpleGraph (Fin n) with (n:ℝ)²/8 ≤ |E(G)| (via `edgeSet.ncard`), no
4-clique (`∀ s, ¬G.IsNClique 4 s`), and every independent Finset of size
≤ ε·n. Read back independently, this is exactly the source question's
affirmative direction, which is the correct polarity for a problem solved
"yes"; I found no semantic defects. The nits are scholarship-level: the page's
second source key [Er90] is absent, and the two keys that are cited ([BoEr76],
[FLZ15]) carry no bibliographic entries.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Let $\epsilon>0$ and
  $n$ be sufficiently large depending on $\epsilon$. Is there a graph on $n$
  vertices with $\geq n^2/8$ many edges which contains no $K_4$ such that the
  largest independent set has size at most $\epsilon n$?"
- Independent back-translation of lines 39–46: "for every real ε > 0 there is
  a threshold N such that every n ≥ N admits a simple graph G on Fin n with
  (i) n²/8 ≤ #edges(G) in ℝ, (ii) no Finset of vertices is a 4-clique,
  (iii) every independent Finset has cardinality ≤ ε·n." This is precisely
  the existence question asked, asserted in its true direction.
- Quantifiers: ε universally quantified first; "sufficiently large depending
  on ε" rendered as ∃ N, ∀ n ≥ N with N after ε — correct dependence order.
  The graph is existential inside, as asked.
- Types: edge count compared in ℝ after casting (`(G.edgeSet.ncard : ℝ)`), so
  n²/8 is real division by the literal 8 — no flooring; the independence bound
  compares `(s.card : ℝ) ≤ ε * (n : ℝ)` in ℝ — correct, since ε·n is not an
  integer in general. `Fin n` as the vertex type is the standard "graph on n
  vertices".
- "Largest independent set has size at most εn" is encoded as *every*
  independent set having size ≤ εn — equivalent over a finite vertex type
  (every independent set is a Finset; bounding all of them bounds the
  maximum, i.e. `indepNum ≤ εn`). "At most" ↦ non-strict ≤: matches, and
  agrees with the upstream formal-conjectures rendering (`G.indepNum ≤ ε * n`).
- Not vacuous or trivially true: the conjunction is the genuine
  Ramsey–Turán tension (K₄-free graphs reach n²/4 edges only via bipartite-
  like structures with independent sets of size ~n/2; forcing independence
  number ≤ εn caps the edge count at (1/8 + o(1))n² by Szemerédi [Sz72], so
  n²/8 is sharp — a substantive theorem, not a degenerate claim). Small n
  below the threshold N impose nothing, and even the degenerate n = 0 case
  would be satisfied by the empty graph, so no hidden falsity at boundary
  parameters (contrast problem 20's n = 0 defect — checked explicitly here:
  at n = 0 all three conjuncts hold for G = ⊥).

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere.
- Division: only `(n : ℝ) ^ 2 / 8` — real division by a nonzero literal;
  total and exact. No ℕ division.
- No `Finset.range`, so no off-by-one surface.
- No vacuous bounded quantifiers: `∀ s, ¬IsNClique 4 s` and the independence
  bound quantify over all Finsets, with no degenerate first term. The empty
  Finset satisfies both hypotheses' conclusions trivially (¬IsNClique 4 ∅
  since card ∅ ≠ 4; card ∅ = 0 ≤ εn), which matches the informal reading.
- "Sufficiently large" via ∃ N, ∀ n ≥ N is the standard, correct encoding
  (extensionally the `atTop` eventual filter used upstream).
- Strict vs non-strict: `ε > 0` strict (source: ε > 0 ✓); edge bound `≥`
  non-strict (source: "≥ n²/8" ✓); independence `≤` non-strict (source: "at
  most" ✓). All three match the source exactly.
- `G.edgeSet.ncard`: `edgeSet ⊆ Sym2 (Fin n)` is finite, so `ncard` is the
  true edge count, never the junk value for infinite sets. Safe — and safer
  than `edgeFinset.card`, which would require a `Fintype G.edgeSet` instance
  (via `DecidableRel G.Adj`) that an arbitrary existentially-bound G does not
  carry in this file's import context (see C2/E).

1. **Unqualified `edgeFinset.card` recommendation (soundness gap in a
   suggestion).** §1/§4 recommend `edgeFinset.card` over `edgeSet.ncard` as
   "more idiomatic", asserting "both give the same result" — true
   mathematically, but the recommendation ignores that `edgeFinset` requires
   a `Fintype G.edgeSet` instance (via `DecidableRel G.Adj`) that an
   arbitrary bound G lacks outside the upstream util's classical-instance
   context. Applied blindly to the raw file, the "consistency" polish would
   break the build that the current spelling passes. Declined (see C2).
2. **Sloppy n = 0 remark (right conclusion, confused justification).** §6's
   "for n = 0, the graph on 0 vertices trivially satisfies all conditions
   …, but n = 0 is excluded by taking N ≥ 1 in the existential" is doubly
   off: nothing in the statement excludes n = 0 (the prover merely *may*
   choose N ≥ 1), and no exclusion is needed precisely because — as its own
   first clause says — n = 0 satisfies everything. A harmless instance of
   the invent-then-excuse pattern flagged in earlier audits (1000, 1005);
   here the small case genuinely doesn't matter, but the reasoning would
   mask a real boundary bug on a problem where it does (cf. problem 20).
3. **Equivalence claim stated without derivation (checks out).** §1's claim
   that the conjecture is equivalent to ∀ ε > 0 eventually
   n²/8 ≤ rt(n; 4, ⌈εn⌉) is correct, but only because both sides are
   ∀ε-quantified: with `ramseyTuranNumber` (as in `conjectures/615.lean`)
   requiring independence *strictly* below ℓ, the (⇒) direction for fixed ε
   fails when εn is an integer (an independence number of exactly εn is "at
   most εn" but not < ⌈εn⌉); one must instantiate the LHS at ε/2. The
   review presents it as a direct restatement — true in the quantified
   aggregate, not term-by-term.

   finding was correct (page-verified here) and was applied to the styled

   Likewise its Problem-615 cross-reference suggestion (page-verified:
   "See also [615]") was never back-ported; fixed in v2.
5. Minor: its §2 "✅ Present and correct" for [BoEr76]/[FLZ15] was judged
