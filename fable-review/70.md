## Summary

The problem (erdosproblems.com/70, **OPEN**): "Let $\mathfrak{c}$ be the
ordinal of the real numbers, $\beta$ be any countable ordinal, and
$2\leq n<\omega$. Is it true that $\mathfrak{c}\to (\beta, n)_2^3$?" — i.e.,
for every 2-coloring of the 3-element subsets of the initial ordinal of the
continuum, is there either a color-0-homogeneous set of order type $\beta$ or
a color-1-homogeneous set of $n$ elements? The Lean
(`conjectures/70.lean:32-52`) defines `OrdinalPartition3_2 α β γ` — every
`f : Ordinal → Ordinal → Ordinal → Fin 2` admits a strictly increasing
`g : Ordinal → Ordinal` carrying ordinals below β (resp. γ) into ordinals below
α with all increasing image-triples colored 0 (resp. 1) — and asserts
`OrdinalPartition3_2 Cardinal.continuum.ord β ↑n` for all countable β and all
finite n ≥ 2. Read back independently, this is exactly the affirmative
direction of the question as asked; I found no semantic defects. The defects
are documentation-level: every docstring writes the partition relation with
superscript and subscript swapped ("²₃", which conventionally denotes
3-colorings of *pairs*, where the code — correctly — implements 2-colorings of
*triples*, "³₂"), the [Er87] key is used but never defined, and the page's
second citation [Va99, 7.83] is missing entirely.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Let $\mathfrak{c}$ be
  the ordinal of the real numbers, $\beta$ be any countable ordinal, and
  $2\leq n<\omega$. Is it true that $\mathfrak{c}\to (\beta, n)_2^3$?"
- Independent back-translation of lines 49-52 with the def at 32-41: "for
  every ordinal β of countable cardinality and every natural n ≥ 2, every
  2-coloring of ordered triples of ordinals admits either (a) a strictly
  increasing map g of the ordinals below β into the ordinals below
  `continuum.ord` with `f (g i) (g j) (g k) = 0` for all i < j < k < β, or
  (b) the same with β replaced by ↑n and color 1." Since a strictly increasing
  ordinal-indexed map is injective and order-preserving, its image is a subset
  of the initial ordinal of $\mathfrak{c}$ of order type exactly β (resp. a set
  of exactly n elements), and increasing triples from the image are precisely
  its 3-element subsets. This is the partition relation
  $\mathfrak{c} \to (\beta, n)^3_2$, asserted affirmatively.
- **Coloring domain**: `f` is total on ordered triples of *all* ordinals
  rather than on increasing triples below α. Equivalence re-derived in both
  directions: any coloring `c` of 3-subsets of α extends to a total `f` (set
  `f x y z := c {x,y,z}` on increasing triples below α, arbitrary elsewhere),
  and homogeneity is only ever evaluated at increasing image-triples, which
  are below α by the membership conjunct. Faithful, not merely harmless.
- **"Ordinal of the real numbers"**: the source's phrase is loose (ℝ is not
  well-ordered); the file reads it as the initial ordinal of the cardinality
  of the continuum (`Cardinal.continuum.ord`), stated explicitly in the
  theorem docstring ("viewed as an initial ordinal"). This is the standard
  partition-calculus reading of $\mathfrak{c}\to(\beta,n)^3_2$ and is exactly
  the reading upstream formal-conjectures HEAD uses (`(𝔠).ord`). Pass, with
  the interpretation now documented in v2's module docstring.
- Quantifiers: β and n universally quantified as theorem binders with explicit
  countability (`β.card ≤ ℵ₀`) and size (`2 ≤ n`) hypotheses — matching "any
  countable ordinal" (which includes finite β; those instances are weaker,
  matching the informal reading) and "2 ≤ n < ω" (n : ℕ supplies n < ω).
- Not vacuous / not trivially false: for n ≥ 4 and infinite β this is the
  genuinely open relation; the n ≤ 3 and β ≤ 2 instances are trivially true
  in the def exactly as they are in the informal calculus (sets with fewer
  than 3 elements carry no triples), so the encoding does not silently alter
  the problem — the triviality is the source's own (upstream documents the
  same boundary; recorded in v2's docstring).

**A2. Lean semantics traps — pass.**

- No ℕ subtraction, no division, no `Finset.range` anywhere.
- Coercion `(↑n : Ordinal)` is `Nat.cast`, order-preserving with `n < ω`

- Vacuous bounded quantifiers: for γ = ↑n with n = 2 the homogeneity clause
  `∀ i j k, i < j → j < k → k < 2 → …` is vacuous and the right disjunct only
  demands two increasing ordinals below `continuum.ord` — trivially satisfied.

## C. Craftsmanship

**C1. Readability — one defect, otherwise good.**

- **[defect: docstring-notation-swap]** All three docstrings write the
  relation as "𝔠 → (β, n)²₃" / "α → (β, γ)²₃" (lines 13, 19, 24) —
  superscript 2, subscript 3, which in the standard convention denotes a
  **3-coloring of pairs**. The code (and the source page, which writes
  $(\beta, n)_2^3$) is a **2-coloring of triples**: superscript 3, subscript
  2. The surrounding English ("2-coloring of the 3-element increasing
  sequences") is correct, so the code is right and the notation is a typo —
  but a reader trusting the notation would formalize a different relation.
  Wrong docstring over right theorem is a defect; fixed in v2 ("³₂"
  throughout).
- Otherwise: the def cleanly separates the relation from its instance; names
  are meaningful (`OrdinalPartition3_2` = 3-subsets, 2 colors); hypotheses
  minimal and clear (`β.card ≤ ℵ₀` is the idiomatic countability encoding).

**C2. Reuse — no Mathlib duplicate; sibling-idiom note.**

- Mathlib has no ordinal partition-relation combinator to reuse (nothing like
  `α → (β, γ)^3_2` exists; static judgment). No local def duplicates a
  Mathlib concept.
- Sibling raw files (591/597) encode partition relations via the subtype
  `OrdinalSet α := {a : Ordinal // a < α}` with `↪o`/`StrictMono`, which
  makes the embedding structure more self-evident than three quantified

  stays a note, not a change — v2 keeps the def byte-identical.
