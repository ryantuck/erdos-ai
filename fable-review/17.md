## Summary

The problem (erdosproblems.com/17, **OPEN**): *"Are there infinitely many primes $p$
such that every even number $n \leq p-3$ can be written as a difference of primes
$n = q_1 - q_2$ where $q_1, q_2 \leq p$?"* — such primes are called **cluster
primes**; the first prime without the property is $97$ (OEIS A038133). The Lean file
defines `IsClusterPrime p` (`conjectures/17.lean:11-14`): `p` is prime and every
`n : ℕ` with `2 ≤ n`, `n ≤ p - 3`, `Even n` is `q₁ - q₂` for primes
`q₁, q₂ ≤ p`, and asserts (`:28`) `{p : ℕ | IsClusterPrime p}.Infinite`. Read back
independently, this is exactly "there are infinitely many cluster primes" — the
conjectured "yes" direction of the open question, which is this raw corpus's
convention for open yes/no questions. Both ℕ-subtractions in the definition are
provably harmless (analysis in A2), and the definition agrees with the upstream
formal-conjectures ℤ-cast encoding on all primes. I found **no semantic defects** —
only scholarship/polish nits (no reference data, missing OEIS/Guy pointers, missing
page-confirmed 97-variants), all addressed in `conjectures-v2/17.lean`.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Are there infinitely many
  primes $p$ such that every even number $n\leq p-3$ can be written as a difference
  of primes $n=q_1-q_2$ where $q_1,q_2\leq p$?" The theorem docstring (lines 16-27)
  reproduces it faithfully and correctly reports the 97 fact and both counting
  bounds ([BES99], [El03]) exactly as on the page.
- Independent back-translation of lines 11-14 + 28: "the set of primes `p` such
  that every even `n` with `2 ≤ n ≤ p - 3` is a difference of two primes `≤ p` is
  infinite." Term-by-term against the source: quantifier order (∀ n, ∃ q₁ q₂)
  matches; the bound `q₁, q₂ ≤ p` is inclusive on both sides, as in the source; the
  difference is `q₁ - q₂` in the source's orientation.
- The explicit `2 ≤ n` hypothesis matches the standard reading of "every even
  number $n \le p-3$" (positive even integers — OEIS A038133's definition says
  "even positive integer"); including `n = 0` would change nothing since
  `0 = 2 - 2` is always representable. No drift.
- Types: everything in ℕ, where the problem lives; no coercions needed (see A2 for
  why the ℕ-subtractions are safe). `Set.Infinite` on a subset of ℕ is the correct
  encoding of "infinitely many primes such that …".
- Smallest-case check (not just "in the limit"): for `p = 5` the only constraint is
  `n = 2`, and `5 - 3 = 2` gives it; for `p = 7`, `n ∈ {2, 4}` via `5-3`, `7-3`.
  Both match hand-computation of the informal definition; `3, 5, 7` are the first
  entries of A038133.
- Not vacuous or trivially false: infinitude of cluster primes is a genuine open
  question (BES99 prove they have density → 0 among primes, and non-cluster primes
  are provably infinite, so the set is a sparse, nontrivial set).

**A2. Lean semantics traps — pass (each checked explicitly).**

- **ℕ subtraction, occurrence 1** (`n ≤ p - 3`, line 13): truncated at 0. For every
  prime `p ≥ 3` it equals the integer `p - 3` (no truncation). For `p = 2` it
  truncates (`0` instead of `-1`), but the hypothesis chain `2 ≤ n → n ≤ 0` is
  unsatisfiable, so `IsClusterPrime 2` holds **vacuously** — exactly as it does in
  the upstream ℤ-cast encoding (`n ≤ (2:ℤ) - 3 = -1` is unsatisfiable for `n : ℕ`).
  The literature (BES99, A038133) restricts "cluster prime" to odd primes; the
  vacuous membership of `2` deviates from that classification but is **invisible to
  the theorem**: adding one element never changes `Set.Infinite`. Documented in the
  v2 docstring; not a defect.
- **ℕ subtraction, occurrence 2** (`n = q₁ - q₂`, line 14): truncated, but under
  `2 ≤ n` it is *exactly equivalent* to the intended integer equation. If
  `q₂ > q₁`, then `q₁ - q₂ = 0 ≠ n`; if `q₁ ≥ q₂`, ℕ- and ℤ-subtraction agree. So
  the witnesses are precisely the pairs with integer difference `n` — no spurious
  witnesses gained, none lost. (The upstream file casts both comparisons to ℤ; the
  two definitions agree on all primes, and on all `p : ℕ` except that upstream also
  admits the trivially-representable `n = 0`.)
- **Division / `Finset.range`:** none in the file.
- **Vacuous bounded quantifiers:** the `p = 2` (and `p = 3`, where `p - 3 = 0`)
  vacuity is analyzed above and matches the source's intent for all odd primes;
  `3` and `5` are genuinely (near-)vacuous cluster primes in the informal
  definition too (A038133 starts `3, 5, 7`).
- **Infinitude encoding:** `Set.Infinite` is the standard and correct rendering of
  "there are infinitely many"; no filter subtleties arise (`Frequently`/`cofinite`
  alternatives would be equivalent).
- **`StrictMono` vs `Monotone`, strict vs non-strict, intervals:** the only
  comparisons are `2 ≤ n`, `n ≤ p - 3`, `qᵢ ≤ p`, all non-strict and all matching
  the source's `≤`.
