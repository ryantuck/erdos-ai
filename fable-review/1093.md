## Summary

The problem (Erdős–Lacampagne–Selfridge [ELS88, p.522], also posed at the 1986 West Coast
Number Theory problem session): for $n \ge 2k$, the *deficiency* of $\binom{n}{k}$ is
undefined if some prime $p \le k$ divides $\binom{n}{k}$, and otherwise equals the number
of $0 \le i < k$ such that $n-i$ is $k$-smooth (all prime factors $\le k$). Two questions,
both OPEN: (1) are there infinitely many binomial coefficients with deficiency $1$?
(2) are there only finitely many with deficiency $>1$? The Lean file defines `IsSmooth`
(prime factors $\le k$), `deficiencyDefined` ($2k \le n$ and no prime $\le k$ divides
$\binom{n}{k}$), and `deficiency` (a `Finset.range k` filter count), then states Part 1 as
`Set.Infinite` and Part 2 as `Set.Finite` of the corresponding pair sets. Read back
independently, the Lean matches the recovered source statement exactly, including on the
site's worked examples (verified by hand for $\binom{7}{3}$, $\binom{23}{5}$,
$\binom{44}{8}$). No semantic defects; direct-assertion form for the two open questions is
legitimate raw-file style with the polarity in the direction asked. Notably, this file is
*more faithful than the upstream formal-conjectures artifact*, which uses Mathlib's
strict-inequality `smoothNumbers k` and thereby miscounts the deficiency whenever $k$ is
prime (it assigns $\binom{7}{3}$ deficiency 0, contradicting the site's own example list).

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "For $n\geq 2k$ we define the
  deficiency of $\binom{n}{k}$ as follows. If $\binom{n}{k}$ is divisible by a prime
  $p\leq k$ then the deficiency is undefined. Otherwise, the deficiency is the number of
  $0\leq i<k$ such that $n-i$ is $k$-smooth, that is, divisible only by primes $\leq k$.
  Are there infinitely many binomial coefficients with deficiency $1$? Are there only
  finitely many with deficiency $>1$?"
- Independent back-translation of the Lean: Part 1 asserts the set of pairs $(n,k)$ with
  $2k \le n$, no prime $\le k$ dividing $\binom{n}{k}$, and exactly one $i \in [0,k)$
  with $n-i$ being $k$-smooth, is infinite; Part 2 asserts the analogous set with count
  $>1$ is finite. Modulo question-vs-assertion form (see A4), these are precisely the two
  questions, in the direction asked.
- "Infinitely many binomial coefficients" is encoded as infinitely many *pairs* $(n,k)$.
  This is the intended reading: the site's example lists count $\binom{8413}{28}$ and
  $\binom{8414}{28}$ separately and report "58 examples with $n\leq 10^5$" as pair
  counts, and the upstream formal-conjectures artifact uses the same pair-set encoding.
  Since `deficiencyDefined` forces $k \le n/2$, no trivial $(n,k)\sim(n,n-k)$ duplication
  arises.
- Definedness is correctly *conjoined inside the set*, so both theorems quantify only
  over coefficients whose deficiency exists — matching "undefined" in the source.
- Sanity-anchored against the site's data by hand: $\binom{7}{3}=35$ (primes $2,3
  \nmid 35$; among $7,6,5$ only $6=2\cdot 3$ is 3-smooth) has deficiency 1 ✓;
  $\binom{23}{5}=33649=7\cdot 11\cdot 19\cdot 23$ (among $23,22,21,20,19$ only
  $20=2^2\cdot 5$ is 5-smooth) has deficiency 1 ✓; $\binom{44}{8}$ (among $44,\dots,37$
  exactly $42=2\cdot3\cdot7$ and $40=2^3\cdot5$ are 8-smooth) has deficiency 2 ✓.
- Not vacuous/trivially satisfiable: degenerate parameters cannot inflate either set.
  $k=0$: `deficiencyDefined n 0` holds for every $n$ (vacuous prime condition), but
  `deficiency n 0 = 0` (empty range), so no $(n,0)$ pair enters either set. $k=1$:
  defined for all $n\ge 2$, but `IsSmooth 1 n` fails for every $n \ge 2$, so deficiency
  is 0. $k=2$: deficiency 1 would force $n$ a power of $2 \ge 4$, but then
  $\binom{n}{2}=2^{a-1}(2^a-1)$ is even, so definedness fails. Both questions are
  genuinely open counting problems.

**A2. Lean semantics traps — pass.**

- **ℕ subtraction** `n - i` in `deficiency`: inside both theorem sets, `deficiencyDefined`
  gives $2k \le n$, and the filter gives $i < k$, so $n - i \ge n-k+1 \ge k+1 > 0$ —
  truncation never engages and the values are the intended $n, n-1, \dots, n-k+1$. (As a
  standalone function on arbitrary inputs the truncation could fire, but the docstring
  scopes it to "when defined" and both uses are guarded; now also documented in the
  docstring.)
- **`IsSmooth k 0`** is *false* (every prime divides 0, and no finite $k$ bounds all
  primes), matching the convention that 0 is not smooth (upstream's `smoothNumbers`
  likewise excludes 0). Unreachable in guarded uses anyway. `IsSmooth k 1` is vacuously
  true — correct (1 is $k$-smooth) and harmless: $n-i \ge k+1 \ge 2$ on the guarded
  domain.
- **No division** anywhere. **`Finset.range k`** $=\{0,\dots,k-1\}$ exactly matches the
  source's $0 \le i < k$ — no off-by-one, and no index re-basing is needed (the source
  itself is 0-indexed in $i$).
- **Vacuous quantifiers:** the $k=0,1$ vacuous cases analyzed under A1 do not distort
  either theorem.
- **"Infinitely many"/"finitely many"** encoded as `Set.Infinite`/`Set.Finite` on the
  explicit solution sets — the standard, correct encoding; no filter machinery needed.
- No `StrictMono`/`Monotone`, no interval-endpoint subtleties. Strictness of `> 1` and
  `= 1` matches the source's "deficiency $>1$" and "deficiency $1$" verbatim.

**A3. Definitions — pass.**

- `IsSmooth` uses the classical convention $p \le k$, which is what the source spells
  out ("divisible only by primes $\leq k$"). This is **deliberately not** Mathlib's
  `Nat.smoothNumbers k` (which requires $p < k$); the two differ exactly when $k$ is
  prime, and the site's own example $\binom{7}{3}$ (deficiency 1 via $6 = 2\cdot 3$
  being 3-smooth) confirms $\le$ is right. Docstring note added (see Addendum).
- `deficiencyDefined` matches the source's two-part definedness condition exactly
  ($n \ge 2k$; no prime $p \le k$ divides $\binom{n}{k}$).
- `deficiency` matches its docstring and the source; degenerate inputs analyzed above.
- No `sorry` in any `def`; the defs and the theorem statements use them consistently
  (no drift). The file compiled in the original pipeline session (only `sorry`
  warnings), per the session log.

**A4. Question form and answer polarity — pass for raw style (note recorded).**

- Both parts are yes/no questions in the source. The raw file states them as direct
  assertions (`Set.Infinite …`, `Set.Finite …`) with the polarity **in the direction
  asked** — which per this pipeline's raw-file standard is acceptable raw style; wrong
  polarity would be a defect, and neither is wrong here. The docstrings pose the
  questions interrogatively and are marked OPEN, so no reader is misled about status.
- A styled (`deepmind/`-form) version of this file should use
  `answer(sorry) ↔ Set.Infinite …` and `answer(sorry) ↔ Set.Finite …` for the two open
  questions. For comparison, the upstream formal-conjectures artifact wraps part (i) in
  `answer(sorry) ↔` but leaves part (ii) as a bare `Set.Finite` assertion — an
  inconsistency on the upstream side (see Part E).
- Direction sanity: the site reports Barreto's *conditional positive* answer to
  question 2 (finiteness) — consistent with the asserted direction; ELS's own data
  (58 deficiency-1 examples vs. 16 known deficiency->1 examples) motivated both asked
  directions.
- No binders before the colon on either theorem.

**A5. Solution status — pass (source-verified).**

- Recovered banner: **OPEN** (tooltip: "This is open, and cannot be resolved with a
  finite computation."), with the standard owner's disclaimer. Both theorem docstrings
  say OPEN — consistent. The [ELS93] partial result ($n \ll 2^k\sqrt{k}$ when the
  deficiency exists and is $\ge 1$) and Barreto's conditional result do not change the
  open status; both are recorded as docstring remarks (Addendum fixes).

## C. Craftsmanship

**C1. Readability — good.**

- Names are meaningful (`IsSmooth`, `deficiencyDefined`, `deficiency`); the three-def
  decomposition mirrors the source's definition structure cleanly; docstrings state the
  mathematics accurately (and, post-fix, carry the page's remarks and examples).
- `Nat.choose n k` is written qualified although `open Nat` is in effect. This is
  **deliberately left as-is**: with both `Nat` and `Finset` open, an unqualified
  `choose` would be ambiguous against `Finset.choose`, so the qualification is
  load-bearing, not noise. (Contrast the 1000/1005 cleanups, where the qualification
  was genuinely redundant.)
- `Finset.range` → `range` under the existing `open Finset` applied (same class of fix
  as the 1000/1005 Addenda; no `Nat.range` exists, so no new ambiguity). Compile-
  sensitive: revert if name resolution surprises arise.
- `open Classical in` on `deficiencyDefined` is unnecessary (a plain `Prop` needs no
  decidability) but harmless; on `deficiency` it supplies the `DecidablePred` for
  `filter` and is required (the original session's build log shows exactly this fix
  making the file compile). Left untouched — compiler-dependent.

**C2. Reuse — correctly *avoids* the tempting Mathlib swap.**

- The one plausible reuse target, `Nat.smoothNumbers`, would be **wrong** here:
  Mathlib's convention is strict ($p < n$), the source's is $p \le k$. The local
  `IsSmooth` is therefore necessary, and the review added a docstring warning against
  the swap. (The upstream artifact fell into precisely this trap — Part E.)
- `FormalConjecturesForMathlib/` is not present in this repository; no other reuse
  candidates identified for these elementary definitions.

## E. Prior-review audit

No `ai-review/1093.md` or `reviews/1093.md` exists (problem formalized upstream before
this project). Per the adapted Part E, two audits substitute:

1. **Docstring claims vs. recovered source — all verified.** "A problem of Erdős,
   Lacampagne, and Selfridge" ✓ (page prose); "[ELS88,p.522]" ✓ (page citation link);
   "OPEN" ✓ (banner); both question sentences match the page verbatim ✓; the deficiency
   definition paragraph matches the page's definition ✓.
2. **Upstream artifact audit — substantive defect found (upstream, not fixable here).**
   The recovered upstream `FormalConjectures/ErdosProblems/1093.lean` (two independent
   log captures, byte-identical) defines
   `deficiency n k := #{i ∈ range k | n - i ∈ smoothNumbers k}`. Mathlib's
   `Nat.smoothNumbers k` requires all prime factors **strictly less than** `k`, while
   the source demands "divisible only by primes $\leq k$". These differ exactly when
   `k` is prime: under the upstream encoding, $6 = 2\cdot 3 \notin$
   `smoothNumbers 3`, so $\binom{7}{3}$ gets deficiency **0**, contradicting the
   source's own example list (which gives it deficiency **1**); $\binom{23}{5}$ and
   $\binom{47}{11}$ are likewise miscounted. The correct upstream fix would be
   `smoothNumbers (k+1)`. Secondary upstream nits: part (ii) is a bare `Set.Finite`
   assertion while part (i) uses `answer(sorry) ↔` — an inconsistent treatment of two
   parallel open questions. **This repo's file does not share either flaw**: its local
   `IsSmooth` uses $\le k$, verified against three of the page's worked examples.
   This is the same failure class as the prior-review pattern "wrong claims about
   Mathlib semantics" (cf. the 1002 audit) — here committed by the upstream author,
   caught by checking the encoding against the source's own data.
