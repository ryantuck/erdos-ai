## Summary

The problem (verbatim from the recovered page): "Let $k\geq 2$ and define
$n_k\geq 2k$ to be the least value of $n$ such that $n-i$ divides $\binom{n}{k}$ for
all but one $0\leq i<k$. Estimate $n_k$." Status OPEN; a problem of Erdős and
Selfridge [ErSe83]. The Lean file defines `countDivisors n k` (how many of the $k$
values $n-i$ divide $\binom{n}{k}$), defines $n_k$ as the least $n \ge 2k$ with
`countDivisors n k = k - 1`, and asserts Monier's known bound $n_k \le k!$ as the
main statement — a reasonable formal proxy for the open "Estimate $n_k$", matching
the source's remarks. The definitions capture the mathematics exactly (verified by
hand against all four known values $n_2=4$, $n_3=6$, $n_4=9$, $n_5=12$), but the file
had two genuine defects: the Monier bound was stated with hypothesis `2 ≤ k` although
the source (and the file's own docstring) restricts it to $k \ge 3$ — and it is
**false** at $k = 2$ since $n_2 = 4 > 2 = 2!$ — and the definition of $n_k$ contained
an **unprovable** `sorry` inside a `def` (`Nat.find ⟨k.factorial, sorry⟩`, whose
proof obligation $2k \le k! \wedge \dots$ is false for $k = 1, 2$). Both fixed.

## A. Semantic fidelity

**A1. Statement fidelity — one defect (fixed); definitions otherwise exact
(source-verified).**

- `countDivisors n k` = card of `(range k).filter (fun i => (n - i) ∣ n.choose k)` —
  literally "the number of $0 \le i < k$ with $(n-i) \mid \binom{n}{k}$". Exact.
- "All but one" is encoded as `= k - 1` (exactly $k-1$ divide). For $n \ge 2k$,
  $k \ge 2$, Erdős–Selfridge (remark on the page, proof in [Mo85]) rules out all $k$
  dividing, so "exactly $k-1$" ⟺ "all but (at most) one" — the encoding matches the
  source's meaning on the domain where it is used. Verified concretely: $n_2$: least
  $n \ge 4$ with count $= 1$ is $n = 4$ ($\binom{4}{2}=6$: $4 \nmid 6$, $3 \mid 6$);
  $n_3 = 6$ ($\binom{6}{3}=20$: $6\nmid$, $5\mid$, $4\mid$); $n_4 = 9$
  ($\binom{9}{4}=126$: $9\mid$, $8\nmid$, $7\mid$, $6\mid$; and $n=8$ gives count 2);
  $n_5 = 12$ ($\binom{12}{5}=792$: $12,11,9,8 \mid$, $10 \nmid$; $n=10,11$ give
  counts 3, 2). All four page values reproduce. Term-by-term exact, 0-indexed $i$
  exactly as in the source ($0 \le i < k$).
- The constraint $n_k \ge 2k$ is `2 * k ≤ n` inside the least-element set. Exact.
- **[defect 1]** `erdos_problem_1063` asserted `erdos1063_nk k ≤ k.factorial` under
  `hk : 2 ≤ k`. The source says "Monier [Mo85] observed that $n_k\leq k!$ for
  $k\geq 3$" — and the $k = 2$ instance is literally false: $n_2 = 4$ while
  $2! = 2$. The file's own docstring even stated the $k \ge 3$ restriction, so the
  theorem contradicted its docstring. Fixed to `hk : 3 ≤ k`, with the $k=2$
  counterexample documented (same pattern as the 1004 EPS87 small-parameter fix).
- Not vacuous (post-fix): for $k \ge 3$ the defining set is nonempty ($n = k!$ works,
  which is exactly Monier's observation), `sInf` is the genuine least element, and
  the bound is a substantive true statement (equality at $k = 3$: $n_3 = 6 = 3!$).
- "Estimate $n_k$" itself is a soft estimation request (like 1005's "Estimate
  $f(n)$") and is not directly formalizable; formalizing the best simple known bound
  is a legitimate raw-file reading, and the upstream file does the same (its summary
  lists Monier's bound, Cambie's bound, and small values, with an open
  better-bound question).

**A2. Lean semantics traps — pass (with the def fix).**

- ℕ subtraction `n - i`: inside the defining set, $2k \le n$ and $i < k$ give
  $n - i \ge k+1 \ge 1$ — honest subtraction, never truncated. Unguarded uses of
  `countDivisors` could truncate ($i \ge n$ gives $n-i = 0$, and `0 ∣ C(n,k)` iff
  `C(n,k) = 0`), but no theorem uses it there; now documented in the docstring.
- `k - 1` on ℕ: for $k \ge 2$ honest; for $k = 0$ it truncates to $0$, making every
  $n$ qualify (count and target both 0) — a degenerate case outside all theorems,
  now documented.
- `Finset.range k` = $\{0,\dots,k-1\}$ matches $0 \le i < k$ exactly. No off-by-one.
- Degenerate $k = 1$: `countDivisors n 1 = 1` always ($n \mid \binom{n}{1} = n$), so
  the defining set is **empty** and `sInf ∅ = 0` is a junk value — harmless (all
  theorems assume $k \ge 2$) and now documented. This is precisely why the original
  `Nat.find` encoding was unfixable (below).
- No division, no filters/limits, no `StrictMono`/interval issues in the file.

**A3. Definitions — one defect (fixed).**

- **[defect 2]** `erdos1063_nk` was defined as
  `Nat.find (⟨k.factorial, sorry⟩ : ∃ n, 2 * k ≤ n ∧ countDivisors n k = k - 1)` —
  a `sorry` inside a `def` (checklist A3 violation even for raw files: soundness,
  not style). Worse, the `sorry` is **unprovable as placed**: it must prove
  `2 * k ≤ k.factorial ∧ countDivisors k.factorial k = k - 1` for *arbitrary* `k`,
  and at $k = 2$ the first conjunct is $4 \le 2$ (false; at $k=1$, $2 \le 1$).
  Replacing it by a whole-existential `sorry` would not help either: at $k = 1$ the
  existential itself is false (the set is empty). The def could therefore never be
  completed. Fixed by the corpus-standard idiom (used by raw siblings 1011, 1013,
  1014, 1015, 1054, 1055, 1083, …):
  `sInf {n | 2 * k ≤ n ∧ countDivisors n k = k - 1}` — sorry-free, value unchanged
  wherever the set is nonempty (all $k \ge 2$; `Nat.sInf` = `Nat.find` there), junk
  value 0 for $k = 1$ documented. Note `Nat.find`'s *value* was proof-irrelevant, so
  no theorem's meaning changes.
- `countDivisors` matches its docstring exactly, including degenerate inputs (now
  documented). No other `sorry` in defs. Defs and theorems use the same notion — no
  drift.

**A4. Question form and answer polarity — pass (raw-file convention).**

- The source is a value/estimate request ("Estimate $n_k$"), OPEN. Raw files in this
  corpus do not use the `answer()` elaborator; per the run instructions,
  direct-assertion form for the *known, true* partial results is acceptable raw
  style with correct polarity. Post-fix, all three statements (Monier bound for
  $k \ge 3$; Erdős–Selfridge non-divisor existence; the four small values) are true
  directions, source-confirmed. No `answer()` and hence no binder-placement issue.

**A5. Solution status — pass (source-verified).**

- Recovered banner: **OPEN** (tooltip: "This is open, and cannot be resolved with a
  finite computation."), with the owner's standard disclaimer. The file (raw style)
  has no category tag; the docstring now records OPEN with the page edition
  (01 February 2026) and access date (2026-03-06). The formalized statements are
  known-true partial results, correctly not claiming a resolution of the estimation
  problem.
