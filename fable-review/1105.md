## Summary

The problem defines the anti-Ramsey number AR(n,G) — the maximum number of colours in an
edge-colouring of $K_n$ containing no rainbow copy of $G$ — and asks two yes/no
questions: (i) is $\mathrm{AR}(n,C_k) = \left(\frac{k-2}{2}+\frac{1}{k-1}\right)n +
O(1)$, and (ii) for $n \ge k \ge 5$, is $\mathrm{AR}(n,P_k) =
\max\left(\binom{k-2}{2}+1,\ \binom{\ell-1}{2}+(\ell-1)(n-\ell+1)+\epsilon\right)$ with
$\ell = \lfloor(k-1)/2\rfloor$, $\epsilon = 1$ for odd $k$, else $2$? Both were answered
affirmatively (page status: PROVED); the cycle asymptotic follows from
Montellano-Ballesteros–Neumann-Lara's exact formula [MoNe05], and the path formula was
announced by Yuan [Yu21]. The Lean file states both results as direct assertions —
acceptable form for a solved problem with the true polarity — and the theorem-level
encodings (O(1) as ∃ C bound, the ℕ-arithmetic path formula) are faithful. However, the
supporting definition `antiRamseyNumber` counts `Set.ncard (Set.range c)` over the
*whole* of `Sym2 (Fin n)`, whose n diagonal elements are not edges of $K_n$; the
supremum it computes is exactly $\mathrm{AR}(n,G) + n$, which falsifies both theorem
statements as written. That is the single [defect]; everything else is polish.

## A. Semantic fidelity

**A1. Statement fidelity — one defect (in a definition, surfacing here); rest pass
(source-verified).**

- Recovered verbatim source statement (see Addendum) matches the module docstring
  (lines 11–32) essentially word for word, including both question parts, the
  definition of AR, ℓ, and ε.
- Independent back-translation of `erdos_problem_1105_cycles` (lines 70–74): "for every
  k ≥ 3 there is a C ≥ 0 with |AR′(n,C_k) − ((k−2)/2 + 1/(k−1))·n| ≤ C for all
  n ≥ k", where AR′ is the file's `antiRamseyNumber`. As an encoding of
  "= (…)n + O(1)" this shape is correct: C is quantified after k (may depend on k), and
  a bound for all n ≥ k is equivalent to an eventual bound since each term is finite.
- Independent back-translation of `erdos_problem_1105_paths` (lines 85–91): "for
  n ≥ k ≥ 5, AR′(n,P_k) = max(C(k−2,2)+1, C(ℓ−1,2)+(ℓ−1)(n−ℓ+1)+ε)" — exactly the
  source formula, *provided* AR′ means AR. It does not (see the defect under A3/A2),
  so both theorems are literally false as written.
- Quantifier structure: cycles — ∀k ∃C ∀n, correct (O(1) constant may depend on k);
  paths — ∀k ∀n with explicit hypotheses 5 ≤ k, k ≤ n matching "n ≥ k ≥ 5". The
  cycles part adds the domain restriction n ≥ k, harmless under O(1) (finitely many
  smaller n, each with a finite value).
- Indexing: vertices are `Fin k`; `pathGraph1105` links i to i+1 (path
  0−1−⋯−(k−1), exactly k vertices and k−1 edges); `cycleGraph1105` links i to
  (i+1) mod k (k vertices, k edges for k ≥ 3). Term-by-term correct at the first
  index; no off-by-one.
- Not vacuous: for n ≥ k an embedding `Fin k ↪ Fin n` exists, so the no-rainbow
  constraint genuinely binds; both equalities are substantive claims.

**A2. Lean semantics traps — one genuine trap sprung (the defect); the classical traps
all pass.**

- **The defect (domain of the color count).** `antiRamseyNumber` (lines 44–47) takes
  `sSup {k | ∃ c : Sym2 (Fin n) → ℕ, Set.ncard (Set.range c) = k ∧ ¬HasRainbowCopy}`.
  `Sym2 (Fin n)` contains the n diagonal elements s(i,i), which are not edges of $K_n$,
  and `HasRainbowCopy` never evaluates c on them (edge-images under an injective map
  are non-diagonal). So the diagonal values are unconstrained and count toward
  `Set.range c`. Consequence, computed exactly: for n ≥ 1 and G with at least two
  edges, the supremum equals AR(n,G) + n. Lower bound: take an extremal AR-coloring
  on the edges and n fresh colors on the n loops. Upper bound: any c avoiding a
  rainbow copy uses ≤ AR(n,G) colors on edges and ≤ n further colors on loops.
  Concrete counterexample to `erdos_problem_1105_paths`: k = n = 5 gives ℓ = 2, RHS =
  max(C(3,2)+1, C(1,2)+1·4+1) = max(4,5) = 5, while LHS = AR(5,P_5) + 5 = 10 (the
  true AR(5,P_5) being the formula value 5). For the cycles theorem the deviation is
  n + O(1) → ∞, so no C exists: the ∃C statement is false for every k. **[defect]** —
  fixed in v2 by counting `Set.ncard (c '' {e : Sym2 (Fin n) | ¬e.IsDiag})`, i.e.
  colors on the actual edges of $K_n$ (not compile-verified).
- ℕ subtraction (paths theorem): k − 2 with k ≥ 5 is safe; ℓ = (k−1)/2 ≥ 2 so
  ℓ − 1 ≥ 1 is safe; n − ℓ with n ≥ k > ℓ is safe, and `n - ℓ + 1` parses as
  (n − ℓ) + 1, which equals the mathematical n − ℓ + 1 given ℓ ≤ n. No truncation
  anywhere. In the cycles theorem all subtraction is in ℝ after casting.
- Division: `(k - 1) / 2` in ℕ is floor division — exactly the source's
  ⌊(k−1)/2⌋. Real division `1 / ((k : ℝ) - 1)` has k ≥ 3, denominator ≥ 2 ≠ 0.
- No `Finset.range` usage; no range off-by-ones possible.
- Vacuous quantifiers: none. For n < k no embedding exists and `HasRainbowCopy` is
  uniformly false, making `antiRamseyNumber` degenerate (all colorings allowed), but
  both theorems hypothesize n ≥ k, so the degenerate regime is never asserted about.
- "O(1)" encoding via ∃ C ≥ 0 bound: standard and correct here (see A1).
- `sSup` well-definedness: the defining set is nonempty (a constant coloring avoids a
  rainbow copy of any G with ≥ 2 edges — C_k has k ≥ 3 edges, P_k has k−1 ≥ 4) and
  bounded (≤ |Sym2 (Fin n)|, finite), so ℕ's `sSup` is a genuine maximum. Same holds
  after the v2 fix (bounded by C(n,2)).
- Strict vs non-strict: `3 ≤ k`, `5 ≤ k`, `k ≤ n`, `n ≥ k` all match the source's
  non-strict conventions.

**A3. Definitions — one defect (as above), rest pass.**

- `HasRainbowCopy` (lines 37–40) matches its docstring and the source notion: an
  embedding φ : V ↪ Fin n such that e ↦ c(Sym2.map φ e) is injective on `G.edgeSet`,
  i.e. a copy of G in $K_n$ all of whose edges receive pairwise distinct colors.
  Injectivity of φ makes edge-images distinct non-diagonal pairs, so distinct edges
  are genuinely compared. Host completeness is correctly implicit (any injection into
  Fin n is a copy in $K_n$).
- `antiRamseyNumber` (lines 42–47): its docstring says "maximum number of distinct
  colors used in an edge-coloring of K_n" but the code counts colors over all of
  `Sym2 (Fin n)` including loops — the def/docstring mismatch is the same [defect]
  as in A2, in its clearest form: the code does not compute what the docstring (and
  the problem) say.
- `pathGraph1105` (lines 49–53): adjacency i+1 = j ∨ j+1 = i on `Fin k` values;
  symmetric, loopless (omega); degenerate k = 0, 1 give the empty graph. Matches
  docstring.
- `cycleGraph1105` (lines 55–60): i ≠ j ∧ ((i+1) % k = j ∨ (j+1) % k = i); for
  k ≥ 3 this is the k-cycle (checked at k = 3, 4 by hand, including the wrap-around
  edge {k−1, 0}); k = 2 degenerates to a single edge and k ≤ 1 to the empty graph,
  but all uses carry k = 3 or hk : 3 ≤ k. Matches docstring.
- No `sorry` inside any def/abbrev/structure.
- Consistency def ↔ theorem: uniform (both theorems use the same `antiRamseyNumber`,
  so the single fix repairs both).
