## Summary

The problem (erdosproblems.com/1052, status **OPEN**, $10 prize): "A unitary divisor of
$n$ is $d \mid n$ such that $(d, n/d) = 1$. A number $n \geq 1$ is a unitary perfect
number if it is the sum of its unitary divisors (aside from $n$ itself). Are there only
finite[ly] many unitary perfect numbers?" — problem B3 in Guy's collection [Gu04];
Carlitz, Erdős, and Subbarao offer \$10 for settling it. The Lean file defines
`unitaryDivisors n` as `n.divisors.filter (fun d => Nat.Coprime d (n / d))`,
`IsUnitaryPerfect n` as `1 ≤ n ∧` (sum of unitary divisors `≠ n`) `= n`, and asserts
`Set.Finite {n : ℕ | IsUnitaryPerfect n}`. Read back independently, the definitions
match the source exactly (verified computationally: the predicate holds for precisely
6, 60, 90, 87360 below $10^5$, and $\sigma^*(N) = 2N$ for the fifth known example), and
the direct-assertion form for this open yes/no question asserts the "yes" direction of
the question as asked — the established raw-file convention in this repository (cf.
`fable-review/1049.md`); the recovered upstream file encodes the identical mathematics
as `answer(sorry) ↔ {n | IsUnitaryPerfect n}.Finite`. No semantic defects; only
polish-level nits (no module docstring/bibliography, remarks dropped between the two
authoring drafts), fixed in place per the Addendum.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (both captures agree): "A unitary divisor of $n$
  is $d\mid n$ such that $(d,n/d)=1$. A number $n\geq 1$ is a unitary perfect number if
  it is the sum of its unitary divisors (aside from $n$ itself). ... Are there only
  finite many unitary perfect numbers?" (sic — the site's "finite many"; the docstring's
  "finitely many" is a grammar fix, not a meaning change).
- Independent back-translation of the theorem: "the set of $n \in \mathbb{N}$ that are
  unitary perfect is finite." This is the "yes" direction of the question as asked.
- `unitaryDivisors n = n.divisors.filter (fun d => Nat.Coprime d (n / d))`:
  `Nat.divisors n` is the divisors of `n` in `[1, n]` (empty at `n = 0`); for `d ∣ n`
  the ℕ-division `n / d` is exact, and `Nat.Coprime d (n / d)` is `gcd(d, n/d) = 1` —
  exactly the source's definition of unitary divisor.
- `IsUnitaryPerfect n = 1 ≤ n ∧ ((unitaryDivisors n).filter (· ≠ n)).sum id = n`: since
  `n` itself is always a unitary divisor for `n ≥ 1` (`gcd(n, 1) = 1`), the filtered sum
  is $\sigma^*(n) - n$, so the condition is "$n$ is the sum of its unitary divisors
  aside from $n$ itself" — verbatim the source. The `1 ≤ n` guard mirrors the source's
  "$n \geq 1$" and is load-bearing: without it, `n = 0` would vacuously satisfy
  `sum ∅ = 0`.
- **Computational verification** (independent Python model of the Lean semantics,
  including the `d ≠ n` filter and the `1 ≤ n` guard): the predicate holds for exactly
  $\{6, 60, 90, 87360\}$ on $[1, 10^5]$, matching the page's list; `n = 1` correctly
  fails (proper unitary sum 0); and for $N = 146361946186458562560000 =
  2^{18}\cdot3\cdot5^4\cdot7\cdot11\cdot13\cdot19\cdot37\cdot79\cdot109\cdot157\cdot313$,
  $\sigma^*(N) = \prod(1 + p^a) = 2N$, confirming the fifth example satisfies the
  encoding.
- Not vacuous/trivial: the set is nonempty (contains 6) and its finiteness is a
  substantive open conjecture; the statement cannot be discharged degenerately.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere (the "σ*(n) − n" of the docstring is realized by filtering
  out `d = n` before summing, not by truncated subtraction — the right encoding).
- Division: `n / d` occurs only under `d ∈ n.divisors`, where `d ∣ n` and `d ≥ 1`, so
  it is exact and never divides by zero.
- No `Finset.range` in the final file; `Nat.divisors`'s internal `Ico 1 (n+1)` gives
  exactly `[1, n]` — no off-by-one (checked: `d = 1` and `d = n` are both unitary
  divisors, as intended; the `(· ≠ n)` filter removes only `n` itself).
- Degenerate inputs: `unitaryDivisors 0 = ∅`; `IsUnitaryPerfect 0` is false via the
  guard; `IsUnitaryPerfect 1` is false (`sum ∅ = 0 ≠ 1`) — all match the informal
  notion. No vacuous-quantifier traps (no bounded quantifiers at all).
- "Finitely many" is encoded as `Set.Finite`, the canonical Mathlib notion — correct
  (no filter/density subtlety in this problem).
- No `StrictMono`/`Monotone` or interval-endpoint issues arise.

**A3. Definitions — pass.**

- No `sorry` inside any `def`/`abbrev`/`structure` (Part D). No drift between what the
