## Summary

The problem (Erdős–Selfridge classification; Guy A18): a prime $p$ is in class $1$ if
$p+1$ is $\{2,3\}$-smooth, and in class $r$ if every prime factor of $p+1$ has class
$\le r-1$ with equality for at least one factor. Are there infinitely many primes in
each class, and how does $p_r^{1/r}$ behave, where $p_r$ is the least prime in class
$r$ ($p_r = 2, 13, 37, 73, 1021, \ldots$, OEIS A005113)? Erdős thought
$p_r^{1/r} \to \infty$; Selfridge thought it bounded. Status OPEN. The pre-fix Lean
file defined the class as a well-founded recursive ℕ-valued function whose
`decreasing_by` was discharged by `all_goals sorry`, then asserted (part 1) that each
class $r \ge 1$ contains infinitely many primes and (part 2) Erdős's growth conjecture
$p_r^{1/r} \to \infty$ via `Tendsto _ atTop atTop`. The mathematical content of both
theorems is a faithful rendering of the problem (verified against the recovered page
and numerically against A005113), but the `sorry` inside the definition is a Part A
defect, and Selfridge's direction of part 2 — present in both the file's first commit
and the upstream artifact — had been silently dropped in a rewrite.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (both captures agree): "A prime $p$ is in class
  $1$ if the only prime divisors of $p+1$ are $2$ or $3$. In general, a prime $p$ is
  in class $r$ if every prime factor of $p+1$ is in some class $\leq r-1$, with
  equality for at least one prime factor. // Are there infinitely many primes in each
  class? If $p_r$ is the least prime in class $r$, then how does $p_r^{1/r}$ behave?"
  The module docstring reproduces this essentially verbatim.
- The informal recursive definition is *ambiguous read literally*: $2$ and $3$ are
  themselves class-1 primes (e.g. $p_1 = 2$), so for $p = 5$ ($p+1 = 6 = 2\cdot 3$)
  the base clause gives class $1$ while the general clause (factors of class $1$,
  equality attained) would give class $2$. The standard resolution — base clause takes
  precedence; equivalently, in the recursion the factors $2, 3$ contribute level $0$ —
  is exactly what the pre-fix Lean encoded (`if q = 2 ∨ q = 3 then 0 else class q`,
  then `sup + 1`). I verified by direct computation that this encoding and the
  base-clause-precedence literal reading agree everywhere sampled and both reproduce
  the page's/OEIS A005113's $p_r = 2, 13, 37, 73, 1021$ for $r = 1..5$; the two
  readings coincide for all primes (whenever some factor lies outside $\{2,3\}$ its
  class is $\ge 1 \ge$ the special-cased contribution of $2,3$, so the max is
  unchanged; when no factor does, both give class $1$).
- Part 1: `Set.Infinite (erdos1055_classSet r)` for all `r ≥ 1` is the "yes" direction
  of the question, universally over classes — matching "infinitely many primes in
  *each* class". The guard `1 ≤ r` is essential, not cosmetic: class 0 is empty (every
  prime has class $\ge 1$), so the unguarded statement would be false at $r = 0$.
- Part 2: `Tendsto (fun r => (p_r : ℝ) ^ ((r : ℝ)⁻¹)) atTop atTop` is exactly
  $p_r^{1/r} \to \infty$, Erdős's conjectured answer to "how does $p_r^{1/r}$
  behave?". Upstream states the same (`erdos_1055.variants.erdos_limit`, with
  `1 / r` for `(r : ℝ)⁻¹` — identical). **Selfridge's bounded direction was missing**
  (see B2); the page presents both beliefs and the upstream artifact formalizes both.
- Not vacuous/trivial: class sets are genuinely nontrivial (class 1 = primes with
  $3$-smooth $p+1$: $2,3,5,7,11,17,23,\ldots$; class 2 starts at 13), and the growth
  statement is a substantive open dichotomy.

**A2. Lean semantics traps — pass (with documented junk-value conventions).**

- No ℕ subtraction in the pre-fix file. (The post-fix `erdos1055_hasClass` uses
  `r - 1` guarded by the `1 ≤ r` conjunct; at `r = 1` it degrades to `¬False`,
  which is the intended "no prime has class 0".)
- Division/rpow: `(p_r : ℝ) ^ ((r : ℝ)⁻¹)` at `r = 0` gives exponent `0⁻¹ = 0` (field
  convention) and `x ^ 0 = 1` — a junk first term invisible to `atTop`. Harmless.
- `sInf` on ℕ of a possibly-empty set returns 0: if some class $r \ge 1$ were empty
  (an open sub-question!), `erdos1055_leastPrimeInClass r = 0` and its term in the
  growth sequence is $0^{1/r} = 0$. The Tendsto statement thus implicitly asserts
  classes are eventually nonempty — consistent with the problem's own presupposition
  ("If $p_r$ is the least prime in class $r$..."), and now documented in the
  docstring, with the nonemptiness itself split out as an auxiliary statement
  (mirroring upstream's `exists_p`). Upstream instead defines $p_r$ by `Nat.find`
  *applied to its own sorried existence theorem* — legal but arguably worse: a
  definition depending on a `sorry`. The `sInf` route reviewed here avoids that.
- No `Finset.range`, no off-by-one indexing; $r$ ranges over ℕ with explicit
  `1 ≤ r` guards where needed (upstream uses ℕ+ — equivalent).
- Filter encoding `Tendsto _ atTop atTop` is the standard encoding of divergence to
  infinity; `∃ M, ∀ r, … ≤ M` is the standard encoding of boundedness.
- No `StrictMono`/`Monotone` or interval-endpoint issues arise.

**A3. Definitions — DEFECT (fixed).**

- **[defect]** Pre-fix `erdos1055_primeClass` carried `decreasing_by all_goals sorry`
  — a `sorry` inside a `def`, caught verbatim by the Part D awk check. Worse than a
  style violation: session B's own build log (see Addendum) shows that with the
  recursive call under `Finset.image (fun q => …)`, Lean generates the termination
  obligation *without the membership hypothesis* `q ∈ (p+1).primeFactors` (omega's
  counterexample constraints mention only `q ≥ 0`-type facts), so the goal as
  generated is **unprovable** — the `sorry` is load-bearing, not a placeholder for an
  easy proof. Mitigations, for the record: the underlying termination fact *is* true
  (a prime factor $q \notin \{2,3\}$ of $p+1$, $p$ prime, satisfies $q < p$ — if
  $q = p+1$ then $p, p+1$ are twin consecutive primes forcing $(p,q) = (2,3)$,
  excluded; otherwise $q \le (p+1)/2 < p$), each *instance* of the sorried obligation
  encountered by the recursion is therefore true, and the equation the def satisfies
  pins down exactly the intended class function (verified numerically). So the
  theorems' *meaning* was right; the artifact was still unsound by A3. **Fixed** by
  replacing the ℕ-valued recursive function with the sorry-free Prop-based encoding
  (`erdos1055_classAtMost` / `erdos1055_hasClass`) from the file's own first commit
  (0d9074d5), which compiled clean in the pipeline on 2026-02-22 with only theorem
  `sorry`s. Structural recursion on `r`; no well-foundedness obligations at all.
- Equivalence of the two encodings (hand proof): `classAtMost` is monotone in `r`
  (because $2,3$ have class 1), `classAtMost 0 = False`, and for prime `p`,
  `classAtMost r p ⟺ class(p) ≤ r`; hence
  `hasClass r p ⟺ class(p) = r` for primes, and `classSet`/`leastPrimeInClass` are
  unchanged as mathematical objects. Non-primes can vacuously satisfy
  `classAtMost`/`hasClass` (e.g. `hasClass 1 8` since $9 = 3^2$), but every use
  conjoins `Nat.Prime p` — now documented.
- No drift between definitions and theorem statements.

**A4. Question form and answer polarity — acceptable raw style (source-verified).**

- Both parts are questions ("Are there infinitely many…?", "how does … behave?").
  The raw file states part 1 as a direct assertion of the "yes" direction and part 2
  as direct assertions of each named belief — **exactly the upstream authoritative
  artifact's convention** (`erdos_1055`, `…variants.erdos_limit`,
  `…variants.selfridge_limit`, all `research open` with `sorry`). Per the pipeline's
  raw-file criterion (judge soundness/polarity, not styling), this is acceptable;
  polarity is the conjectured/believed direction in each case and the docstrings say
  so explicitly. No `answer()` machinery exists in this raw file, so the
  binders-before-colon trap does not arise.
- The two part-2 statements are mutually exclusive; each is attributed and cannot be
  read as a claim of settled truth (docstrings updated to cross-reference each other).

**A5. Solution status — pass (source-verified).**

- Both recovered captures carry the **OPEN** banner (tooltip: "This is open, and
  cannot be resolved with a finite computation.") plus the owner's standard
