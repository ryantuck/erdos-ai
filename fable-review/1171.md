## Summary

The problem ([Va99, 7.84], OPEN): *Is it true that, for all finite k < ω,
ω₁² → (ω₁·ω, 3, …, 3)²_{k+1}?* — i.e., for every (k+1)-coloring of the pairs of
ordinals below ω₁², is there either a homogeneous set of order type ω₁·ω in color 0 or
a monochromatic triple in one of the remaining k colors. The Lean file
(`conjectures/1171.lean`) defines `omega1 := (aleph 1).ord`, defines the multi-color
partition relation `OrdinalPartitionMulticolor α k target₀ target_rest` via strictly
monotone embeddings of `{x // x < target}` into `{x // x < α}` with monochromaticity on
increasing pairs, and asserts `OrdinalPartitionMulticolor (omega1 ^ 2) k
(omega1 * omega0) 3` for every `k : ℕ` with a `sorry` proof — the direct assertion of
the asked ("yes") direction, this raw corpus's standard convention for open yes/no
questions. Read back independently, the definition is an exactly correct rendering of
α → (β₀, β₁, …, β₁)²_{k+1} and the instantiation matches the source term-by-term
(ω₁² source, ω₁·ω for color 0, 3 for each of the k other colors). No semantic defects;
the single defect is scholarship-class: the citation keys [Va99] and [Ba89b] are used
in the theorem docstring but defined nowhere in the file (no module docstring, no
bibliography). Fixed in `conjectures-v2/1171.lean`.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Is it true that, for all finite
  $k<\omega$,\[\omega_1^2\to (\omega_1\omega, 3,\ldots,3)_{k+1}^2?\]" The theorem
  docstring (lines 27–34) reproduces the question and adds a correct natural-language
  gloss of the arrow notation.
- Independent back-translation of lines 41–43: "for every natural number k, for every
  function f from ordered pairs of ordinals below ω₁² to Fin (k+1), either there is a
  strictly monotone map g from the ordinals below ω₁·ω to the ordinals below ω₁² with
  f(g i, g j) = 0 for all i < j, or there are a color c with c.val > 0 and a strictly
  monotone map g from the ordinals below 3 to the ordinals below ω₁² with
  f(g i, g j) = c for all i < j." This is exactly ∀ k < ω :
  ω₁² → (ω₁·ω, 3, …, 3)²_{k+1}: the subscript k+1 is the number of colors (`Fin
  (k+1)`), entry 0 is ω₁·ω, and each of the k remaining entries is 3 — a homogeneous
  set of order type 3 being precisely a monochromatic triple.
- Ordinal arithmetic checked against Mathlib's conventions: `omega1 ^ 2` is ordinal
  exponentiation, ω₁² = ω₁·ω₁ (the source ordinal); `omega1 * omega0` follows Mathlib's
  standard convention `a * succ b = a * b + a`, so it is ω copies of ω₁ — the standard
  ω₁·ω of the source notation ω₁ω, and ω₁·ω < ω₁·ω₁ = ω₁², so the color-0 target is a
  proper target. `omega0` is Mathlib's `Ordinal.omega0` via `open Ordinal`; the literal
  `3` is the ordinal 3.
- Order-type encoding: a strictly monotone `g : {x // x < β} → {x // x < α}` between
  well-ordered subtypes is an order isomorphism onto its image, so its image has order
  type exactly β; conversely any subset of order type β admits such an enumeration, and
  a homogeneous set of type ≥ β restricts to one of type exactly β. The `∃ g,
  StrictMono g` encoding is exactly "there exists a homogeneous subset of order type β".
  Term-by-term exact, no translation residue.
- Not vacuous: for k ≥ 1 this is a substantive open partition relation (the k = 1 case
  already strengthens the setting of Baumgartner's conditional result from source ω₁·ω
  to ω₁²). The k = 0 instance is trivially true (below, A2) but matches the informal
  reading of the degenerate 1-color relation; no silent alteration.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction, no division, no `Finset.range`, no sequence indexing anywhere —
  the whole statement lives in `Ordinal` with `<`, `^`, `*` only.
- Subtype order: `i < j` on `{x : Ordinal // x < α}` is `i.val < j.val`, the induced
  well-order of type α; `StrictMono` uses exactly that order on both sides. Correct.
- Coloring domain: `f` is a *total* function on ordered pairs (diagonal and decreasing
  pairs included), while the standard relation colors unordered 2-element subsets.
  Equivalence checked by hand: homogeneity reads `f` only at (g i, g j) with i < j,
  hence only at increasing pairs (`StrictMono` gives g i < g j); every coloring of
  increasing pairs extends to a total function, so quantifying over total `f` neither
  strengthens nor weakens the relation.
- Degenerate k = 0: the color type is `Fin 1`; the second disjunct requires
  `0 < c.val` for `c : Fin 1`, which is unsatisfiable, so the relation reduces to
  "every 1-coloring admits a set of order type ω₁·ω homogeneous in the only color 0" —
  true, since every pair is colored 0 and a strictly monotone embedding of
  `{x // x < ω₁·ω}` into `{x // x < ω₁²}` exists (ω₁·ω < ω₁²), e.g. the inclusion of
  values. This matches the informal degenerate instance of "for all finite k"; not a
  vacuity problem.
- `0` and `c` in `Fin (k + 1)`: `k + 1 > 0`, so the literal `0 : Fin (k+1)` is
  well-formed; `0 < c.val` correctly says "c is not color 0".
- `StrictMono` (not `Monotone`) is required and used — a merely monotone map could
  collapse the set and misrepresent the order type. Strict `<` on `i < j` is the right
  pair condition. Correct choices throughout.
- Universe note: `Ordinal` carries no universe ascription, so the statement is
  universe-polymorphic and reads identically about each universe's ω₁; harmless, same
  design as sibling `conjectures/1170.lean` (see fable-review/1170.md §A2).

**A3. Definitions — pass.**
