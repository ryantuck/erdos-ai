## Summary

The problem (OPEN on the source page): can every large integer n be written
as n = x² + y² − z² with max(x², y², z²) ≤ n? The page remarks that the
largest integer known which cannot be written this way is 6563, and that
[Va99] reports the analogous statement to be 'obvious' if ≤ n is relaxed to
≤ n + 2√n. The Lean file (`conjectures/1148.lean`, lines 12–16) asserts:
there exists N such that every n ≥ N admits x, y, z : ℕ with
x² + y² − z² = n (equation stated in ℤ via a type ascription) and
x² ≤ n ∧ y² ≤ n ∧ z² ≤ n. Read back independently, this is exactly the
asked ("yes") direction of the question, in the direct-assertion form this
raw corpus uniformly uses for open yes/no questions. I found no semantic
defects; the one defect is bibliographic (the used citation key is defined
nowhere). Computational cross-checks performed for this review confirm the
page's 6563 remark and the plausibility of the conjectured direction.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Can every large
  integer $n$ be written as $n=x^2+y^2-z^2$ with
  $\max(x^2,y^2,z^2)\leq n$?" — status banner **OPEN** (tooltip: "This is
  open, and cannot be resolved with a finite computation."), with the
  owner's standard disclaimer. Single remark: "The largest integer known
  which cannot be written this way is $6563$. [Va99] reports this is
  'obvious' if we replace $\leq n$ with $\leq n+2\sqrt{n}$."
- Independent back-translation of lines 13–15: "there is a threshold N such
  that every natural n ≥ N can be written n = x² + y² − z² (computed in ℤ)
  with x², y², z² all ≤ n." "Every large integer n" is the standard
  eventually-all reading, correctly rendered `∃ N, ∀ n ≥ N`; the direction
  asserted is the question as asked (see A4).
- Types: n, x, y, z : ℕ with the defining equation type-ascribed to ℤ
  (`(x ^ 2 + y ^ 2 : ℤ) - z ^ 2 = n`), so the subtraction happens in ℤ and
  the equality coerces n — arithmetic in the intended ring. Restricting the
  witnesses x, y, z to ℕ rather than ℤ is without loss of generality: only
  their squares occur, and (−x)² = x². Restricting n to ℕ is likewise
  faithful — "every large integer" concerns n → +∞.
- max(x², y², z²) ≤ n is encoded as the three conjuncts
  `x ^ 2 ≤ n ∧ y ^ 2 ≤ n ∧ z ^ 2 ≤ n` (in ℕ, where the squares live) —
  elementwise ≤ is exactly max ≤. Equivalent and arguably clearer than a
  `max` term.
- Indexing: no sequences, no indexing conventions to reconcile.
- Not vacuous or trivially true/false: the constraint genuinely bites —
  computationally there are exactly 77 non-representable n below 8000
  (largest 6563), so no degenerate witness family (e.g. z = y forcing
  n = x²) satisfies the statement trivially, and the assertion is the
  substantive open conjecture, true for all checked n in (6563, 20000].

**A2. Lean semantics traps — pass.**

- **ℕ subtraction: none.** The only subtraction is `- z ^ 2` inside the
  ℤ-ascribed equation, so it is integer subtraction; no truncation-at-0
  hazard. This is the single most likely trap for this problem shape and
  the first pass handled it correctly. (Had the equation been stated in ℕ,
  `x ^ 2 + y ^ 2 - z ^ 2 = n` would be satisfied by truncation artifacts
  whenever z² > x² + y², e.g. x = y = 0, z² > 0, n = 0 — the ascription
  avoids exactly this.)
- Division: none anywhere.
- `Finset.range`: none; no off-by-one surface.
- Vacuous quantifiers: `∀ n ≥ N` over ℕ is never vacuous (ℕ is unbounded);
  the existential over N is the intended "for all sufficiently large".
  `∃ N, ∀ n ≥ N, P n` is the correct filter-free rendering of
  `∀ᶠ n in atTop, P n` (the file imports `AtTopBot.Basic` but does not use
  filters — see C1).
- Boundary values: for tiny n the statement imposes nothing (they sit below
  N); at n = 0, x = y = z = 0 works anyway. No degenerate-index issues.
- No `StrictMono`/`Monotone`, no open/closed interval subtleties.

**A3. Definitions — pass (trivially).**

- The file declares no `def`/`abbrev`/`structure`; nothing to check, no

**A4. Question form and answer polarity — pass (corpus convention).**

- The source is a **yes/no question** ("Can every large integer…?"),
