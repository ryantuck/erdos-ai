## Summary

The problem (verbatim from the recovered page): "We say $G$ is Ramsey size
linear if $R(G,H)\ll m$ for all graphs $H$ with $m$ edges and no isolated
vertices. Are there infinitely many graphs $G$ which are not Ramsey size
linear but such that all of its subgraphs are?" Status **PROVED** ("solved in
the affirmative") — Wigderson [Wi24] proved there are infinitely many such
graphs, non-explicitly; $K_4$ remains the only explicit example. The Lean file
defines subgraph containment (`IsSubgraphOf`), the classical Ramsey property
`R(G,H) ≤ n` via 2-colorings of $K_n$ (`RamseyProp`), `NoIsolatedVertices`,
and `IsRamseySizeLinear` ($\exists C>0$ with $R(G,H) \le C\cdot e(H)$ for all
isolated-vertex-free $H$), then asserts: for every $N$ there is a graph $G$ on
$p \ge N$ vertices that is not Ramsey size linear while every proper subgraph
(H embeds in G, G does not embed in H) is. I back-translated independently and
verified the encoding computationally; the Lean says exactly what the problem
says, in the correct (affirmative, solved) polarity. **No semantic defects.**
The gaps are scholarship (no bibliography, [Er95] uncited) and docstring
explicitness about two interpretive steps, addressed in
`conjectures-v2/79.lean`. Notably, the prior review's "most critical issue" —
that the file should have used the *size Ramsey number* $\hat r$ — is refuted
by the recovered source, which defines Ramsey size linearity via the
*classical* Ramsey number $R(G,H)$, exactly as the file does.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Independent back-translation of lines 48-55: "For every natural $N$ there
  exist $p \ge N$ and a graph $G$ on `Fin p` such that (i) $G$ is not Ramsey
  size linear, and (ii) every graph $H$ (on any `Fin q`) that embeds into $G$,
  and into which $G$ does not embed, is Ramsey size linear." This is the
  affirmative answer to the page's question, with "infinitely many" rendered
  as "arbitrarily many vertices" and "proper subgraph of $G$" rendered
  up-to-isomorphism.
- **"Infinitely many" encoding is faithful.** Forward: infinitely many
  pairwise non-isomorphic witnesses must have unbounded vertex counts
  (finitely many graphs per count), and any witness with $k \ge N$ vertices
  lives on `Fin k`. Backward: a small witness cannot be smuggled onto a large
  `Fin p` by padding with isolated vertices — for a padded $G' = G \sqcup
  \overline{K_t}$, the core $G$ is a proper subgraph of $G'$
  ($G \sqsubseteq G'$, $G' \not\sqsubseteq G$ by vertex count) and $G$
  non-RSL forces clause (ii) to fail (and $G'$ non-RSL ⇔ $G$ non-RSL, since
  $R(G',H) \le \max(R(G,H), |V(G')|)$ and $e(H) \ge 1$ for every nontrivial
  $H$ in the quantification). So each witness is genuinely a new minimal
  example. The padding loophole that would afflict a bare
  "arbitrarily-large-vertex-count" encoding is closed precisely by the
  minimality clause the problem itself carries.
- **"Proper subgraph" encoding is exactly right.** For finite simple graphs,
  an adjacency-preserving injection gives $e(H) \le e(G)$ and
  $|V(H)| \le |V(G)|$, so `IsSubgraphOf H G ∧ ¬ IsSubgraphOf G H` holds iff
  $H$ is isomorphic to a subgraph of $G$ not equal to $G$ — i.e., a proper
  subgraph up to isomorphism (mutual containment forces equal vertex/edge
  counts, making the injection an isomorphism). `IsRamseySizeLinear` is
  isomorphism-invariant, so quantifying over isomorphic copies on `Fin q`
  loses nothing.
- **Interpretive step, documented:** the page's literal text says "all of its
  subgraphs" (no "proper"), which read literally is unsatisfiable ($G$ is a
  subgraph of itself, and cannot be both RSL and non-RSL) and would
  contradict the PROVED-affirmative status. The intended reading — proper
  subgraphs, i.e., *minimally* non-Ramsey-size-linear graphs — is confirmed
  by the recovered [Wi24] title "Infinitely many minimally Ramsey size-linear
  graphs" and by [EFRS93]. The input docstring already (correctly) says
  "proper subgraphs"; v2 records that the page omits the word. Not a defect.
- Types appropriate: vertex types `Fin p`/`Fin q`, the linearity constant
  `C : ℝ` with the count cast (`(n : ℝ) ≤ C * (H.edgeFinset.card : ℝ)`), all
  arithmetic in ℝ. No indexing conventions in play.
- Not vacuous or trivially false: witnesses are required to be non-RSL *and*
  minimally so; the degenerate candidates (empty graph, padded graphs,
  graphs with isolated vertices) all fail one clause, as computed above.

**A2. Lean semantics traps — pass.**

- ℕ subtraction: none.
- Division: none (the bound is multiplicative, `C * card`).
- `Finset.range`: not used. No off-by-one surface; `RamseyProp G H n` is
  upward monotone in `n` (restrict a colouring of `Fin (n+1)` to the first
  `n` vertices), so `∃ n ≤ C·m, RamseyProp G H n` is exactly
  "$R(G,H) \le C\cdot m$" for the minimal such $n$.
- Vacuous quantifiers / degenerate inputs (this batch's checklist): the empty
  graph ($q = 0$) vacuously satisfies `NoIsolatedVertices` with
  `edgeFinset.card = 0`, so `IsRamseySizeLinear` demands
  `∃ n ≤ 0, RamseyProp G H n` for it — and `RamseyProp G H 0` always holds,
  because the empty $H$ embeds into `Sᶜ` via the empty injection. So the
  degenerate case imposes no constraint and cannot falsify RSL for any $G$;
  it silently matches the source (where the $m = 0$ bound is vacuous). A
  single vertex ($q = 1$) correctly *fails* `NoIsolatedVertices`
  (`Adj v v = False`), matching "no isolated vertices". No junk values
  anywhere (`sInf`/`liminf`/`limsup`/`rpow`/default-valued binders all
  absent; problem-25 and problem-33 classes do not arise).
- "Infinitely many" filter/encoding: `∀ N, ∃ p ≥ N` — verified faithful in
  A1; no `Set.Infinite`/filter machinery needed.
- Strict vs non-strict: `C > 0` strict (matches $\ll$; harmless either way),
  `p ≥ N` non-strict (correct), `(n : ℝ) ≤ C * m` non-strict (correct for
  $O(\cdot)$).
- Constant quantifier order (problem-55 class): `∃ C` precedes `∀ q H`, so
  `C` is uniform over all $H$ and can depend only on `G` — exactly the
  Vinogradov $\ll$ of the source (implied constant depends on $G$). No
  parameter for `C` to absorb.
- The instance binder `[DecidableRel H.Adj]` inside the `∀` is semantically
  harmless: instances exist for every `H` (classically), and
  `edgeFinset.card` is instance-independent (`Fintype` is a subsingleton), so
  the quantified statement is equivalent to the instance-free one.
- Import reachability (problem-65 class): `edgeFinset` lives in
  `Mathlib.Combinatorics.SimpleGraph.Finite` (imported directly; verified in
  the pinned mathlib scratch clone), `ᶜ` comes from the complete Boolean
  algebra structure in `…SimpleGraph.Basic`. Moot in any case: the log shows
  this exact file building.

## E. Prior-review audit (`deepmind/ai-review/79.md`)

The prior review was written against the styled copy (its references to
`@[category …]`/`answer(True)`/namespace `Erdos79` match no text in the raw
file). Auditing its mathematics:

1. **Its "most critical issue" (§6) is wrong.** It claims the local
   definition "uses the classical *vertex* Ramsey number formulation" while
   "the standard definition … concerns the *size Ramsey number*
   $\hat r(G,H)$", declares the library's $\hat r$-based
   `SimpleGraph.IsRamseySizeLinear` "correct and the local definition …
   wrong", and grades the file **Incorrect** on that basis. The recovered
   source refutes this: the page *defines* Ramsey size linear as
   "$R(G,H)\ll m$", the `/latex/79` recovery reads "R(G,H) is O(m)", and the
   recovered page for the sibling problem 567 likewise uses $R(G,H)$. In
   "Ramsey size linear" (per [EFRS93]'s title and definition), *size* names
   the parameter $m = e(H)$ the classical Ramsey number is linear in — not
   the size Ramsey number $\hat r$. The two notions are genuinely different
   quantities, so following the prior review's recommendation would have
   replaced a faithful statement with a different (page-inconsistent) one.
   This is the recurring prior-review failure class of endorsing an encoding
   that contradicts the source (cf. 1005) — here with the aggravation that
   the *upstream library definition itself* deviates from the page it cites;
   the raw file under review is the artifact that got it right.
2. **Its padding analysis (§5) reaches the right verdict by the wrong
   argument.** It says vertex-padding "arguably doesn't affect the
   mathematical content, since any non-Ramsey-size-linear graph can't be
   trivially padded without changing its Ramsey properties." That reasoning
   is backwards: padding barely changes Ramsey properties
   ($R(G \sqcup \overline{K_t}, H) \le \max(R(G,H), |V|)$), so a padded
   non-RSL graph *stays* non-RSL. What actually closes the loophole is the
   problem's own minimality clause: the unpadded core is a non-RSL *proper
   subgraph* of the padded graph, so padded graphs fail clause (ii) (see
   A1). Conclusion right, derivation unsound.
3. **Citations (§2): correct.** [Er95] is indeed cited by the page and
   missing from the file; [EFRS93]/[Wi24] indeed lacked data. Fixed in v2
   (with the caveat that its "no volume number in the source" observation
   matches my recovery).
4. **Other correctness claims (§6) re-derived and confirmed:** the
   proper-subgraph encoding ("embeds but is not co-embeddable") is correct;
   the affirmative polarity matches Wigderson's result; `RamseyProp`'s
   complement-based colouring is a genuine edge partition of $K_n$.
5. **Missed by the prior review:** the "all of its subgraphs" vs "proper
   subgraphs" wording gap between page and docstring (it quotes the page
   *with* "their proper subgraphs", which is not what the page says — a
   small misquote that hid the interpretive step); any small-case
