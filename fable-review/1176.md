## Summary

The problem (OPEN; Erdős–Galvin–Hajnal): let $G$ be a graph with chromatic number
$\aleph_1$; is it true that there is a colouring of the edges with $\aleph_1$ many
colours such that, in any countable colouring of the vertices, there exists a vertex
colour containing all edge colours? The consistency of a "yes" answer was proved by
Hajnal and Komjáth. The Lean file defines a cardinal-valued colorability predicate
`CardColorable1176` and asserts: for every graph on a `Type`-0 vertex set that is *not*
countably colorable, there is a type `EC` of cardinality $\aleph_1$ and an edge
colouring `edgeColor : G.edgeSet → EC` such that for every map of the vertices into a
countable type there is a colour class containing, for each edge colour, an edge with
both endpoints in that class. The conclusion is a faithful (and upstream-matching)
encoding of the question's conclusion, but the hypothesis says only "chromatic number
$\ge \aleph_1$" where the source pins it *exactly* at $\aleph_1$ — the same defect this
pipeline found and fixed in problem 1068, and not a ZFC-equivalent reading. Fixed by
adding the `G.CardColorable1176 ℵ₁` upper-bound hypothesis.

## A. Semantic fidelity

**A1. Statement fidelity — one defect (fixed); conclusion passes (source-verified).**

- Recovered verbatim source statement (see Addendum): "Let $G$ be a graph with
  chromatic number $\aleph_1$. Is it true that there is a colouring of the edges with
  $\aleph_1$ many colours such that, in any countable colouring of the vertices, there
  exists a vertex colour containing all edge colours?" The module docstring (lines
  16–19) reproduces this verbatim.
- Independent back-translation of `erdos_problem_1176` (lines 31–42): "for every graph
  $G$ on a `Type`-0 vertex set with no proper colouring by at most $\aleph_0$ colours,
  there exist a type $EC$ with $\#EC = \aleph_1$ and a function
  $\mathrm{edgeColor} : E(G) \to EC$ such that for every countable type $VC$ and every
  function $\mathrm{vertexColor} : V \to VC$ there is $b \in VC$ with: every
  $ec \in EC$ is the colour of some edge both of whose endpoints have vertex-colour
  $b$."
- **[defect] Hypothesis weakened from "chromatic number ℵ₁" to "chromatic number
  ≥ ℵ₁"** (line 33). `¬G.CardColorable1176 ℵ₀` says only that $G$ is not properly
  colorable with countably many colours, i.e. $\chi(G) \ge \aleph_1$; it does not cap
  $\chi(G)$ at $\aleph_1$. The universal statement therefore ranges over a strictly
  larger class of graphs (e.g., under $\neg CH$-style configurations, graphs with
  $\chi = \aleph_2$), so the assertion is *stronger* than the question asked. The two
  readings are not known to be ZFC-equivalent: the conclusion does transfer upward from
  a subgraph $H \subseteq G$ with $\chi(H) = \aleph_1$ to $G$ (extend the edge
  colouring arbitrarily into the same colour set and restrict any countable vertex
  colouring of $G$ to $H$), but producing such an $H$ inside an arbitrary graph with
  $\chi \ge \aleph_2$ is a well-known open problem going back to Galvin. The
  first-pass session log confirms the error was a deliberate gloss, not a typo: its
  closing summary reads "chromatic number ℵ₁ (not colorable with ℵ₀ colors)". The
  recovered upstream formal-conjectures file uses exact equality
  (`G.chromaticCardinal = aleph 1`). This is the *identical* defect class found and
  fixed in `conjectures/1068.lean` (fable-review/1068.md, defect 2), whose fix pattern
  — add the ℵ₁-colorability upper bound as a second hypothesis — is reused here:
  `¬G.CardColorable1176 ℵ₀ → G.CardColorable1176 ℵ₁ → …` pins
  $\chi(G) = \aleph_1$ exactly (cardinals are totally ordered, so $\chi \le \aleph_1$
  and $\chi > \aleph_0$ force equality).
- Quantifier structure otherwise matches: edge colouring existential before the
  universal over vertex colourings; the colour class $b$ existential before the
  universal over edge colours ($\exists b, \forall ec$ — "a vertex colour containing
  *all* edge colours", not colour-by-colour classes). This agrees term-for-term with
  the recovered upstream statement (`∃ vc, ∀ ec, ∃ u v h, …`).
- "Colouring of the edges with ℵ₁ many colours": encoded as `#EC = ℵ₁` with an
  arbitrary (not necessarily surjective) function. Surjectivity — "actually using"
  all $\aleph_1$ colours — is forced by the conclusion itself: instantiating
  `VC := PUnit` with the constant vertex colouring makes the inner condition "every
  $ec$ is attained by some edge", so the encoding does not admit a degenerate
  small-range edge colouring. Matches the upstream encoding (`mk EColor = aleph 1`).
- "Countable colouring of the vertices": `Countable VC` with an arbitrary function
  `V → VC`. `Countable` in Mathlib means $\#VC \le \aleph_0$ (finite included), which
  is the standard set-theoretic reading of "countable colouring" (at most countably
  many classes; the colouring is *not* required to be proper — indeed no proper
  countable colouring exists under the hypothesis, and arbitrary partitions are the
  intent). Correct.
- Neither vacuous nor trivial: graphs with $\chi = \aleph_1$ exist on `Type`-0 vertex
  sets (e.g. suitable graphs on subtypes of ℝ; $\aleph_1 \le 2^{\aleph_0} = \#ℝ$ in
  ZFC), and `Type` contains types of cardinality exactly $\aleph_1$ (e.g.
  `(ℵ₁).out`), so the `∃ EC` is satisfiable; under the hypothesis the edge set has
  cardinality $\ge \aleph_1$ (a graph with countably many edges is countably
  colorable: isolated vertices form one class, the $\le \aleph_0$ covered vertices get
  distinct colours), so an edge colouring onto $\aleph_1$ colours exists. The
  statement is a substantive open question.
- Vertex type restricted to `Type` (universe 0) while `CardColorable1176` is
  universe-polymorphic. The upstream file quantifies over `Type*`. A universe-0
  restriction is this corpus's raw-file convention (identical in
  `conjectures/1068.lean`, kept by its review) and universe-0 already contains types
  of every relevant cardinality, but it is noted as [polish] below, not a defect.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction, no division, no `Finset.range`, no indexing anywhere.
- Vacuous-quantifier audit: if `VC` is empty and `V` nonempty, `vertexColor : V → VC`
  has no inhabitants and that instantiation is vacuously satisfied — harmless (the
  source's "countable colouring" presupposes at least one class; nonempty `VC` gives
  the real content). If `V` were empty the hypothesis `¬CardColorable1176 ℵ₀` is
  false (the empty graph is colorable), so no degenerate-graph instance arises.
- `∀ v ∈ (e.val : Sym2 V), vertexColor v = b`: `Sym2` membership for `s(u,v)` is
  exactly $\{u, v\}$, so this says both endpoints lie in class $b$ — matching the
  docstring's stated interpretation and the upstream's
  `c_vert u = vc ∧ c_vert v = vc`. (The type ascription on `e.val` is redundant but
  harmless.)
- "Infinitely many"/filter encodings: none needed. Cardinal comparisons (`≤ ℵ₀` via
  `Countable`, `= ℵ₁`, `≤ κ`) are the correct encodings of the informal notions.
- No `StrictMono`/`Monotone` or interval-endpoint issues.

**A3. Definitions — pass.**

- `SimpleGraph.CardColorable1176` (lines 10–11) matches its docstring: properly
  colorable with at most $\kappa$ colours, via `∃ α, #α ≤ κ ∧ Nonempty (G.Coloring α)`.
  `G.Coloring α` is Mathlib's *proper* colouring, which is the right notion for a
  chromatic-number hypothesis. Monotone in $\kappa$, as the exact-ℵ₁ two-hypothesis
  encoding requires. Degenerate inputs behave correctly (`κ = 0` forces `α` empty, so
  only edgeless-and-empty graphs qualify). No `sorry` in the definition.
- Identical (up to the name suffix) to `SimpleGraph.CardColorable` in
  `conjectures/1068.lean`; the suffix avoids a cross-file name clash in a joint build.
- No drift between what the def computes and how the theorem uses it.
