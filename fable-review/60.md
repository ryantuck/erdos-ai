## Summary

The problem (verbatim from the recovered page, **OPEN** banner): "Does every graph on
$n$ vertices with $>\mathrm{ex}(n;C_4)$ edges contain $\gg n^{1/2}$ many copies of
$C_4$?" — conjectured by Erdős and Simonovits, who could not even prove that at least 2
copies are guaranteed; He, Ma, and Yang [HeMaYa21] proved it when $n = q^2+q+1$ for
even $q$. The Lean input (`conjectures/60.lean:57-63`) asserts: there exist $c > 0$ and
$N_0$ such that for all $n \ge N_0$, every graph on `Fin n` with more than
`extremalNumber60 C₄ n` edges has `labeledC4Count ≥ c·n^{1/2}`. Read back
independently, this is a faithful direct assertion of the conjectured "yes" direction
of the open question (the raw-pipeline convention), with correct quantifier order (one
absolute constant $c$ outside all universals), sound helper definitions (checked on
degenerate and small inputs), and the standard interpretations of $\gg$ (Ω with
absolute constant) and "copies" (labeled, non-induced — both constant-factor immaterial
choices). I found no semantic defects. The nits are scholarship-level: the docstring
cites [Er90]/[Er93]/[765] with no bibliography at all, omits the page's He–Ma–Yang
remark, and records no status/provenance — all addressed in `conjectures-v2/60.lean`,
together with two page-confirmed variants. The input file is untouched.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Independent back-translation of lines 57–62: "there is a real $c > 0$ and a threshold
  $N_0$ such that for every $n \ge N_0$ and every simple graph $G$ on $n$ labeled
  vertices, if $G$ has strictly more edges than the C₄-extremal number for $n$, then
  the number of injective C₄-adjacency-preserving maps `Fin 4 → Fin n` is at least
  $c\sqrt{n}$." This matches the source question's "yes" direction term by term.
- $\gg n^{1/2}$ is correctly rendered as $\exists c > 0$, count $\ge c\,n^{1/2}$ for
  all sufficiently large $n$ — the standard Vinogradov/Ω reading with an absolute
  constant. The $N_0$ slack is moreover *equivalent* to the all-$n$ form here: any
  graph exceeding $\mathrm{ex}(n;C_4)$ edges is by definition not C₄-free, hence has
  ≥ 1 unlabeled = 8 labeled copies, so the finitely many $n < N_0$ are absorbed by
  shrinking $c$. No content drifts either way.
- "Copies" is counted labeled (injective homomorphisms from the 4-cycle): exactly
  8 labeled per unlabeled copy (the image 4-cycle determines the map up to
  $\mathrm{Aut}(C_4) = D_4$, order 8), a constant factor absorbed by $c$. Non-induced
  containment is the standard extremal-graph-theory convention for both
  $\mathrm{ex}(n;C_4)$ and copy counting. Both choices faithful.
- Strict inequality `>` on the edge count is correct and essential ("with
  $>\mathrm{ex}(n;C_4)$ edges"); graphs with exactly $\mathrm{ex}(n;C_4)$ edges can be
  C₄-free.
- Not vacuous/trivial: for every $n \ge 4$, $\mathrm{ex}(n;C_4) < \binom{n}{2}$ (K_n
  contains C₄), so the hypothesis is satisfiable at all large $n$; the uniform constant
  $c$ makes the assertion substantive. For $n \le 3$ every graph is C₄-free (no
  injective `Fin 4 → Fin n`), the extremal number equals the maximum edge count, and
  the hypothesis is unsatisfiable — benignly vacuous, and behind $N_0$ anyway.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere. The only `%` is `(i.val + 1) % m` in `cycleGraph60` — ℕ
  mod with $m = 4 > 0$, correct cyclic successor.
- Division: only `(1 : ℝ) / 2` (exact real division) — the exponent is genuinely 0.5.
- `(n : ℝ) ^ ((1 : ℝ) / 2)` is `Real.rpow` (real exponent), base $n \ge 0$: equals
  $\sqrt n$; at $n = 0$ it is 0 (exponent ≠ 0, so no `rpow 0 0 = 1` junk — batch
  checklist item checked).
- `Fin 4` addition in `f (i + 1)` wraps ($3 + 1 = 0$), giving exactly the four cyclic
  adjacencies $f_0f_1, f_1f_2, f_2f_3, f_3f_0$. Intended and correct.
- `sSup` junk values (batch checklist): `extremalNumber60 C₄ n`'s value set is
  nonempty (empty graph, 0 edges, C₄-free) and bounded above by
  `Fintype.card (Sym2 (Fin n))` (every edge set lives in that finite ambient type), so
  `Nat.sSup` is the genuine maximum for every $n$ — including $n \le 3$, where it
  correctly returns $\binom{n}{2}$. No junk value is reachable in this file's use.
  (`Set.ncard` on `edgeSet` is likewise honest: the set is finite.)
- Degenerate inputs (batch checklist): `labeledC4Count 0 G = 0` (the function type
  `Fin 4 → Fin 0` is empty); `extremalNumber60` degenerates only for an `H` contained
  in every graph (empty value set, `sSup ∅ = 0`) — impossible for H = C₄. No
  default-valued binders (`optParam`) anywhere; no `liminf`/`limsup`.
- No `∀ x < 0`-style vacuous bounded quantifiers; the one benign vacuity ($n \le 3$)
  matches the source's intent (see A1). `StrictMono`/interval issues: none arise.
- Constant quantifier order (problem-55 class): $c$ and $N_0$ are existential *outside*
  `∀ n, ∀ G` — the required order for an absolute implied constant; nothing for $c$ to
  absorb illegitimately.

**A3. Definitions — pass.**

- `cycleGraph60` (lines 25–28): for $m = 4$, adjacency $i \ne j \wedge (j = i+1 \bmod
  4 \vee i = j+1 \bmod 4)$ gives edges exactly $\{0,1\},\{1,2\},\{2,3\},\{3,0\}$;
  checked the diagonals: $(0,2)$ and $(1,3)$ are non-adjacent (e.g. $2 \ne 1 = (0+1)\%4$

- `extremalNumber60` (lines 35–37): `sSup` of achieved edge counts of H-free graphs =

   333–350 — which contains p. 335. The styled `deepmind/deepmind/60.lean:40-41`
   carries the wrong expansion to this day (out of scope to fix there; v2 of the raw
   file uses the corroborated entry with the conflict documented).
2. **Stale/incorrect Mathlib location claims.** At current Mathlib HEAD (355bc1e),
   `cycleGraph` lives in `CycleGraph.lean:29` and is defined by pattern matching
   (`⊥` for $n = 0$ **and** $n = 1$; `Adj a b := a - b = 1 ∨ b - a = 1` in `Fin`
   arithmetic for $n \ge 2$) — not in `Circulant.lean:62` as `circulantGraph {1}`, and
   the "returning ⊥ for n = 0" parenthetical is incomplete (also $n = 1$).
   `labelledCopyCount` is at `Copy.lean:509`, not 406 (drift). `extremalNumber` at
   `Extremal/Basic.lean:78` and the `(n) (H)` argument-order note are exactly right.
   The reuse *recommendations* all remain valid; only the supporting details aged.
3. **Vague `sSup` fragility mechanism (right conclusion).** "If the conditions above
   were not met (e.g., for a degenerate H), `sSup` could return a junk value" — the
   only failure mode is *nonemptiness* (an `H` contained in every graph gives
   `sSup ∅ = 0`); boundedness can never fail, since the value set is always contained
   in `{0, …, card (Sym2 (Fin n))}`. Unlike the 1005 audit's unsound boundedness
   argument, the concrete nonemptiness/boundedness claims it makes for H = C₄ are
   correct; only the counterfactual is imprecise.

   nowhere establishes that the threshold is *necessary* — it is: the all-$n$ form is
   false at $n = 4$ via $K_4 - e$ (exactly one C₄; 8 < 16 labeled copies — see B2).

5. Minor: its variant snippet uses `2 ∣ q` where `Even q` is the Mathlib idiom (v2 uses
