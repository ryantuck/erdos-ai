## Summary

The problem (OPEN on the source page): start from $K_n$ and repeatedly delete the three
edges of a uniformly random triangle until the graph is triangle-free; with $f(n)$ the
number of edges remaining, is it true that $\mathbb{E}f(n) \asymp n^{3/2}$ and that
$f(n) \ll n^{3/2}$ almost surely? A Bollobás–Erdős problem ([Bo98,p.231][Va99,3.61],
posed at the 1990 "Quo Vadis, Graph Theory?" conference); Grable [Gr97] proved
$\mathbb{P}(f(n) > n^{7/4+\varepsilon}) \to 0$ and Bohman–Frieze–Lubetzky [BFL15]
proved $f(n) = n^{3/2+o(1)}$ a.s., which resolves neither part. The Lean file declares
the process's two summary quantities — $\mathbb{E}[f(n)]$ and
$\mathbb{P}(f(n) \in P)$ — as placeholder constants and asserts the two parts as
separate theorems: $\exists c_1, c_2 > 0$ with $c_1 n^{3/2} \le \mathbb{E}[f(n)] \le
c_2 n^{3/2}$ eventually, and $\exists C > 0$ with
$\mathbb{P}(f(n) \le C n^{3/2}) \to 1$. Read back independently, both statements are
faithful renderings of the two-part question's "yes" direction (the corpus convention
for open yes/no questions); the defect is not in the statements but beneath them: the
placeholders are `def … := sorry`, i.e. data-level `sorry`s riding on `sorryAx`, and no
axiom ties either constant to an actual random process.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified), modulo the A3 defect.**

- Recovered verbatim source statement (see Addendum): "Construct a random graph on $n$
  vertices in the following way: begin with the complete graph $K_n$. At each stage,
  choose uniformly a random triangle in the graph and delete all the edges of this
  triangle. Repeat until the graph is triangle-free. Describe the typical parameters
  and structure of such a graph. In particular, if $f(n)$ is the number of edges
  remaining, then is it true that $\mathbb{E}f(n)\asymp n^{3/2}$ and that
  $f(n) \ll n^{3/2}$ almost surely?"
- The module docstring reproduces the process description and the "in particular"
  question essentially verbatim but silently drops the soft framing sentence "Describe
  the typical parameters and structure of such a graph. In particular, …" — the same
  benign narrowing as 1005's "Estimate $f(n)$" preamble; formalizing the specific
  question is correct scope. Restored to the v2 module docstring for the record.
- Independent back-translation of `erdos_problem_1155_expectation` (lines 60–65):
  "there are positive reals $c_1, c_2$ and a threshold $N_0$ with
  $c_1 n^{3/2} \le \mathbb{E}[f(n)] \le c_2 n^{3/2}$ for all $n \ge N_0$." This is
  exactly $\mathbb{E}f(n) \asymp n^{3/2}$ in its standard eventually-two-sided reading.
- Independent back-translation of `erdos_problem_1155_almost_sure` (lines 73–78):
  "there is $C > 0$ with $\mathbb{P}(f(n) \le C n^{3/2}) \to 1$." This is the standard
  w.h.p. reading of "$f(n) \ll n^{3/2}$ almost surely" for a sequence of finite
  probability spaces — and the page itself endorses the w.h.p. reading by glossing
  [BFL15]'s "almost surely" as "in other words, for every $\epsilon>0$,
  $\mathbb{P}(n^{3/2-\epsilon}<f(n)<n^{3/2+\epsilon})\to 1$".
- Splitting the single compound question ("is it true that X and that Y?") into two
  theorems asserting X and Y respectively is an exact encoding of the "yes" direction.
- Non-vacuity, mathematical: neither part follows from the known [BFL15] bound
  ($n^{3/2}\log n$ is $n^{3/2+o(1)}$ but beats every $C n^{3/2}$), so both statements
  are substantive open questions. Non-vacuity, formal: because the two quantities are
  unspecified constants (A3), the *formal* propositions are contingent on an arbitrary
  function — the file is a specification, not a self-contained statement. See A3.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere; all arithmetic after the casts happens in ℝ.
- `(n : ℝ) ^ ((3 : ℝ) / 2)` is real rpow with exact real exponent `1.5` (no ℕ-division
  flooring; `(3 : ℝ) / 2` is exact field division). At $n = 0$: $0^{3/2} = 0$ (rpow of
  positive exponent), harmless and in any case shielded by `∃ N₀`/`atTop`.
- No `Finset.range`; the threshold form `∃ N₀, ∀ n ≥ N₀` has no off-by-one exposure.
- No vacuous bounded quantifiers. The inner predicate
  `fun k => (k : ℝ) ≤ C * (n : ℝ) ^ ((3 : ℝ) / 2)` correctly captures the event
  $\{f(n) \le C n^{3/2}\}$ with $n$ bound by the outer lambda.
- Filter encodings: `Tendsto … atTop (nhds 1)` is the standard, correct encoding of
  "probability tending to 1"; `∃ N₀, ∀ n ≥ N₀` correctly encodes "for all sufficiently
  large $n$" (equivalent to `∀ᶠ n in atTop`).
- No `StrictMono`/`Monotone` or interval-endpoint issues arise.

**A3. Definitions — DEFECT.**

- `noncomputable def triangleRemovalExpectedEdges (n : ℕ) : ℝ := sorry` (line 48) and
  `noncomputable def triangleRemovalEdgeProb (n : ℕ) (P : ℕ → Prop) : ℝ := sorry`
  (line 52) are `sorry`s inside `def`s — the one thing the checklist forbids outside
  proof bodies, and this corpus's `sorry-in-definition` defect class (cf.
  fable-review/1123, 1137). A data-level `sorry` elaborates via `sorryAx : ∀ α, Bool →
  α`, an unsound placeholder axiom inhabiting *every* type (including `False`), so
  every downstream statement inherits dependence on it; the originating session's own
  build log shows the two extra "declaration uses `sorry`" warnings on lines 48/52.
  **[defect]**
- Beneath the `sorry` mechanics lies the substantive limitation (correctly identified
  by the prior review for the styled copy): the two constants carry no axioms tying
  them to any actual probability space, nor to each other, so the theorems are
  specifications rather than formal statements of the problem. Unlike 1137 (where
  `Nat.nth Nat.Prime` was a drop-in canonical fix), there is no cheap canonical
  replacement: a genuine construction needs the sequential random process. It *is*
  buildable in principle with Mathlib's `PMF` monad — well-founded recursion on the
  edge-set cardinality: if the triangle set of the current edge set is nonempty,
  `bind` a `PMF.uniformOfFinset` choice over its `attach` and recurse on the edge set
  minus the chosen triangle's three edges (strict card decrease), else `pure` the edge
  count; then $\mathbb{E} = (\sum' k, k \cdot p\,k).toReal$ and
  $\mathbb{P}(P) = (\sum' k, \text{if } P k \text{ then } p\,k \text{ else } 0).toReal$.
  That is a ~60-line construction whose termination/`decreasing_by` obligations and
  exact lemma names cannot be validated without a compiler; shipping it unverified
  would risk breaking the v2 batch build.
- **Fix applied (v2):** both defs demoted to `opaque` constants — the honest form of
  the same modeling compromise (an unspecified constant with *no* unsound axiom behind
  it), and exactly what the archived styled copy of this problem did. The
  specification-only status, the shared-underlying-process intent (the prior review's
  §6b suggestion), and the deferred `PMF` route are now documented in the docstrings.
  The defect is thereby resolved at the `sorryAx` level while the deeper
  specification-only limitation remains, documented rather than hidden.
- `ContainsTriangle`/`TriangleFree` (lines 35–40) match their docstrings and the
  source's termination condition, including degenerate cases (on `V` with fewer than 3
  vertices, `ContainsTriangle` is correctly false). No `sorry` in either. Note they
  are *never used* by the theorems — dead documentation-code; see C1.

**A4. Question form and answer polarity — pass (corpus convention).**

- The source is a yes/no question ("is it true that…?"), OPEN. This plain-Mathlib
  corpus has no `answer()` elaborator; its uniform convention (cf. 1153, 1154) is a
  direct assertion of the asked ("yes") direction with a `sorry` proof, which is

  of the question is answered "yes". Correct direction for an OPEN problem stated per
  this corpus's convention.
- No binders before the colon on either theorem (both are binder-free), so nothing is
  spuriously universally quantified.
