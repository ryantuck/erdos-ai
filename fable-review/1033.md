## Summary

The problem: let $h(n)$ be the largest value such that every graph on $n$ vertices with
more than $n^2/4$ edges contains a triangle whose vertices have degrees summing to at
least $h(n)$. Estimate $h(n)$ — in particular, **is it true** that
$h(n) \geq (2(\sqrt{3}-1) - o(1))n$? The page status is OPEN; Erdős–Laskar [ErLa85]
proved $2(\sqrt{3}-1)n \geq h(n) \geq (1+c)n$, and Fan [Fa88] improved the lower bound
to $\frac{21}{16}n$. The Lean statement (`deepmind/1033.lean`) encodes the question as
`answer(sorry) ↔ ∀ ε > 0, ∃ N₀, ∀ n ≥ N₀, ∀ G : SimpleGraph (Fin n),
G.edgeFinset.card > n^2/4 → ∃ u v w, Adj … ∧ (deg u + deg v + deg w : ℝ) ≥
(2(√3−1) − ε)n`. Read back independently, this is exactly the unfolding of
"$h(n) \geq (2(\sqrt{3}-1)-o(1))n$", with correct question form and polarity. The two
defects are non-semantic-content ones: (1) restyling silently dropped the raw file's
`open Classical` (and `noncomputable section`), so the styled statement almost certainly
fails to elaborate — `G.edgeFinset` and `G.degree` need `Fintype`/`DecidableRel`
instances that exist for a quantified `G` only under classical decidability or explicit
binders; (2) the `[Er93]` bibliography entry names the wrong paper.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "Let $h(n)$ be such that every
  graph on $n$ vertices with $>n^2/4$ many edges contains a triangle whose vertices have
  degrees summing to at least $h(n)$. Estimate $h(n)$. In particular, is it true
  that\[h(n)\geq (2(\sqrt{3}-1)-o(1))n?\]" The module docstring reproduces this
  essentially verbatim.
- Independent back-translation of lines 55–62: "for every $\varepsilon > 0$, eventually
  every $n$-vertex graph with more than $\lfloor n^2/4 \rfloor$ edges has a triangle of
  degree sum $\geq (2(\sqrt{3}-1)-\varepsilon)n$." Unfolding $h$: since the set of valid
  thresholds is downward closed, $h(n) \geq t$ iff every graph with $> n^2/4$ edges has a
  triangle with degree sum $\geq t$; and "$h(n) \geq (c - o(1))n$" iff for every
  $\varepsilon > 0$, eventually $h(n) \geq (c-\varepsilon)n$. The composition is exactly
  the Lean RHS. **Term-by-term faithful**; the soft "Estimate $h(n)$" preamble is
  correctly scoped out (only the "in particular" question is formalized), as in
  fable-review/1005.
- "Graph on $n$ vertices" ↔ `SimpleGraph (Fin n)`: correct (simple graphs, matching the
  Mantel-threshold context).
- Triangle encoding `G.Adj u v ∧ G.Adj v w ∧ G.Adj u w`: distinctness of $u,v,w$ is
  automatic from irreflexivity (`G.Adj x y → x ≠ y`), so this is precisely a triangle.
- Not vacuous: for each fixed $\varepsilon$, the hypothesis is satisfiable for all
  $n \geq 3$ (e.g. any graph with $> n^2/4$ edges exists and by Mantel contains a
  triangle), and small $n$ are absorbed by $N_0$; for small $\varepsilon$ the statement
  carries the full open content.

**A2. Lean semantics traps — pass.**

- `n ^ 2 / 4` is ℕ floor division; for an integer edge count $m$,
  $m > \lfloor n^2/4 \rfloor \iff m > n^2/4$ over ℚ (if $m > \lfloor x \rfloor$ then
  $m \geq \lfloor x \rfloor + 1 > x$; conversely $m > x \geq \lfloor x \rfloor$).
  Re-derived by hand: the floor division is exactly right for both parities of $n$.
- No ℕ subtraction anywhere; `Real.sqrt 3 - 1` and the threshold arithmetic live in ℝ.
  The degree sum is computed in ℕ and cast once, correctly placed
  (`(… + … + … : ℝ)`).
- No `Finset.range`, no interval endpoints, no `StrictMono`/`Monotone` issues.
- "For all sufficiently large" is encoded as `∃ N₀, ∀ n ≥ N₀` — standard and correct;
  `≥` is inclusive, harmless.
- No vacuous bounded quantifiers: the only degenerate cases ($n \leq 2$, where no graph
  has $> n^2/4$ edges) make the inner implication vacuously true for those $n$, which
  matches the informal reading (the bound is asymptotic anyway).

**A3. Definitions — pass (trivially).** No helper `def`/`abbrev`/`structure`; no `sorry`
outside the proof bodies.

**A4. Question form and answer polarity — pass.**

- The source is a yes/no question ("is it true that…?"), so `answer(sorry) ↔ P` is the
  required shape; `P` is the question as asked, so `True` would mean "yes". With the
  problem OPEN, `answer(sorry)` is correct. (The style review `reviews/1033.md` flagged
  the missing `answer()` wrapper on an earlier revision; the current `deepmind/1033.lean`
  already has it — the fix was applied and correctly.)
- No binders before the colon (line 55, `theorem erdos_1033 :` is binder-free), so the
  iff is not spuriously universally quantified.

**A5. Solution status — pass (source-verified).**

- Recovered page banner: **OPEN** (tooltip: "This is open, and cannot be resolved with a
  finite computation."), with the owner's standard disclaimer. `@[category research
  open]` and both docstrings agree. The partial results (Erdős–Laskar bounds, Fan's
  improvement) match the page's remarks paragraph exactly.

**[defect] Restyling drift: `open Classical` (and `noncomputable section`) dropped.**

- The raw first pass (`conjectures/1033.lean` line 7) had
  `open Classical SimpleGraph Finset` inside a `noncomputable section`. The styled file
  kept only `open SimpleGraph Finset`. But `G.edgeFinset` requires
  `[Fintype G.edgeSet]` and `G.degree` requires `[Fintype (G.neighborSet _)]`, and for a
  *universally quantified* `G : SimpleGraph (Fin n)` Mathlib provides these only from
  `DecidableRel G.Adj` — which is not derivable without either `Classical.propDecidable`
  (a **scoped**, low-priority instance, active only under `open Classical`/`open scoped
  Classical`) or an explicit `[DecidableRel G.Adj]` binder. The styled file has neither,
  so the theorem statement almost certainly fails to elaborate. Corpus siblings confirm
  the two conventions: `open … Classical` (1008, 1009, 1016, 1021, **1034** — the
  same-page-neighbor with the same statement shape) or explicit binders (1007, 1010,
  1012, 1017–1019). This borders the out-of-scope "compilation status" rule, but a
  statement that cannot elaborate asserts nothing, so it is treated as a Part A defect
  entering during restyling. **Fixed** by restoring `Classical` to the `open` line
  (smallest diff, restores the raw file's semantics, matches neighbor 1034); not
  compile-verified. `noncomputable section` is not needed back — it matters only for
  `def`s, and the file has none.

- Attribution in prose matches the references (Erdős–Laskar and Fan are credited with
  exactly the results the page credits them with).

**B2. Variants and completeness — pass; enrichment applied.**

- The problem is single-part; the "in particular" question is the formalizable core and
  is captured. The "Estimate $h(n)$" framing is soft (a Case-2 `h(n) = answer(sorry)`
  variant would require defining $h$ via `sSup` — new machinery; noted as optional, not
  a missing part).
- The page's remarks yield three worthwhile solved variants (optional enrichment, not
  missing parts): Erdős–Laskar lower ($h(n) \geq (1+c)n$), Erdős–Laskar upper
  ($2(\sqrt{3}-1)n \geq h(n)$), Fan's improvement ($h(n) \geq \frac{21}{16}n$). All
  three added as `erdos_1033.variants.*` (Addendum fix 4; not compile-verified). The
  upper bound is formalized in $\varepsilon$-asymptotic form because the literal all-$n$
  inequality is **false at small $n$**: $h(3) = 6 > 2(\sqrt{3}-1)\cdot 3 \approx 4.39$
  (the only 3-vertex graph with $> 9/4$ edges is $K_3$, degree sum 6) — same treatment
  as the 1004/EPS87 precedent, counterexample documented in the variant docstring.
  ($h(4) = 8 > 2(\sqrt 3 - 1)\cdot 4 \approx 5.86$ fails too: every 4-vertex graph with
  $\geq 5$ edges contains $K_4$ minus at most one edge, forcing a triangle of degree sum
  8.)

## E. Prior-review audit (`ai-review/1033.md`)

Accurate on the core semantics (its §6 table, the floor-division equivalence argument,
and the quantifier-order judgment all re-derive correctly), but four findings:

1. **Wrong claim about Mathlib semantics (the 1002 failure class), masking the real
   defect.** §1 states the `DecidableRel G.Adj` requirement "is resolved implicitly via
   classical logic (Mathlib provides `Classical.dec`)" and demotes the explicit-binder
   pattern to a consistency nicety. This is false for the file under review:
   `Classical.propDecidable` is a *scoped* instance, active only under `open Classical`,
   which the styled file dropped in restyling. Nothing else supplies
   `Fintype`/`DecidableRel` instances for a bound `G`, so the statement it certified
   as correct very likely does not elaborate. The review identified exactly the right
   area, then reasoned itself out of the defect with an incorrect semantics claim.
2. **Wrong bibliographic conjectures.** §2 guesses [ErLa85] is "On the degree of
   vertices in a maximal independent set, J. Combin. Theory Ser. B 39 (1985)" — wrong
   paper (actual: "A note on the size of a chordal subgraph", Congr. Numer. 1985,
   81–86, per the recovered `/latex/1033`); its Fan title guess "On triangle degree sum"
   is also wrong ("Degree sum for a triangle in a graph"). Both were flagged as
   unverified, and both were later corrected in `deepmind/1033.lean` — but a reviewer
   inventing plausible-looking citations is exactly how fabricated bibliography enters
   a corpus.
3. **Missed the [Er93] error while endorsing it.** §2's table marks [Er93] "✓ Page
   number matches" for "_On some of my favourite theorems_ (1993)". The page number is
   the tell it missed: p. 344 cannot lie in that paper (pp. 97–132); the key resolves to
   the Quaestiones Mathematicae paper (333–350). The checkmark endorsed an internally
   inconsistent reference.
4. **Correct elsewhere.** Its variant suggestions match the page remarks; "no additional
   references appear on the website beyond these three" is confirmed by the recovered
   page; the distinctness-via-looplessness observation for the triangle encoding checks
   out; the floor-division analysis is sound (re-derived in A2).

The style review `reviews/1033.md` correctly caught the missing `answer()` wrapper
(since fixed); its checklist did not cover the dropped `open Classical`.
