## Summary

The problem (erdosproblems.com/19, status **DECIDABLE** — "Resolved up to a finite
check" — $500 prize) is the **Erdős–Faber–Lovász conjecture**, phrased on the page
as a question: *"If $G$ is an edge-disjoint union of $n$ copies of $K_n$ then is
$\chi(G)=n$?"* Kang–Kelly–Kühn–Methuku–Osthus [KKKMO21] proved the answer is yes
for all sufficiently large $n$; Hindman [Hi81] for $n<10$. The Lean file
(`conjectures/19.lean:33-44`) asserts: for every `n ≥ 2`, finite `V`, graph `G` on
`V`, and family of `n` finsets each an `n`-clique of `G`, pairwise sharing at most
one vertex, with every edge of `G` inside some clique — `G.chromaticNumber = n`.
Read back independently, this is exactly the conjectured "yes" direction of the
question, with "edge-disjoint union of $n$ copies of $K_n$" encoded by the
standard (and correct) vertex-intersection-≤-1 formulation. I found **no semantic
defects** — only scholarship/polish nits (citation key `[KKKMO21]` used with no
bibliography, missing page-confirmed Erdős–Füredi variant, docstring silent on the
question form and on why `hn : 2 ≤ n` is load-bearing), all addressed in
`conjectures-v2/19.lean`.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "If $G$ is an edge-disjoint
  union of $n$ copies of $K_n$ then is $\chi(G)=n$?" The docstring (lines 24,
  26-31) renders it as an assertion and explains the encoding accurately.
- Independent back-translation of lines 33-44: "for all n ≥ 2 and every finite
  graph G equipped with n vertex sets, each an n-clique of G, pairwise
  intersecting in ≤ 1 vertex, whose cliques cover all edges of G, the chromatic
  number of G equals n." Term-by-term:
  - `hclique` + `IsNClique n` (= `IsClique` ∧ `card = n`) is exactly "each copy is
    a $K_n$ sitting inside $G$"; combined with `hcover` ("no extra edges"), $G$ is
    exactly the union of the copies (up to isolated vertices, next bullet).
  - `hpairwise` (≤ 1 shared vertex) is **equivalent to edge-disjointness given the
    copies are complete**: two $K_n$'s sharing vertices $u \ne v$ both contain the
    edge $uv$; conversely ≤ 1 shared vertex forbids any shared edge. This is the
    standard encoding and the docstring justifies it correctly (lines 29-30).
  - `hcover` is necessary (without it $G$ could be a supergraph with arbitrarily
    large $\chi$) and present.
- **Benign generalization identified:** `V` is not required to be covered by the
  cliques, so `G` may have isolated vertices outside the union. This is
  truth-preserving: clique `0` forces $\chi(G) \ge n$ (a $K_n$ subgraph), and
  isolated vertices never raise $\chi$ above a value that is already ≥ 1. Any
  informal instance embeds with `V` = union of copies, so formal ⟹ informal, and
  informal + the trivial isolated-vertex argument ⟹ formal. Not a defect;
  documented in v2.
- Distinctness of the $n$ copies is not assumed but is forced: equal cliques
  would share $n \ge 2$ vertices, violating `hpairwise`. Correct behavior.
- Not vacuous / not trivially false: the hypotheses are satisfiable (e.g. $n$
  disjoint copies of $K_n$ on `Fin n × Fin n`, where $\chi = n$; or any
  near-pencil), and the conclusion is a genuine conjecture, not implied
  degenerately.

**A2. Lean semantics traps — pass (each checked explicitly).**

- **ℕ subtraction / division / `Finset.range`:** none in the file.
- **Degenerate `n`:** this is the one live trap, and the file handles it. At
  `n = 0` (without `hn`) the clique family is empty, `hcover` forces `G`
  edgeless, and the conclusion `chromaticNumber = 0` is **false** for nonempty
  `V` (Mathlib gives χ = 1 for a nonempty edgeless graph). So a positivity
  hypothesis is *necessary*, not stylistic — see Part E for the prior review
  getting this wrong. `1 ≤ n` would suffice (at `n = 1`: one $K_1$, `G` edgeless,
  `V` nonempty via clique 0, χ = 1 = n even with extra isolated vertices);
  `2 ≤ n` additionally drops only that trivially-true case. Acceptable; v2
  documents the rationale.
- **Vacuous quantifiers:** `hpairwise` at `n = 1` ranges over no pairs — vacuous
  and harmless (single copy). No other bounded quantifiers.
- **`chromaticNumber` codomain:** `ℕ∞`; the equality `G.chromaticNumber = n`
  coerces `n`. With `V` a `Fintype` the chromatic number is finite, so the
  ENat equality is exactly the intended ℕ fact. Correct.
- **Strict vs non-strict / intervals / filters:** only `≤` comparisons, matching
  the source; no filter encodings needed ("sufficiently large n" appears only in
  the *status* prose, not in the statement, which is the full conjecture).

## E. Prior-review audit (`deepmind/ai-review/19.md`)

The prior review's overall verdict ("correct and complete") is right, but it
contains one unsound mathematical argument, one apparent fabrication, and one
misquote:

1. **Wrong edge-case analysis at `n = 0` (unsound argument, right conclusion).**
   §6 claims: "for n = 0, Fin 0 is empty (no cliques, G has no edges, χ(G) = 0 —
   trivially true but degenerate)" and calls `2 ≤ n` "a safe choice that avoids
   any edge-case subtlety without losing generality." Re-derived: at `n = 0`
   nothing ties `V` to the (empty) clique family, so take `V = Fin 1` — `hcover`
   forces `G` edgeless, and Mathlib's χ of a nonempty edgeless graph is **1, not
   0**; the `n = 0` instance is **false**, and the positivity hypothesis is
   *necessary*, not merely safe. The review implicitly assumed `V` empty. This
   is the recurring prior-review failure class (invent a benign reading of a
   degenerate case instead of checking it); here the file was protected by `hn`,
   so no defect results — but the argument would have waved through a broken
   `n = 0`-inclusive variant.
2. **Variant not on the page (apparent fabrication).** §3 lists as website
   content a fourth variant: "Minimum copies for excess chromatic number:
   Finding the smallest m_k such that m_k edge-disjoint copies of K_n have
   chromatic number ≥ n + k." The recovered page (edition 23 January 2026,
   accessed 2026-02-24) contains **no such variant** — its remarks contain
   exactly the [Er97d] intersection questions and the [Er93] Erdős–Füredi
   generalisation. Either drawn from an unverifiable earlier edition or
   invented; matches the known "claims about source content that isn't there"
   failure pattern (cf. 1001, inverted).
3. **Misquote of the problem's grammatical form.** §5 quotes the statement as
   the assertion "If G is an edge-disjoint union of n copies of K_n then
   χ(G) = n", dropping the page's interrogative "then **is** χ(G)=n?". No
   polarity consequence here, but form classification is exactly what A4 exists
   to check, and the review's "unambiguous / direct" reading skipped it.
4. **Omissions.** It does not mention that the page attributes the
   Erdős–Füredi proof (large $n$) to **[KKKMO24]** and the $n^{3/2}$ bound to
   **Horák–Tuza [HoTu90]** (consequence: the archived styled file
   `deepmind/deepmind/19.lean:73` credits the Füredi variant's proof to
   [KKKMO21] — the wrong paper); and it does not notice that the Füredi variant
   is false at $k = 0$ as the page states it (the styled file inherited exactly
   that unguarded `k`, i.e. a literally-false-at-`k = 0` statement — avoided
   here by v2's `1 ≤ k`).
5. **Verified correct:** its Mathlib-semantics claims (`IsNClique` unfolding,
   ENat-valued `chromaticNumber` with well-behaved coercion under `Fintype`),
   the necessity of `hcover`, the implied distinctness argument, the `n = 1`
   analysis, and its website summary (Boulder 1972 origin, Kahn's $(1+o(1))n$
   with the \$100 prize, Hindman's $n < 10$, the DECIDABLE/$500 status) all
   check out against the recovered page.

Nothing the prior review flagged went unfixed (it flagged nothing actionable for
