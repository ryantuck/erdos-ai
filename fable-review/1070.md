## Summary

The problem (verbatim from the recovered page): "Let $f(n)$ be maximal such that, given
any $n$ points in $\mathbb{R}^2$, there exist $f(n)$ points such that no two are
distance $1$ apart. Estimate $f(n)$. In particular, is it true that $f(n)\geq n/4$?"
Status **OPEN**. The Lean file encodes the "in particular" yes/no question as
`answer(sorry) ↔ ∀ n ≥ 1, ∀ f : Fin n → ℝ², ∃ S, |S| ≥ n/4 ∧ S independent`, plus a
solved Croft lower-bound variant ($0.22936n$) and a solved Moser-spindle upper-bound
variant. The question form, polarity, and open status are all correct, and the
independent-set encoding is sound. Two defects: (1) the configurations are arbitrary
functions `Fin n → ℝ²`, i.e. point *multisets* — the weighted strengthening of the
question asked, which is potentially a genuinely different question at the exact
threshold $1/4$ (fixed: `Function.Injective f` added, matching the corpus convention of
1066/101/604); (2) the upper-bound variant asserted "for all sufficiently large $n$
there is an $n$-point configuration with independence number $\le (2/7)n$", attributed
to the Moser spindle — but disjoint spindle unions achieve $\le (2/7)n$ **only when
$7 \mid n$** (for $7 \nmid n$ they give $2\lceil n/7\rceil > (2/7)n$, at every scale),
so the statement as written is true only via the much stronger 2023 result [MRVZ23]
(fixed: restated as the exact spindle bound $f(7m) \le 2m$, with the [MRVZ23]
$(1/4+o(1))n$ bound added as its own variant).

## A. Semantic fidelity

**A1. Statement fidelity — one defect (fixed); otherwise pass (source-verified).**

- Independent back-translation of the pre-fix `erdos_1070` RHS (lines 62–66): "for every
  $n \ge 1$ and every function from $n$ indices to the plane, some index set of
  real-cast cardinality $\ge n/4$ has all its pairs of distinct indices at distance
  $\ne 1$." Modulo the multiset issue below, this is exactly "every $n$-point
  configuration contains $\ge n/4$ points, no two at distance 1", i.e. $f(n) \ge n/4$.
  The soft "Estimate $f(n)$" preamble is correctly scoped out; the formalized question
  is the page's "in particular" question.
- **[defect] Missing distinctness.** The source's "given any $n$ points" means $n$
  (distinct) points; the corpus encodes this consistently (`deepmind/1066.lean:55`
  `Function.Injective f`; `deepmind/101.lean`, `deepmind/604.lean` use
  `Finset (EuclideanSpace ℝ (Fin 2))`, distinct by construction). The pre-fix statement
  quantified over *all* `f`, including non-injective ones — i.e. over point multisets.
  An independent index set in a multiset configuration is a *weighted* independent set
  (all copies of a point are mutually non-adjacent, since $\operatorname{dist}=0\ne 1$),
  so the pre-fix RHS asserts: every finite unit-distance graph $G$ with integer vertex
  weights $w$ has an independent set of weight $\ge w(V)/4$ — equivalently
  $\chi_f(G) \le 4$ for every finite unit-distance graph. That is a formally *stronger*
  statement than the question asked, and the strengthening is load-bearing here:
  duplication can strictly lower the independence ratio of a configuration below that of
  its support (e.g. a unit path $u{-}v{-}w$ with $v$ doubled has ratio $2/4 = 1/2 <
  2/3$), there is no perturbation argument transferring the distinct case to the
  multiset case (perturbing a duplicated point only *removes* unit distances, which
  weakens the graph in the wrong direction), and [MRVZ23]'s $\chi_f(\text{plane}) \ge 4$
  puts the weighted version exactly at the boundary — a single finite unit-distance
  graph with $\chi_f > 4$ would make the pre-fix RHS **false** while the page's question
  stays open (indeed [MRVZ23] *conjecture* its answer is yes). Under an
  `answer(sorry) ↔ P` encoding, $P$ must be the question as asked, not a stronger one.
  **Fixed:** `Function.Injective f` added to the main theorem (and, for consistency of
  what "$f(n)$" means across the file, to both bound variants — see A5/Addendum).
- Indexing: no sequence indexing arises; `Fin n` indexes an unordered configuration.
  `(S.card : ℝ) ≥ (n : ℝ) / 4` with integer card correctly means
  $|S| \ge \lceil n/4 \rceil$; comparison is done in ℝ after casts, as intended.
- Not vacuous: for $n \le 4$ the claim degenerates to "some single point exists"
  (true, needs $n \ge 1$ — hypothesis present); for large $n$ it is the substantive
  open question. The `∃ S` is never satisfied by the empty set once $n \ge 1$ (card
  $0 < n/4$ requires... note $0 \ge n/4$ fails for $n \ge 1$). Fine.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere.
- Division: `(n : ℝ) / 4`, `22936 / 100000`, `1 / 4` are all real-field divisions with
  nonzero literal denominators; no ℕ flooring (all divisions happen after casts to ℝ).
- No `Finset.range`; `Fin n` and `Finset (Fin n)` carry no off-by-one risk here.
- Vacuous quantifiers: `∀ i ∈ S, ∀ j ∈ S, i ≠ j → …` on a singleton or empty `S` is
  vacuously true — correct: singletons *are* independent sets.
- "For all sufficiently large" in the (new) asymptotic variant is encoded as
  `∃ N₀, ∀ n ≥ N₀` — standard and correct; `(1/4 + o(1))n` is correctly unfolded to
  "$\forall \varepsilon > 0$, eventually $\le (1/4+\varepsilon)n$".
- Strictness: `dist (f i) (f j) ≠ 1` is exactly "not at distance exactly 1"; the page's
  independence condition. Non-strict `≥` on the cardinality bound matches $f(n) \ge n/4$.

**A3. Definitions — pass (trivially).** No `def`/`abbrev`/`structure` in the file; no
`sorry` outside proof bodies.

**A4. Question form and answer polarity — pass.**

- The source is a yes/no question ("is it true that $f(n)\geq n/4$?"); the encoding
  `answer(sorry) ↔ P` with `P` the question as asked is the right shape, and the
  problem being OPEN (recovered banner, with tooltip "This is open, and cannot be
  resolved with a finite computation") makes `answer(sorry)` correct.
- Polarity by hand: RHS true ⟺ every (distinct-point, post-fix) configuration has an
  independent set of size $\ge n/4$ ⟺ $f(n) \ge n/4$ for all $n$ ⟺ the question's
  answer is "yes". Correct.
- No binders before the colon on the `answer()` theorem (line 82 post-fix:
  `theorem erdos_1070 : answer(sorry) ↔ …` is binder-free; all quantifiers sit inside
  the iff). The solved variants correctly take binders (direct assertions, Case 3).

**A5. Solution status — pass (source-verified), one attribution defect (fixed).**

- Page banner **OPEN**; owner's disclaimer present; `@[category research open]` on the
  main theorem agrees. Both bound variants are genuinely solved results and are tagged
  `research solved`. Consistent.
- **[defect] Moser-spindle variant asserted more than the spindle proves.** Pre-fix
  `erdos_1070.variants.upper_bound` claimed: $\exists N_0, \forall n \ge N_0$, some
  $n$-point configuration has independence number $\le (2/7)n$, docstring "(Moser
  spindle)". Arithmetic: disjoint far-apart spindle copies give, for $n = 7m + r$ with
  $1 \le r \le 6$, independence number exactly $2m + \alpha(\text{leftover}) \ge 2m+1 >
  (2/7)n = 2m + 2r/7$ (and any leftover $r \ge 4$ points contribute $\ge 2$ since the
  plane has no unit-distance $K_4$) — so the spindle yields $f(n) \le (2/7)n$ **only for
  $7 \mid n$**, and in general only $f(n) \le 2\lceil n/7 \rceil = (2/7)n + O(1)$; the
  deficit does *not* vanish for large $n$. The pre-fix statement is nonetheless *true* —
  but only because $f(n)/n \to c \le 1/4 < 2/7$ by [MRVZ23] (2023), a far stronger
  ingredient than its docstring claimed. (Cf. the page itself: "The Moser spindle shows
  $f(n)\leq \frac{2}{7}n$" — literally false at, e.g., $n = 1$, where $f(1) = 1 > 2/7$;
  like the 1004 EPS87 precedent, the honest formalization is the corrected exact
  statement.) **Fixed:** restated as the exact spindle content — for every $m \ge 1$
  there is an injective placement of $7m$ points with every independent set of size
  $\le 2m$ — and the true asymptotic statement added separately as
  `erdos_1070.variants.upper_bound_asymptotic` with the correct attribution [MRVZ23].

## E. Prior-review audit (`ai-review/1070.md`)

Substantially useful (its citation flags were real and got fixed), but three findings:

1. **Fabricated asymptotic excuse on the upper bound (§6).** "The `∃ N₀` quantifier
   correctly accounts for the fact that this only works for sufficiently large $n$ (you
   need $n$ to be a multiple of 7 **or large enough that rounding doesn't matter**)."
   The bolded clause is false: rounding *never* stops mattering. For every $n$ with
   $7 \nmid n$, at any scale, spindle unions give independence number
   $\ge 2\lfloor n/7\rfloor + 1 > (2/7)n$ (leftover points contribute $\ge 1$, and
   $\ge 2$ once $r \ge 4$, vs. an allowance of $2r/7 < 2$). The `∃ N₀` statement it
   blessed is true only via [MRVZ23] — a 2023 breakthrough, not the Moser spindle. This
   is the same failure class as the 1000 audit (invent a discrepancy-resolution and
   excuse it asymptotically) and it masked the real A5 defect.
2. **Unsound endorsement of the non-injective encoding (§5).** It correctly notices
   injectivity is absent, then argues this is "the correct choice" because coincident
   points "don't conflict, making the conjecture harder to prove and thus the stronger
   statement". For an *open question encoded as `answer(sorry) ↔ P`*, encoding a
   strictly stronger $P$ is precisely wrong — the iff must carry the question *as
   asked*, and here the strengthening (weighted/multiset version ⟺ $\chi_f \le 4$ for
   all finite unit-distance graphs) is plausibly inequivalent at the exact constant,
   sitting on the boundary of [MRVZ23]'s $\chi_f(\text{plane}) \ge 4$. Endorsing an
   encoding that its own reading shows to be stronger than the source is the 1005
   failure pattern. (Its per-configuration claim "the independence number can only be
   larger" is also not the relevant comparison — the issue is that the ∀ ranges over
   strictly more configurations, some with strictly smaller independence *ratio* than
   any distinct-point realization of the same support.)
3. **Minor factual slips.** `unitDistanceGraph` is at `deepmind/704.lean:57` (def line),
   not `:51`; `IsIndepSet` is not "defined at 750.lean:46" — `deepmind/750.lean` uses
   Mathlib's `SimpleGraph.IsIndepSet` (at lines 65/85/104), there is no local
   definition. Its §2 table ("[ACMVZ23]/[LaRo72] MISSING, [MRVZ23] lacks title")
   describes the raw `conjectures/1070.lean`, and those items were fixed in
   `deepmind/1070.lean` before this review — flagged items were fixed; nothing it
   flagged remains open except the [MRVZ23]-variant gap, which this review filled.

What it got right: the question-form/`answer(sorry)` call; the citation gaps (since
fixed); the observation that the $m_1$ density variant belongs to problem 232's
formalization rather than this file; the readability assessment.
