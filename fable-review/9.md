## Summary

The problem (erdosproblems.com/9, OPEN): *"Let A be the set of all odd integers ≥ 1 not
of the form p + 2^k + 2^l (where k, l ≥ 0 and p is prime). Is the upper density of A
positive?"* The Lean file defines `IsRepresentable n` (∃ p k l, p prime ∧
n = p + 2^k + 2^l), the set `erdos9Set` of odd non-representable naturals, a counting
function |S ∩ {0,…,N}| via `Set.ncard`, an ℝ-valued `upperDensity` as
limsup count/(N+1) over `atTop`, and asserts `upperDensity erdos9Set > 0`
(`conjectures/9.lean:41`). Read back independently, the Lean asserts exactly the "yes"
direction of the question, byte-for-byte the right-hand side of the upstream
formal-conjectures encoding `erdos_9 : answer(sorry) ↔ 0 < Erdos9A.upperDensity`
(recovered from the logs). Under this pipeline's convention for raw files (no `answer()`
elaborator available), direct assertion of the conjectured, unrefuted direction of an
OPEN question is acceptable (cf. `fable-review/3.md`, `7.md`). I found no semantic
defects — only polish-level nits and docstring enrichment opportunities.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (capture in
  `claude-session-logs/6b2a4748-6fb4-406b-b748-448ca9adb4e4.jsonl`, line 11 — the
  original session's Read of the then-extant `tidy/9.html`): "Let $A$ be the set of all
  odd integers $\geq 1$ not of the form $p+2^{k}+2^l$ (where $k,l\geq 0$ and $p$ is
  prime). Is the upper density of $A$ positive?"
- Independent back-translation of lines 13–42: "the limsup over N of
  |{n ≤ N : n odd, n ≥ 1, n ≠ p + 2^k + 2^l for all primes p and k, l ≥ 0}| / (N+1)
  is a positive real." This is the assertion that the upper density of A is positive —
  the question's "yes" direction.
- Quantifiers/types: `p k l : ℕ` with `Nat.Prime p` correctly renders "p prime, k, l ≥ 0"
  (ℕ makes k, l ≥ 0 automatic; 2^0 = 1 is allowed, as intended). "Odd integers ≥ 1" =
  odd naturals: ℕ is the right carrier; `1 ≤ n ∧ ¬Even n` is Odd n (the `1 ≤ n` is
  redundant — 0 is even — but mirrors the source's "≥ 1" harmlessly).
- The source explicitly asks about **upper** density, and the file formalizes upper
  density (limsup), not lower or natural density. Match.
- Not vacuous/trivially false: the smallest representable number is 2 + 1 + 1 = 4, so
  1, 3 ∈ A (nonempty; upstream proves these as test lemmas); positivity of the upper
  density is the genuine open question (Crocker/Pan's partial results fall short of
  positive density), not a degenerate truth or falsity.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere.
- Division: only `(count : ℝ) / (N + 1 : ℝ)` — field division with denominator ≥ 1,
  never zero; no ℕ flooring (the cast happens before dividing).
- No `Finset.range`; the counting window `Set.Iic N` = {0, …, N} is finite in ℕ, so
  `Set.ncard` is the true cardinality (no infinite-set junk value 0), and the
  denominator N + 1 = |{0, …, N}| is the exactly matching normalization. Against the
  textbook upper density limsup |A ∩ [1, N]|/N the ratios differ by O(1/N) (and 0 ∉
  erdos9Set anyway), so the limsups agree — no off-by-one.
- Filter encoding: `Filter.limsup … Filter.atTop` in ℝ. The sequence lies in [0, 1],
  so the set of eventual upper bounds is nonempty (contains 1) and bounded below by 0
  (no a < 0 can eventually dominate a nonnegative sequence), hence the ℝ `limsup`
  (`sInf` of eventual upper bounds) is the genuine finite limit superior — the standard
  and correct encoding of upper density. No junk-value hazard.
- No vacuous bounded quantifiers, no `StrictMono`/`Monotone`, no interval-endpoint
  issues.
