## Summary

The problem (verbatim from the recovered page, SOLVED banner, $250): "A set
of integers $A$ is Ramsey $r$-complete if, whenever $A$ is $r$-coloured, all
sufficiently large integers can be written as a monochromatic sum of elements
of $A$. Prove any non-trivial bounds about the growth rate of such an $A$ for
$r>2$." Solved by Conlon, Fox, and Pham [CFP21]: for every $r \ge 2$ there is
an $r$-Ramsey complete $A$ with $|A \cap \{1,\ldots,N\}| \ll r(\log N)^2$ for
all large $N$, and this is best possible — there exists $c > 0$ such that any
$A$ with $|A \cap \{1,\ldots,N\}| \le c\,r(\log N)^2$ for all large $N$ is
not $r$-Ramsey complete. The Lean (`conjectures/55.lean`) defines
`IsRamseyComplete A r` correctly (colourings of ℕ, monochromatic `Finset`
subset sums, all large `n` represented) and states both the upper and lower
bounds — but in both theorems the constant is existentially quantified
*inside* `∀ r : ℕ, 2 ≤ r → …`, so `C`/`c` may depend on `r`. That makes the
`r` factor in `C * r * (log N)^2` absorbable into the constant, and the pair
of theorems then pins only $\Theta_r((\log N)^2)$ per fixed $r$, not the
uniform $\Theta(r(\log N)^2)$ rate that the page (and the file's own
docstring) assert. One [defect]; everything else checks out.

## A. Semantic fidelity

**A1. Statement fidelity — one defect (constant quantifier order); otherwise pass (source-verified).**

- Independent back-translation of `erdos_problem_55_upper` (lines 34–42):
  "for every $r \ge 2$ there exist a set $A \subseteq \mathbb{N}$, Ramsey
  $r$-complete, and a constant $C > 0$ and threshold $N_0$ with
  $|A \cap [1,N]| \le C\,r(\log N)^2$ for all $N \ge N_0$." Back-translation
  of `erdos_problem_55_lower` (lines 47–55): "for every $r \ge 2$ there is a
  $c > 0$ such that any $A$ whose counting function is eventually
  $\le c\,r(\log N)^2$ is not $r$-Ramsey complete."
- **[defect] Constant quantifier order.** The page reads: "constructed for
  every $r\geq 2$ an $r$-Ramsey complete $A$ such that for all large $N$
  $\lvert A\cap \{1,\ldots,N\}\rvert \ll r(\log N)^2$" and "there exists
  some constant $c>0$ such that if $A\subset \mathbb{N}$ satisfies
  $\lvert A\cap\{1,\ldots,N\}\rvert \leq cr(\log N)^2$ for all large $N$
  then $A$ cannot be $r$-Ramsey complete" — in both, the constant is uniform
  and the $r$-dependence is carried explicitly by the $r$ factor ($r$ occurs
  free under the "there exists some constant"). The input's own docstring
  mirrors this ("there exists c > 0 such that if |A ∩ {1,...,N}| ≤
  c · r · (log N)² …" with `r` free after the existential). The Lean instead
  binds `∃ C`/`∃ c` under `∀ r`. With an $r$-dependent constant,
  $C(r)\cdot r$ is just another $r$-dependent constant: the formal statements
  are equivalent to per-$r$ bounds $\Theta_r((\log N)^2)$ and carry **no**
  information about the dependence on $r$ — the explicit `(r : ℝ)` factor in
  both bounds is decorative. Since the joint $r,N$ growth rate is exactly
  what [CFP21] resolved (and what "best possible" pairs), this is a semantic
  weakening of the docstring's and page's claim, not just a nit. **Fixed in
  v2** by hoisting `∃ C`/`∃ c` outside `∀ r` (the archived styled artifact
  `deepmind/deepmind/55.lean` had already made the identical change).
  Caveat: the CFP paper itself is unreachable offline, so the uniform
  reading rests on the page's phrasing and the corpus artifacts — noted in
  the confidence line.
- Original ask is "$r > 2$"; both theorems take `2 ≤ r`. Correct scope: the
  formalization encodes the *resolution*, and the page states CFP's result
  for every $r \ge 2$ (subsuming the Burr–Erdős $r=2$ case, Problem 54).
  Not a defect.
- "A set of integers" vs `Set ℕ`: the page's lower-bound remark itself
  quantifies over $A \subset \mathbb{N}$, and counting via
  $|A \cap \{1,\ldots,N\}|$ plus "all sufficiently large integers" as subset
  sums presuppose positive elements. `Set ℕ` is the faithful type (0 ∈ A
  would be harmless: it contributes nothing to sums and is outside
  `Icc 1 N`).
- "monochromatic sum of elements of $A$": the Lean requires
  `S : Finset ℕ`, `↑S ⊆ A`, `∃ c, ∀ x ∈ S, χ x = c`, `S.sum id = n` — a
  monochromatic *subset* sum, i.e. distinct summands, which is the standard
  Burr–Erdős definition of Ramsey completeness that the page's loose "sum of
  elements" abbreviates. Colouring domain: `χ : ℕ → Fin r` colours all of ℕ
  rather than only `A`; equivalent, since colourings of `A` extend to ℕ and
  restrict back, and only the colours on `S ⊆ A` matter.
- Not vacuous / not trivially false: the upper bound demands a genuinely
  sparse complete set (a nontrivial existence); the lower bound's hypothesis
  is satisfiable (any finite or sparse `A`) and its conclusion nontrivial.
  Degenerate satisfiers checked: `A = ∅` satisfies the lower bound's
  hypothesis and is indeed not Ramsey complete — consistent, not
  trivializing.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction; no division anywhere.
- `Finset.Icc 1 N` is exactly $\{1, \ldots, N\}$ — no off-by-one against the
  source's $|A \cap \{1,\ldots,N\}|$.
- `Real.log` junk values at small `N` (`log 0 = log 1 = 0`): in the upper
  bound the threshold `N₀` is existential, so the prover picks `N₀ ≥ 2`;
  in the lower bound the hypothesis's `N₀` is existential too, so requiring
  the bound only eventually matches "for all large $N$" exactly. At `N = 1`
  the bound would force `A ∩ {1} = ∅` — but no theorem forces `N₀ ≤ 1`.
  Harmless (degenerate-input check per this batch's warning: no junk value
  can falsify or trivialize either statement).
- Vacuous quantifiers: `∀ n ≥ N₀` with large `N₀` is the intended
  "sufficiently large"; `∃ c : Fin r, ∀ x ∈ S, χ x = c` is vacuously
  satisfiable for `S = ∅`, but `S = ∅` sums to 0 and so only ever represents
  `n = 0` — invisible for large `n`. For `r = 0` there is no
  `χ : ℕ → Fin 0`, so `IsRamseyComplete A 0` is vacuously true — unused
  (theorems take `r ≥ 2`), now documented in the v2 def docstring.
- "All sufficiently large" encoded as `∃ N₀, ∀ n ≥ N₀` — standard and
  correct; no filter machinery, no liminf/limsup (batch problem-33 class:
  n/a). No `StrictMono`/`Monotone` or open/closed interval issues. No
  default-valued binders / `optParam` (batch problem-25 class: n/a).
