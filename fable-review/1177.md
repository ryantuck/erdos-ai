## Summary

The problem (Erdős–Galvin–Hajnal, [Va99, 7.94], OPEN): for a finite 3-uniform
hypergraph $G$, let $F_G(\kappa)$ be the collection of 3-uniform hypergraphs with
chromatic number $\kappa$ not containing $G$. Three assertions: (1) if
$F_G(\aleph_1) \ne \emptyset$ then some $X \in F_G(\aleph_1)$ has cardinality at most
$2^{2^{\aleph_0}}$; (2) if $F_G(\aleph_1)$ and $F_H(\aleph_1)$ are both non-empty then
so is their intersection; (3) if $\kappa, \lambda$ are uncountable and
$F_G(\kappa) \ne \emptyset$ then $F_G(\lambda) \ne \emptyset$. The Lean file defines
proper colorings, a cardinal-valued "has chromatic number" predicate (min-attaining
characterization), and sub-hypergraph freeness, and states all three parts as direct
assertions (`erdos_problem_1177a/b/c`) with `sorry`. Read back independently, all
three Lean statements assert exactly the source's three conditionals; I found no
semantic defects, only polish-level nits (a missing bibliography entry for the cited
`[Va99]` key, redundant finiteness hypotheses, and an undocumented degenerate-case
convention in `IsFreeOf`).

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum) matches the module docstring
  (lines 10–25) essentially word for word, all three paragraphs; the only variance is
  the harmless rename $\lambda \to \mu$ in Part 3 (Lean's `λ` keyword), which the
  theorem docstring notes.
- Independent back-translation, Part 1 (lines 61–73): "for every finite 3-uniform $G$:
  if some 3-uniform hypergraph has chromatic number exactly $\aleph_1$ and is $G$-free,
  then one such exists whose vertex type has cardinality $\le 2^{2^{\aleph_0}}$." This
  is Part 1, reading "cardinality of $X$" as the number of vertices — the standard
  reading. `^` on `Cardinal` is right-associative, so
  `2 ^ 2 ^ aleph 0` parses as $2^{(2^{\aleph_0})}$, as required.
- Part 2 (lines 84–101): "for all finite 3-uniform $G, H$: if each of $F_G(\aleph_1)$,
  $F_H(\aleph_1)$ is non-empty, some $W$ has chromatic number $\aleph_1$ and is both
  $G$-free and $H$-free." Exactly "$F_G(\aleph_1) \cap F_H(\aleph_1) \ne \emptyset$"
  unfolded. The source introduces $H$ without restating "finite 3-uniform"; the Lean's
  `[Fintype VH]` + card-3 hypotheses are the only sensible reading (a problem about
  forbidden *finite* configurations).
- Part 3 (lines 112–124): "for all finite 3-uniform $G$ and cardinals
  $\kappa, \mu \ge \aleph_1$: $F_G(\kappa) \ne \emptyset \to F_G(\mu) \ne \emptyset$."
  Matches; "uncountable" ⟺ $\aleph_1 \le \kappa$ under choice (Mathlib's `Cardinal`
  theory is choice-based), and $\aleph_1$ is the successor cardinal of $\aleph_0$, so
  the encoding is exact, not merely sufficient.
- Quantifier structure: $G$ (and $H$, $\kappa$, $\mu$) universally quantified as
  theorem binders — correct for direct assertions ("Let $G$ be …"); the hypergraphs
  witnessing non-emptiness are existentials in hypothesis and conclusion. Since there
  is no `answer()`/iff wrapper, binders before the colon are correct here.
- Vertex types range over `Type` (universe 0), which realizes every relevant
  cardinality ($\aleph_1$, $2^{2^{\aleph_0}}$, all uncountable $\kappa$ in
  `Cardinal.{0}`), so no generality is lost against the source's set-sized hypergraphs.
- Not vacuous: for $G$ with at least one edge that is not a lone triple (e.g. two
  triples sharing two vertices), Erdős–Hajnal-style constructions make
  $F_G(\aleph_1) \ne \emptyset$ plausible, so the hypotheses are satisfiable and the
  parts are substantive conjectures. Degenerate $G$ (edgeless, or a single triple)
  make $F_G(\aleph_1)$ empty — via a *false hypothesis*, not a trivially true
  conclusion — which matches the source's intent (see A3 and Part E).

**A2. Lean semantics traps — pass.**

- No ℕ subtraction, no division, no `Finset.range`, no indexing of sequences anywhere
  in the file — the dominant trap classes are structurally absent.
- Cardinal exponentiation `2 ^ 2 ^ aleph 0`: right-associative, correct grouping;
  `aleph 0 = ℵ₀` and `aleph 1 = ℵ₁` in Mathlib's `Cardinal` namespace (`open Cardinal`
  line 4). `Cardinal` powers have no junk-value pitfalls at these arguments.
- Vacuous bounded quantifiers: `∀ e ∈ edges, …` with `edges = ∅` makes
  `IsProperColoring3` vacuously true — correct (a hypergraph with no edges is properly
  colored by anything); interaction with `HasChromaticNumber3` gives chromatic number
  1 for nonempty vertex sets, 0 for the empty one, both harmless since the theorems
  demand chromatic number $\aleph_1$.
- "Chromatic number $= \kappa$" encoding: `HasChromaticNumber3` (lines 37–39) says
  some color type of size $\le \kappa$ admits a proper coloring AND every admitting
  color type has size $\ge \kappa$. Together these force
  $\kappa = \min\{\#\alpha : \alpha \text{ admits a proper coloring}\}$, and the two
  conjuncts applied to each other show the min is *attained* at exactly $\kappa$. The
  set of admitting cardinalities is upward closed (post-compose with an injection,
  which preserves $c\,v \ne c\,w$) and non-empty (take $\alpha := V$, $c := \mathrm{id}$:
  proper, since card-3 edges contain two distinct vertices), so "least size of a color
  set" is well-defined and the definition is exactly "chromatic number equals
  $\kappa$". Requiring type-cardinality rather than "colors actually used" is
  equivalent: a coloring using $S \subseteq \alpha$ colors factors through a type of
  size $\#S$.
- Strictness/interval issues: `hκ : aleph 1 ≤ κ` non-strict is right — $\kappa =
  \aleph_1$ is an uncountable cardinal and must be included (it is the flagship case).

**A3. Definitions — pass, with a convention worth documenting (now documented).**

- `IsProperColoring3` (lines 30–31): matches its docstring and the standard
  no-monochromatic-edge notion; on card-3 edges `∃ v ∈ e, ∃ w ∈ e, c v ≠ c w`
  automatically gives $v \ne w$. Degenerate inputs behave as intended.
- `HasChromaticNumber3` (lines 37–39): matches its docstring (see A2 analysis).
  Behavior on degenerate inputs: empty $V$ forces $\kappa = 0$; edgeless non-empty $V$
  forces $\kappa = 1$ — both correct and both incompatible with $\aleph_1$, as they
  should be.
- `IsFreeOf` (lines 44–46): "no injective vertex map sending each edge of $G$ onto an
  edge of $H$" — the standard (non-induced) sub-hypergraph containment, negated. The
  set-image-equality formulation `↑e' = f '' ↑e` is equivalent to
  `e.map ⟨f, hf⟩ ∈ edgesH` (Finset-to-Set coercion is injective); the sibling
  `conjectures/593.lean` uses the latter form (`Hypergraph3.ContainsCopy`) for the
  same concept. **Degenerate-case convention:** for edgeless $G$, `IsFreeOf` reduces
  to "no injective $V_G \to V_H$ exists", so any $H$ with at least $|V_G|$ vertices
  *contains* the edgeless $G$ — the injectivity requirement covers isolated vertices.
  This makes $F_G(\aleph_1) = \emptyset$ for edgeless $G$ (uncountable chromatic
  number forces uncountably many vertices), rendering the parts vacuously true via a
  false hypothesis. That is consistent with the informal problem (which only cares
  about $G$ with edges), but the convention was undocumented — now noted in the v2
  docstring. Not a defect: no reading of the source is violated on any $G$ the
  problem is *about*.
- No `sorry` in any `def`; no drift between what the defs compute and what the
  theorems need (the same three predicates are used uniformly in hypothesis and
  conclusion in all three parts).

## E. Prior-review audit (`deepmind/ai-review/1177.md`)

Largely accurate — its correctness analysis of the three defs and three parts checks
out on re-derivation (the `^`-associativity claim, the `aleph 1 ≤ κ` ⟺ uncountable
claim, the min-max chromatic-number argument, and the edge-injectivity-from-
vertex-injectivity remark are all correct). Four findings:

1. **Inverted degenerate-case claim.** "The degenerate case where G has no edges is
   handled gracefully — every hypergraph is vacuously G-free, and the statements
   remain true." This is **backwards**: for `edgesG = ∅`, `IsFreeOf` is
   `¬∃ f, Injective f` (the edge condition is vacuous), so every $H$ with at least
   $|V_G|$ vertices — in particular every hypergraph of uncountable chromatic
   number — *contains* the edgeless $G$, and $F_G(\aleph_1)$ is **empty**, not
   all-encompassing. The conclusion ("statements remain true") survives, but by the
   opposite mechanism (false hypothesis, not vacuous freeness). Same failure family
   as the 1000/1005 audits: a fabricated justification that happens to land on the
   right verdict and would mask a real bug where the degenerate case matters.
2. **"Unavailable" data that was recoverable.** "The reference 'Va99' is not expanded
   to a full bibliographic entry on the website itself, so the shorthand is
   consistent with the source." True about the website (confirmed by the recovered
   `/latex/1177` fetch), but the full `[Va99]` entry was recoverable from sibling
   files in the very codebase it surveyed — the recurring claiming-unavailable
   pattern (cf. the 1001 audit). It also did not flag that the raw file's *used* key
   is never *defined* in the module docstring (B1 gap).
3. **Reuse survey misses its own example.** It states "The `IsFreeOf` notion
   (sub-hypergraph freeness) does not appear elsewhere in the codebase and could
   potentially be extracted" — yet problem 593, which it itself surveys two
   paragraphs earlier, defines `Hypergraph3.ContainsCopy`, the identical containment
   notion whose negation is `IsFreeOf` (verified in `conjectures/593.lean:48–50`).
4. **Legacy mismatches (no action).** Its theorem names (`erdos_1177`,
   `erdos_1177.variants.*`) belong to the styled `deepmind/deepmind/1177.lean`, not
   the raw file (`erdos_problem_1177a/b/c`); expected for a legacy review. Its
   website claims (status Open, `[Va99, 7.94]`, attribution) are all confirmed by the
   recovered page.

Nothing it flagged went unfixed (it flagged only naming suggestions, out of scope /
