## Summary

The problem ([Va99, 7.86], OPEN): *Is it consistent that ω₂ → (α)²₂ for every
α < ω₂?* — i.e., is there a model of ZFC in which, for every ordinal α below the second
uncountable ordinal, every 2-coloring of pairs of ordinals below ω₂ admits a
monochromatic set of order type α. The Lean file (`conjectures/1170.lean`) defines
`omega2 := (aleph 2).ord`, defines the balanced partition relation
`OrdinalPartition κ α` via strictly monotone embeddings of `{x // x < α}` into
`{x // x < κ}` with a monochromaticity condition on increasing pairs, and asserts
`∀ α < omega2, OrdinalPartition omega2 α` with a `sorry` proof. Read back
independently, `OrdinalPartition` is an exactly correct rendering of κ → (α)²₂, and the
theorem asserts the *property* whose consistency the problem asks about — a scope
decision the docstring documents explicitly ("This is a consistency question … We
formalize the property itself"), and the same design used by the archived styled
version. No semantic defects; the two defects are scholarship-class: the citation keys
[La82]/[FoHa03] are used but defined nowhere in the file, and the site's source
reference [Va99, 7.86] is missing entirely. Both fixed in `conjectures-v2/1170.lean`.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified), with a documented meta-level scope
decision.**

- Recovered verbatim source statement (see Addendum): "Is it consistent
  that\[\omega_2\to (\alpha)_2^2\]for every $\alpha <\omega_2$?" The theorem docstring
  (lines 25–29) reproduces this and the arrow-notation gloss faithfully.
- Independent back-translation of lines 40–43: "for every ordinal α less than ω₂, for
  every function f from ordered pairs of ordinals below ω₂ to Bool, there exist a color
  c and a strictly monotone map g from the ordinals below α to the ordinals below ω₂
  such that f(g i, g j) = c for all i < j." This is exactly the property
  ∀ α < ω₂ : ω₂ → (α)²₂.
- The **consistency wrapper is not (and cannot be) formalized**: the source asks
  Con(ZFC + P), a meta-theoretic statement about models of ZFC, which Lean's fixed
  foundation cannot express at the object level. The file formalizes P itself and says
  so explicitly (lines 31–32: "This is a consistency question … We formalize the
  property itself."). This matches the archived styled version
  (`deepmind/deepmind/1170.lean`, whose `answer(sorry) ↔` RHS is the same property P)
  and is the only reasonable scope; the gap is documented, so I rate this a design
  decision, not a defect. Note the one-directional relationship: *proving* the Lean
  statement would witness the affirmative answer (truth in the ambient universe gives a
  model), but *refuting* it would not by itself settle the consistency question. Now
  documented more fully in the v2 module docstring.
- Order-type encoding: a strictly monotone `g : {x // x < α} → {x // x < κ}` is an
  order isomorphism onto its image, so its image is a subset of order type exactly α;
  conversely any subset of order type α admits such an enumeration, and a homogeneous
  set of order type ≥ α restricts to one of type exactly α. The `∃ g, StrictMono g`
  encoding is therefore exactly equivalent to "there exists a monochromatic subset of
  order type α". Term-by-term exact, no translation residue.
- Not vacuous: for α ≥ 2 the statement genuinely constrains colorings (e.g. it fails
  for large α under CH — see A5 note), and the universal over all α < ω₂ makes the
  conjunction highly nontrivial; the degenerate α ≤ 1 instances are vacuously true in
  both the formal and informal readings (A2).

**A2. Lean semantics traps — pass.**

- No ℕ subtraction, no division, no `Finset.range`, no indexing shifts anywhere — the
  entire statement lives in `Ordinal` with `<` only.
- Subtype order: `i < j` on `{x : Ordinal // x < κ}` is `i.val < j.val` (the induced
  order), and `StrictMono` on these subtypes uses exactly that order — the intended
  well-order of type κ (respectively α). Correct.
- Coloring domain: `f` is a *total* function on ordered pairs (including diagonal and
  decreasing pairs), while the standard κ → (α)²₂ colors unordered 2-element subsets.
  Equivalence checked by hand: the homogeneity condition reads `f` only at (g i, g j)
  with i < j, hence only at increasing pairs (StrictMono gives g i < g j); every
  coloring of increasing pairs extends to a total function, so universally quantifying
  over total `f` is the same as universally quantifying over colorings of unordered
  pairs. No strengthening or weakening.
- Vacuous quantifiers at degenerate α: for α = 0 the domain `{x // x < 0}` is empty
  (g exists trivially, `StrictMono` and homogeneity vacuous); for α = 1 the
  homogeneity condition `i < j → …` has no instances. Both make ω₂ → (α)²₂ trivially
  true, which matches the informal convention (any singleton/empty set is homogeneous).
  No silent alteration.
- `∃ c : Bool` sits outside `∃ g` — "some color admits a homogeneous set" — the correct
  reading of the subscript 2; `Bool` correctly encodes 2 colors.
- `StrictMono` (not `Monotone`) is required and used — a merely monotone map could
  collapse the set and misrepresent the order type. Correct choice.
- Universe note: `Ordinal` is written without a universe ascription, so `omega2` and
  the theorem are universe-polymorphic; in every universe the statement reads the same
  way about that universe's ω₂. Harmless; sibling `conjectures/1172.lean` pins
  `Ordinal.{0}` only where cardinal-arithmetic hypotheses (CH/GCH) make it matter,
  which is not the case here.

- `OrdinalPartition` (lines 16–20) matches its docstring, including the "increasing

**A4. Question form and answer polarity — pass (corpus convention).**

- The source is a **yes/no question** ("Is it consistent that …?"), **open**. This raw
  corpus has no `answer()` elaborator (Mathlib-only imports); its uniform convention
  for open yes/no questions is a direct assertion of the asked ("yes") direction with a
  `sorry` proof (cf. fable-review/1150.md §A4, 1167.md §A4 and siblings 1141–1168).
  Lines 40–43 assert the property whose consistency is asked — the closest
  object-level rendering of the "yes" direction, and precisely the RHS the styled
  archive puts inside `answer(sorry) ↔`. Polarity verified by hand: proving the
  formalized property in Lean would witness a model in which it holds, answering the
  question "yes"; there is no polarity inversion.
- One nuance worth recording (review-level, hedged — not on the page, so not added to
  the artifact's docstring): the asserted property is, to reviewer knowledge, *known to
  fail under CH* (classically, CH implies ω₂ ↛ (ω₁+2)²₂, a result usually attributed
  to Hajnal — this is exactly why the problem is posed as a consistency question and
  why the partial results of Laver and Foreman–Hajnal are consistency results from
  large cardinals). Consequently the direct assertion is not merely open but provably
  unprovable in ZFC-style foundations (its `sorry` can never be closed); this is an
  inherent cost of the documented "formalize the property" design shared with the
  styled file, not a fixable encoding error. The v2 docstring documents the
  direct-assertion convention and meta-level gap without asserting the (unsourced) CH
  remark.
- No `answer()` in the file, so the binders-before-colon trap is N/A; for a direct
  assertion the leading `∀ α` binder (inside the colon here anyway) is the correct
  universal quantification.
