## Summary

The problem (SOLVED): for a meromorphic function $f$, let $n(r,a)$ count the number of
roots of $f(z) = a$ in the disc $|z| < r$; does there exist a meromorphic (or entire)
$f$ such that for every $a \neq b$,
$\limsup_{r\to\infty} n(r,a)/n(r,b) = \infty$? It is Problem 1.25 in Hayman's problem
book [Ha74], attributed to Erdős; Gol'dberg [Go78] and Toppila [To76] constructed entire
functions with the property. The Lean (`conjectures/1116.lean:28-33`) asserts directly:
there exists an entire ($\mathbb{C}$-differentiable) $f : \mathbb{C} \to \mathbb{C}$
such that for all $a \neq b$ and all $M, R \in \mathbb{R}$ there is $r > R$ with
$M \cdot n(r,b) < n(r,a)$, where $n$ is `rootCount` (distinct solutions in the open
disk, via `Set.ncard`). Read back independently, this is the affirmative answer to the
question as asked, in its strongest (entire) form, with a sound multiplicative encoding
of $\limsup = \infty$ that handles $n(r,b) = 0$ radii correctly. I found no
defect-class findings — only enrichment and documentation nits (missing [Ha74]
attribution and bibliography, an unsupported "independently", and the undocumented
multiplicity convention), all addressed in `conjectures-v2/1116.lean`.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified).**

- Recovered verbatim source statement (see Addendum): "For a meromorphic function $f$
  let $n(r,a)$ count the number of roots of $f(z)=a$ in the disc $\lvert z\rvert <r$.
  Does there exist a meromorphic (or entire) $f$ such that for every $a\neq b$
  $\limsup_{r\to \infty}\frac{n(r,a)}{n(r,b)}=\infty$?"
- Independent back-translation of lines 28–33: "there is an entire function $f$ such
  that for every ordered pair $a \neq b$ and every $M, R$, some $r > R$ has
  $M \cdot n(r,b) < n(r,a)$." Since $a$ and $b$ range over ordered pairs, the condition
  holds in *both* directions for each unordered pair — exactly what "for every
  $a \neq b$, $\limsup n(r,a)/n(r,b) = \infty$" demands (and simultaneously satisfiable
  precisely because these are limsups along interleaved sequences of radii, not
  limits).
- The multiplicative encoding is a faithful rendering of $\limsup_{r\to\infty} = \infty$
  for a ratio of counts: $\limsup = \infty$ iff $\forall M\,\forall R\,\exists r > R$
  with ratio $> M$, and $M \cdot n(r,b) < n(r,a)$ is that inequality cleared of
  denominators. At radii with $n(r,b) = 0$ it demands $n(r,a) > 0$ (for any $M \ge 0$;
  see A2 for $M < 0$), which matches the informal convention that a positive count over
  zero is $\infty$ while $0/0$ radii cannot serve as witnesses. Faithful.
- "Meromorphic (or entire)": the Lean formalizes the entire case
  (`Differentiable ℂ f`). Because the question is disjunctive and was answered YES with
  *entire* witnesses [Go78, To76], the entire existential is the true, strongest
  statement and settles the question as posed (entire ⟶ meromorphic). Correct scope;
  the omission of a separate meromorphic variant is not a missing part (see B2).
- Not vacuous/trivial: constant functions fail the statement — for constant $f$,
  `rootCount` is 0 for *every* $a$ (empty set, or infinite disk on which `ncard`
  returns 0), so $M \cdot 0 < 0$ is false; and any nonconstant witness must attain
  every complex value (if $a$ is omitted, $n(r,a) = 0$ for all $r$ and the pair
  $(a, \cdot)$ fails), so the statement genuinely encodes the hard construction, not a
  degenerate one.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction, no division anywhere in the statement: the encoding deliberately
  cleared the ratio to a multiplication, with casts `(rootCount … : ℝ)` placed so the
  arithmetic happens in ℝ. This is exactly the right way to avoid the ℕ-division and
  division-by-zero traps that a literal `n(r,a) / n(r,b)` encoding would create.
- `Set.ncard` on an infinite set returns 0 (junk value). Reachable only for constant
  $f$ at the value it takes (fiber = full disk): analyzed in A1, it only makes constant
  functions fail, which they must. For nonconstant entire $f$, fibers are discrete,
  hence finite in every bounded disk, so `ncard` is the true count. No trap fires.
- Open disk `‖z‖ < r` matches the source's $\lvert z\rvert < r$. `r > R` strict matches
  "arbitrarily large $r$". Negative or zero $r$ give the empty disk and count 0 —
  harmless, since the existential over $r$ simply avoids them.
- `∀ M : ℝ` includes $M < 0$. Contrary to the "trivially satisfied" gloss one might
  give (see E), for $M < 0$ the condition $M \cdot n(r,b) < n(r,a)$ is *not* vacuous at
  radii where $n(r,b) = 0 = n(r,a)$ (it reads $0 < 0$); but any $r$ with
  $n(r,b) > 0$ or $n(r,a) > 0$ satisfies it, so the $M < 0$ instances are strictly
  subsumed by $M \ge 0$ instances and add no spurious strength or weakness. Harmless.
- No `range`, no bounded quantifiers over ℕ, no `StrictMono`/`Monotone`, no
  liminf/limsup library encoding to mis-pick (the limsup is hand-rolled, correctly).
- Vacuous-quantifier audit (the 1115 failure mode): the universal over $(a, b, M, R)$
  is guarded only by `a ≠ b`, which is satisfiable everywhere; no guard can be
  unsatisfiable for a candidate witness, so no constant-function or empty-guard
  trivialization exists. Checked explicitly: constant functions fail (A1); the
  statement is not trivially provable.

**A3. Definitions — pass, one documentation nit.**

- `rootCount` matches its docstring and the source's $n(r,a)$ under the
  *distinct-roots* reading of "count the number of roots". No `sorry` in any def. Used
  consistently in the theorem.
- Nit [polish]: the traditional Nevanlinna counting function $n(r,a)$ counts roots
  *with multiplicity* ($\bar n(r,a)$ is the distinct count). The source page says only
  "count the number of roots" and does not specify; the literal reading is the distinct
  count, and the input's docstring flags `Set.ncard` but not the convention choice.
  These conventions yield genuinely different formal statements (neither obviously
  implies the other for ratio limsups), though the Gol'dberg/Toppila constructions are
  believed to satisfy both. Since the ambiguity is inherited from the source, this is
  documentation, not a defect: v2 documents the choice in both docstrings.
  (Formalizing the with-multiplicity version would need analytic-order machinery —
  e.g. `AnalyticAt.order` — not present in the file; deferred, see B2.)
- Degenerate inputs: `rootCount f 0 a = 0` (empty disk), `rootCount` of constant
  functions = 0 everywhere — both analyzed above, both harmless.

## E. Prior-review audit (`deepmind/ai-review/1116.md`)

The prior review's *logical* analysis is largely sound, but it contains one instance of
the corpus's recurring fabricated-bibliography failure and two smaller mathematical
slips:

1. **Hallucinated bibliographic titles (§2).** It asserts: "The website
   (erdosproblems.com/1116) lists three references: … **[Go78]** — Gol'dberg, A. A.,
   *On the deficiencies of meromorphic functions* (1978). **[To76]** — Toppila, S.,
   *On Nevanlinna's second theorem and deficient values* (1976)." The recovered
   `/latex/1116` bibliography gives **different titles**: Go78 is "Counting functions
   of sequences of a-points for entire functions" (*Sibirsk. Mat. Zh.*) and To76 is
   "On the counting function for the a-values of a meromorphic function" (*Ann. Acad.
   Sci. Fenn. Ser. A I Math.*). The invented titles are plausible-sounding
   Nevanlinna-theory phrases, i.e. classic hallucination, and they propagated into the
   styled file's first-generation docstring (later corrected in
   `deepmind/deepmind/1116.lean`, which now carries the `/latex`-recovered titles). The
   raw file under review here was *not* contaminated (it defines no bibliography), but
   the audit point stands: the prior review claimed website-verified citations it did
   not have. Same failure class as 1001's "data unavailable that is in fact
   recoverable", inverted: data asserted that was never on the page.
2. **"Great Picard" for Little Picard (§6.2).** "By the Great Picard Theorem, a
   non-constant entire function omits at most one value" — that statement is the
   *Little* (small) Picard theorem; Great Picard is the local statement at an essential
   singularity. The surrounding argument (the property forces the witness to attain
   every value; consistent with the constructions) is correct and was re-derived
   independently in A1.
3. **Negative-M gloss slightly false (§6, "Potential concerns" 3).** "The quantifier
   `∀ M : ℝ` includes negative M, for which the condition is trivially satisfied." Not
   quite: at radii where both counts are 0, $M \cdot 0 < 0$ fails even for $M < 0$, so
   the condition still forces a radius with a nonzero count — it is *subsumed by*
   the $M \ge 0$ instances, not trivial (this is exactly what makes constant functions
   fail for every $M$). The conclusion ("not a flaw") is right; the justification would
   mask a real degeneracy on a statement where the $n \equiv 0$ case mattered — the
   same invented-then-excused pattern flagged in the 1000 and 1005 audits.
4. **What it got right** (re-derived, confirmed): the multiplicative limsup encoding
   and its $n(r,b) = 0$ boundary behavior; `Differentiable ℂ` = entire; open disk
   matching; `ncard`-on-infinite-sets analysis for constant functions; the
   multiplicity-ambiguity observation (a genuine and the most substantive mathematical
   point about this formalization); the acceptability of the entire-only existential;
   the missing-[Ha74] flag (still unfixed in `conjectures/1116.lean` — now fixed
   in v2).
