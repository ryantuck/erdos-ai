## Summary

The problem (OPEN on the source page): let $A=\{1\leq a_1<a_2<\cdots\}$ and
$B=\{1\leq b_1<b_2<\cdots\}$ be sets of integers with $a_n/b_n\to 1$; if
$A+B$ contains all sufficiently large positive integers, is it true that
$\limsup 1_A\ast 1_B(n)=\infty$? — a conjecture of Erdős and Sárközy
[Va99, 1.17], a stronger form of Erdős #28 (the $A=B$ case). The Lean
(`conjectures/1145.lean:31-37`) states: for all infinite `A B : Set ℕ` with
`Nat.nth`-enumeration ratios tending to 1 and cofinite pointwise sumset
`A + B`, the ordered-pair representation function
`repFunction₂ A B n = ncard {(a,b) ∈ A×B | a+b = n}` is unbounded
(`∀ M, ∃ n, … ≥ M`). Read back independently, this is the asked ("yes")
direction of the question, in the raw corpus's standard direct-assertion
convention for open yes/no problems. Unboundedness is equivalent to
$\limsup = \infty$ for ℕ-valued sequences, and allowing $0 \in A \cup B$
(where the source displays positive integers) is both endorsed by the
site-linked upstream formalization and provably equivalent to the
positive-only reading via the shift $(A+1, B+1)$. The only genuine faults
are documentation-level: the docstring claims positivity the code does not
impose, and [Va99] is cited but never defined.

## A. Semantic fidelity

**A1. Statement fidelity — pass (source-verified), one docstring
inaccuracy deferred to C1.**

- Recovered verbatim source statement (see Addendum): "Let $A=\{1\leq
  a_1<a_2<\cdots\}$ and $B=\{1\leq b_1<b_2<\cdots\}$ be sets of integers
  with $a_n/b_n\to 1$. If $A+B$ contains all sufficiently large positive
  integers then is it true that $\limsup 1_A\ast 1_B(n)=\infty$?"
- Independent back-translation of lines 31–37: "for every pair of infinite
  subsets A, B of ℕ whose n-th elements have ratio tending to 1, if only
  finitely many naturals are outside A + B, then for every M some n has at
  least M representations n = a + b with a ∈ A, b ∈ B." This is the
  question's content, asserted in the asked direction.
- **Conclusion shape.** `∀ M : ℕ, ∃ n, repFunction₂ A B n ≥ M`
  (unboundedness) versus the source's $\limsup 1_A\ast 1_B(n)=\infty$
  (every level set infinite): these are *equivalent* for an ℕ-valued
  sequence. Unboundedness trivially follows from limsup = ∞; conversely, if
  some level set $\{n : r(n) \ge M_0\}$ were finite and nonempty with
  maximum attained value $V$, the level set at $V+1$ would be a subset of it
  yet empty, contradicting unboundedness — so unboundedness forces every
  nonempty level set to be infinite, i.e. limsup = ∞. The docstring's gloss
  "i.e., the representation function is unbounded" (line 27) is thus
  mathematically accurate. (The upstream compiled version uses
  `limsup … = (⊤ : ℕ∞)` directly; both encodings are correct.)
- **Membership of 0.** The source displays $A, B \subseteq \{1,2,\ldots\}$;
  the Lean quantifies over all `A B : Set ℕ`, so 0 may belong to either set
  — a *more general* universal statement. Three independent reasons this is
  acceptable rather than a fidelity defect: (i) the site-linked official
  formalization (google-deepmind/formal-conjectures
  `ErdosProblems/1145.lean`, recovered from the logs, "Formalised
  statement? Yes" on the page) deliberately formalizes the 0-inclusive
  version, with a formalization note recording that 0-membership "has been
  left purposely ambiguous" in the site's comment discussion (the problem
  was originally stated as $A+B=\mathbb{N}$, which *forces* small elements);
  (ii) the page's own necessity example ("$1_A\ast 1_B(n)=1$ for all $n$")
  requires $0 \in A \cap B$ to cover $n \in A \cup B$, so the site itself
  reads the convolution 0-inclusively; (iii) the two readings are provably
  equivalent: a positive instance is a 0-inclusive instance, and the shift
  $A' = A+1$, $B' = B+1$ carries any 0-inclusive instance to a positive one,
  preserving infinitude, the ratio limit ($({a_n+1})/({b_n+1}) \to 1$ since
  $a_n, b_n \to \infty$ and $a_n/b_n \to 1$), sumset cofiniteness
  ($A'+B' = (A+B)+2$), and the representation function up to a shift
  ($r_{A',B'}(n) = r_{A,B}(n-2)$ for $n \ge 2$, else 0). So neither
  direction of the question changes. The *docstring*, however, states
  "1 ≤ a₁" positivity that the code does not impose, with no note — see C1.
- Indexing: `Nat.nth` is 0-indexed, the source 1-indexed; the map
  $n \mapsto a_{n+1}$ identifies the two ratio sequences, and
  `Tendsto _ atTop` is invariant under the shift. Term-by-term there is
  nothing to reconcile beyond the limit — no finite-index data is used.
- Not vacuous / not trivial: the hypotheses are satisfiable ($A = B = \mathbb{N}$
  satisfies all three), the conclusion is not implied degenerately (the
  page's own example shows bounded representation functions coexist with
  cofinite sumsets once the ratio hypothesis is dropped), and the $A = B$
  specialization is the open Erdős #28 — a substantive open conjecture.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere.
- Division: the only division is real, in `hAsymp` (line 34). If $0 \in B$
  then `Nat.nth (· ∈ B) 0 = 0` and the $n=0$ term is $x/0 = 0$ by Lean's
  convention — a single term (for $n \ge 1$, `Nat.nth` strict monotonicity
  on infinite sets gives $b_n \ge n > 0$), invisible to `atTop`. Harmless,
  and identical to the upstream compiled version's behavior.
- No `Finset.range`; no off-by-one surface.
- No vacuous bounded quantifiers. `∀ M : ℕ, ∃ n, r n ≥ M` at $M = 0$ is
  trivially satisfiable, as it should be — the strength is at large $M$.
- Filter/cofiniteness encodings: `{n | n ∉ (A + B)}.Finite` (line 35) is
  exactly "all sufficiently large integers lie in A + B" (in ℕ, cofinite =
  eventually-in-atTop; the upstream uses `∀ᶠ n in atTop, n ∈ A + B`,
  equivalent). "limsup = ∞" as unboundedness: equivalence verified in A1.
  `A + B` is the pointwise sumset under `open Pointwise` — correct notion.
- `Set.ncard` junk-value check: the defining set of `repFunction₂` is
  *always finite* (it injects into $\{0,\dots,n\}$ via the first
  coordinate), so `ncard` is the true cardinality — the infinite-set-gives-0
  trap does not arise.
- No `StrictMono`/`Monotone` or interval-endpoint issues: the source's
  increasing enumeration is supplied canonically by `Nat.nth` on infinite
  sets.

**A3. Definitions — pass.**

- `repFunction₂` (lines 16–17) matches its docstring and the source's
  $1_A \ast 1_B$: it counts ordered pairs $(a,b) \in A \times B$ with
  $a+b=n$, which is $\sum_{a+b=n} 1_A(a) 1_B(b)$. Degenerate input $n=0$
  counts $(0,0)$ iff $0 \in A \cap B$ — consistent with the convolution.
  No `sorry` in any definition; the def is used consistently by the theorem.

**A4. Question form and answer polarity — pass (corpus convention).**

  the fable-review precedents there). In styled question form it would be

- Binder placement: with no `answer()`, the binders-before-colon rule is
