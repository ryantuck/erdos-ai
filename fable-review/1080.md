## Summary

The problem (erdosproblems.com/1080, [Er75][Er79g]): let $G$ be a bipartite graph on
$n$ vertices such that one part has $\lfloor n^{2/3}\rfloor$ vertices; is there a
constant $c>0$ such that if $G$ has at least $cn$ edges then $G$ must contain a $C_6$?
The answer is **no** (De Caen–Székely [DeSz92]); the page banner is **DISPROVED
(LEAN)**. The Lean file formalizes the disproof as a direct assertion: for every
$c > 0$ there exist $n$ and a bipartite $G$ on `Fin n` with one part of size exactly
$\lfloor n^{2/3}\rfloor$, at least $cn$ edges, and no $C_6$. This is the true direction
(acceptable raw style for a solved problem), and the graph-theoretic encodings
(`ContainsCycle6`, `numEdges`, proper-2-coloring bipartiteness) are individually
correct. However, as written the statement was **trivially true**: `n = 0` with the
empty graph satisfies every conjunct for every $c$ (part size $0 = \lfloor 0^{2/3}
\rfloor$, $0 \ge c\cdot 0$ edges, vacuously no $C_6$). The upstream artifact avoids
exactly this with a `[Nonempty V]` hypothesis. Fixed by adding `0 < n`.

## A. Semantic fidelity

**A1. Statement fidelity — one defect (fixed); otherwise pass (source-verified).**

- Recovered verbatim source statement: "Let $G$ be a bipartite graph on $n$ vertices
  such that one part has $\lfloor n^{2/3}\rfloor$ vertices. Is there a constant $c>0$
  such that if $G$ has at least $cn$ edges then $G$ must contain a $C_6$?"
- Independent back-translation of the pre-fix theorem: "for every real $c>0$ there are
  $n$ and a simple graph $G$ on `Fin n` admitting a proper 2-coloring whose color-0
  class has exactly $\lfloor n^{2/3}\rfloor$ elements, with $\ge cn$ edges and no
  6-cycle." That is precisely the negation of the source's universally quantified
  question body — the correct (true) direction for a problem solved in the negative.
- Total-vertex vs part-size bookkeeping is right: $G$ lives on `Fin n` ($n$ = total
  vertices) and the *part* has $\lfloor n^{2/3}\rfloor$ vertices, exactly as the
  problem statement (the remarks' $f(n,m)$ convention — parts of sizes $n$ and $m$,
  total $n+m$ — is a different bookkeeping and is not what the theorem encodes; no
  conflation occurs).
- **[defect] Degenerate witness (vacuous truth).** `∃ (n : ℕ) …` admitted `n = 0`:
  take $G = \bot$ on `Fin 0`; the coloring condition is vacuous and the color-0 class
  has cardinality $0$, while `Nat.floor ((0:ℝ) ^ ((2:ℝ)/3)) = 0` (`Real.rpow` with
  base 0 and nonzero exponent is 0), so the part-size equation holds; `numEdges = 0 ≥
  c * 0` holds because the bound is `≥`, not `>`; and `¬ContainsCycle6` is vacuous on
  an empty vertex type. So `⟨0, ⊥, …⟩` proved the whole theorem for every $c$ — the
  formalization carried none of the mathematical content. The recovered upstream
  artifact guards against exactly this with `[Nonempty V]` in its (equivalent,
  question-form) statement. **Fixed** by adding the conjunct `0 < n`
  (`conjectures/1080.lean:72`); not compile-verified. Post-fix the statement is
  substantive: for each $c$, a witness needs $\ge cn$ edges on a nonempty $C_6$-free
  bipartite graph, so as $c\to\infty$ witnesses are forced to be large and genuinely
  dense (small-$n$ cheap witnesses like a single edge on $n=2$ only cover $c \le 1/2$,
  which is inherent in the negation form and matches the upstream reading).
- Truth of the fixed statement: follows from De Caen–Székely's
  $f(n,\lfloor n^{2/3}\rfloor) \gg n^{58/57+o(1)}$ (their graphs avoid $C_4$ *and*
  $C_6$, hence a fortiori $C_6$), modulo routine padding with isolated vertices to hit
  the exact part size $\lfloor n^{2/3}\rfloor$ of the *total* vertex count — padding
  preserves bipartiteness, edge count, and $C_6$-freeness.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere. The only divisions are `(2 : ℝ) / 3` (exact real
  division) and none in ℕ.
- `Nat.floor ((n : ℝ) ^ ((2 : ℝ) / 3))` is real `rpow` then floor — exactly
  $\lfloor n^{2/3}\rfloor$; positive base for $n \ge 1$; the $n=0$ corner was the A1
  defect, now excluded from doing harm.
- "At least $cn$ edges" ⇒ `≥ c * n` — non-strict, correct.
- `ContainsCycle6` (lines 14–21): all $\binom{6}{2}=15$ pairwise-distinctness clauses
  are present and the 6 adjacency clauses trace a-b-c-d-e-f-a; this is "contains $C_6$
  as a (not necessarily induced) subgraph" — the correct notion, and equivalent to the
  upstream `walk.IsCycle ∧ walk.length = 6` encoding.
- `numEdges` (lines 26–29) filters ordered pairs with `p.1 < p.2 ∧ Adj`, counting each
  undirected edge exactly once via the linear order on `Fin n`; equals
  `G.edgeFinset.card`. Degenerate case `n = 0` gives 0, as it should.
- The `DecidableRel G.Adj` instance is introduced by an anonymous existential binder
  (line 70); local hypotheses of class type are picked up by instance resolution, and
  the original pipeline session's `lake build` of this exact pattern succeeded.
- No `Finset.range`, no `StrictMono`/`Monotone`, no filter encodings of "infinitely
  many" arise. (Note: the fixed statement is the plain negation `∀c ∃n`, matching the
  upstream negation, not an "arbitrarily large n" strengthening; see B2.)

**A3. Definitions — pass.**

- Both defs match their docstrings and behave correctly on degenerate inputs; no
  `sorry` inside any `def`. No drift between the defs and the theorem's use of them.
- `noncomputable` on `numEdges` is unnecessary in principle (decidable filter over a
  fintype) but harmless and compile-verified as-is in the original session; removal is
  compiler-dependent — deferred.

**A4. Question form and answer polarity — pass (raw-file convention).**

- The source is a yes/no question answered "no". This raw file uses direct-assertion
  form asserting the *negation* — per the run instructions, direct-assertion form for a
  solved problem is acceptable raw style **iff the polarity is the true direction**,
  which it is (verified by hand: the theorem body is the negation of "∃c>0 such that
  every such graph with ≥ cn edges contains a C₆", and the answer to that question is
  no). The upstream styled artifact uses `answer(False) ↔ ∃ c > 0, ∀ …` — logically the
  same commitment.
- `∀ (c : ℝ), 0 < c → …` after the colon is fine here (no `answer()` iff to
  mis-quantify).

**A5. Solution status — pass (source-verified; docstring now records it).**

- Page banner: **DISPROVED (LEAN)** — "This has been solved in the negative and the
  proof verified in Lean." The pre-fix docstring said only "The answer is no"; the
  Lean-verification status (and the upstream artifact's attribution "formalized in
  Lean by Alexeev using Aristotle", with proof at plby/lean-proofs) is now recorded in
  the docstring. Raw files carry no category attribute, so nothing else to reconcile.
