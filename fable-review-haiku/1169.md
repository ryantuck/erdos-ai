## Summary

The problem: Erdős and Hajnal ask whether ω₁² ↛ (ω₁², k)² holds for all finite k < ω. That is, does there exist a 2-coloring of pairs of ordinals below ω₁² such that no subset of order type ω₁² is monochromatic in color 0 and no subset of order type k is monochromatic in color 1? Hajnal proved this true under the Continuum Hypothesis; the problem is open in ZFC but consistent (its negation is also consistent). The Lean file defines `OrdinalPartitionPair` to encode α → (β, γ)² and states `erdos_1169` as a bare assertion that the negation holds for all k : ℕ. Read back independently: the definition is correct in form, but the theorem statement has two linked defects: (1) it quantifies over all ℕ including k ∈ {0, 1, 2} where the partition relation trivially holds, making the negation false for those cases; (2) it is encoded as a direct assertion rather than the yes/no question form `answer(sorry) ↔ P` required by the checklist for yes/no source questions.

## A. Semantic fidelity

**A1. Statement fidelity — source-verified, one quantifier-range defect.**

- Recovered verbatim source statement from page 1169_a.txt (erdosproblems.com/1169, edited 25 January 2026): "Is it true that, for all finite $k<\omega$, $\omega_1^2 \not\to (\omega_1^2, 3)^2$?" The formula displays k=3 specifically, but the prose frames it as a question about all finite k.
- Independent back-translation of the Lean: lines 43–45 state `∀ k : ℕ, ¬ OrdinalPartitionPair (omega1 ^ 2) (omega1 ^ 2) (↑k)`. This reads as "for all natural numbers k, the partition relation fails." The definition of `OrdinalPartitionPair` (lines 18–25) encodes α → (β, γ)² correctly: for every 2-coloring, either a β-homogeneous set (color 0) or γ-homogeneous set (color 1) exists, where homogeneity is captured via strictly monotone embeddings.
- Quantifier structure: source "for all finite k" matches Lean `∀ k : ℕ` in shape. However, **[defect]** the range is wrong: the source asks about *nontrivial* finite k (standard in partition calculus, k ≥ 3), while the Lean includes k ∈ {0, 1, 2} where the partition relation is *trivially true* (vacuous conditions), making ¬OrdinalPartitionPair provably *false* for those cases (see A2 analysis below).
- Types: `omega1 ^ 2` (exponentiation of ordinals) and `↑k` (ℕ to Ordinal coercion) are appropriate.
- Not vacuous as stated: The theorem is provably false for k=0,1,2, so the statement is not merely vacuous but *contradictory for those specific instances*. This is the defect.

**A2. Lean semantics traps — source-identified issue documented below.**

- No ℕ subtraction.
- Division: `OrdinalPartitionPair` uses no division.
- Vacuous quantifiers: **Critical issue here.** For k=0, the type `{x : Ordinal // x < (↑0 : Ordinal)}` is empty (ordinals below 0 do not exist). The two disjuncts of `OrdinalPartitionPair` then read:
  - (1) ∃ g : {x < β} → {x < ω₁²}, StrictMono g ∧ [condition on g's image] — the existence is possible (strictly monotone function from a nonempty set into ω₁²).
  - (2) ∃ g : {x < 0} → {x < ω₁²}, StrictMono g ∧ [monochromaticity of empty function] — the monochromaticity condition is *vacuously true* (no pairs i < j in the empty type).
  
  Thus at least the second disjunct holds trivially, so `OrdinalPartitionPair(ω₁², ω₁², 0)` is **true**, and `¬OrdinalPartitionPair(ω₁², ω₁², 0)` is **false**.

  For k=1, the type `{x < 1}` is a singleton {0}. The monochromaticity conditions `∀ i j : {x < 1}, i < j → f(g i)(g j) = ...` are vacuously true (no pairs i < j exist in a singleton). Again, both disjuncts hold trivially, `OrdinalPartitionPair(ω₁², ω₁², 1)` is true, and the negation is false.

  For k=2, any 2-coloring f over {0,1} ⊂ ω₁² must have both colors represented somewhere (pigeonhole on the pair (0,1)). Either all edges are color 0 (first disjunct satisfied by the identity embedding) or there exist a < b with f(a,b) ≠ 0, giving a color-1 monochromatic pair (second disjunct satisfied by that pair). The negation is false.

  **The theorem statement ∀ k : ℕ, ¬ OrdinalPartitionPair (omega1 ^ 2) (omega1 ^ 2) (↑k) is provably false in ZFC.**

- `StrictMono` vs `Monotone`: correctly uses strict monotonicity for embeddings.
