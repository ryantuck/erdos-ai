## Summary

Problem 1117 asks: given an entire (holomorphic) non-monomial function f, let ν(r) count the points on the circle |z| = r where f achieves its maximum modulus. Is it possible for liminf_{r→∞} ν(r) = ∞? The problem is open; the analogous limsup question was answered affirmatively by Herzog–Piranian in 1968. The Lean file defines the supporting notions (`IsMonomial`, `maxModulus`, `nu`), all sound. The one semantic defect: the problem asks a yes/no question, so the statement should have the form `answer(sorry) ↔ P`, but instead it is a bare assertion `∃ f, P`. This is a defect-class finding (matching problem 1005's A4 issue).

## A. Semantic fidelity

**A1. Statement fidelity — DEFECT (deferred to A4; question form).** 

- Independent back-translation of lines 42–44: "There exists an entire non-monomial function f such that for every N, there exists R such that for all r ≥ R, ν(r) ≥ N." Unpacked: this asserts the *existence* of such a function. The statement and semantics are mathematically sound as written.
- Quantifier structure: existential over functions, universally quantified N, existentially quantified R. The order is correct and the meaning is transparent.
- Types: ℂ → ℂ for the function; ℝ for radii; ℕ for ν(r) and N; all appropriate.
- Indexing: not applicable; the statement involves real-valued radii, not sequences.
- Vacuousness: the statement is not vacuous — a general entire function (e.g., e^z) does *not* satisfy the property, so the existence claim is substantive.

**A2. Lean semantics traps — pass.**

- No ℕ subtraction anywhere.
- Division: `sSup` is used on a bounded set of reals; harmless. The `(maxModulus f r)` construction involves no division-by-zero.
- No `Finset.range` off-by-one issues (no ranges used).
- Vacuous quantifiers: none arise problematically.
- Filter encoding: the statement uses explicit quantifiers (∀ N, ∃ R, ∀ r) which is the standard ε-δ encoding of "liminf = ∞", equivalent to ∀ ε > 0 eventually P(ε). This is correct.
- No `StrictMono`/`Monotone` confusion.

**A3. Definitions — pass.**

- `IsMonomial` (lines 12–14): correctly captures f(z) = c·z^n for c ∈ ℂ, n ∈ ℕ. Includes the zero function (c = 0), which is correct — the problem excludes monomials specifically to avoid the trivial case where f(z) = c·r^n is constant on |z| = r.
- `maxModulus` (lines 18–19): uses `sSup` on the nonempty set {‖f(z)‖ : ‖z‖ = r}. For r > 0, the circle is compact, so the set is compact nonempty and `sSup` yields the maximum; for r = 0, the set is {‖f(0)‖}, a singleton; for r < 0, the circle is empty and `sSup ∅ = 0` (or ⊥ in the conditional lattice), which is a degenerate case not relevant in the theorem statement (∀ r sufficiently large, R ≤ r).
- `nu` (lines 23–24): uses `Set.ncard`, which returns 0 for infinite sets. For an entire non-monomial function, the maximum-modulus set on any circle is always finite (a classical result in complex analysis), so `ncard` coincides with cardinality. This implicit assumption is acceptable for a conjecture but should be noted.
- All definitions are used consistently; no `sorry` appears in any definition.

**A4. Question form and answer polarity — DEFECT.**

- The source problem, as stated in the docstring (lines 29–30): "Is it possible for liminf_{r→∞} ν(r) = ∞?" is a **yes/no question**.
- Per FABLE_REVIEW.md A4 and the corpus convention (seen in `deepmind/657.lean`, `deepmind/1005.lean`, `deepmind/1053.lean`, etc.), such questions must be encoded as `answer(sorry) ↔ P`, where P is the proposition (here, the existence claim), and `answer(sorry)` leaves the answer open.
- The current formalization (lines 42–44) is a bare assertion `∃ f, P`, not wrapped in `answer(…) ↔`. **[defect]** — This is the same pattern as problem 1005 (pre-fix), where the reviewer noted: "the source asks a yes/no question while `erdos_1005` was encoded as a direct assertion (no `answer(sorry) ↔` wrapper), contrary to the checklist's A4 and this corpus's uniform convention."
- Polarity check (post-fix): if `answer(True)` and the RHS is true, the answer is "yes, such a function exists", which matches the problem's question. If `answer(False)` and the RHS is false, the answer is "no, no such function exists". With the problem open, `answer(sorry)` is appropriate.
- No binders before the colon (line 42: `theorem erdos_problem_1117 :` is binder-free).
