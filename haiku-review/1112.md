# Haiku Review: Erdős Problem 1112

**Verdict:** NEEDS REVISION
**Confidence:** high — the problem statement and known results were verified against the module docstring, the prior review's recovered source material, the erdosproblems metadata mirror (dated 2026-07-25), and standard mathematical references on lacunary sequences and sumsets.

## Summary

Erdős Problem 1112 concerns the existence of a finite threshold r_k(d₁, d₂) such that for any lacunary sequence B with ratio ≥ r_k, there exists a gap-bounded sequence A with gaps in [d₁, d₂] whose k-fold sumset avoids B. For k=3, d₁=2, d₂=3, the answer is known to be "no finite threshold exists" (Bollobás–Hegyvári–Jin); for k ≥ 3 generally, the question remains open. The Lean statement correctly encodes the mathematical objects (lacunary sequences, gap-bounded sequences, k-fold sumsets) and the negation predicate (intersection always occurs), but **makes a universal assertion ("for all k ≥ 3 and all d₁ < d₂") that claims more than is known**. The theorem should either narrow its scope to known/resolved parameter ranges or be reformulated as a conjecture about a specific open subcase. Additionally, the custom `kFoldSumset` definition duplicates Mathlib's pointwise scalar multiplication on sets (`n • S`), and several important solved variants (k=2 results, r₃(2,3) non-existence) are absent.

## A. Semantic fidelity

**A1. Statement fidelity — DEFECT: overstrong universal quantification**

- **Back-translation (lines 35–43):** The theorem asserts: for any natural numbers d₁, d₂, k, r with 1 ≤ d₁ < d₂ and 3 ≤ k, there exists a strictly monotone sequence B of positive integers with lacunary ratio r (B(i+1) ≥ r·B(i)) such that for every strictly monotone positive-integer sequence A with gap constraints d₁ ≤ A(i+1)−A(i) ≤ d₂, there exists an integer n belonging to both the k-fold sumset kA and the range of B.
  
- **Comparison to problem statement:** The English problem asks about the existence of r_k(d₁, d₂)—a single threshold that might or might not exist—and notes that "The general question of existence of r_k(d₁, d₂) for k ≥ 3 remains open." The formalization interprets this as asserting that r_k is *guaranteed NOT to exist* for all k ≥ 3 and all valid (d₁, d₂). This is too strong.
  
- **Known vs. open:** The theorem's universal claim is not fully justified:
  - *Known fact (Bollobás–Hegyvári–Jin):* r₃(2,3) does not exist. The theorem's statement IS TRUE for this parameter triple.
  - *Partially known (Erdős–Graham, Chen):* r₂(2,3) = 2 exists; r₂(a,b) ≤ 2 for a < b, b ≠ 2a; further bounds on r₂. These concern k=2, outside the theorem's k ≥ 3 scope.
  - *Open:* The existence of r_k(d₁, d₂) for most other (k ≥ 3, d₁, d₂) triples—in particular, whether there exist *any* (d₁, d₂) for which r_k exists when k ≥ 3.
  
- **The defect:** The theorem claims ∀ d₁ d₂ k ≥ 3 [property], but property is only known/resolved for isolated points (e.g., (3,2,3)) and conjectured/open for the rest. A correct formalization should either: (i) restrict to known cases, (ii) formalize the existence question ("does there exist any (d₁, d₂) for which r_k(d₁, d₂) exists?"), or (iii) acknowledge the claim as an open conjecture. The current form presents an unresolved question as a theorem.

**A2. Lean semantics traps — pass**

- **Natural number subtraction:** A(i+1) − A(i) on ℕ is well-defined because StrictMono A ensures A(i+1) > A(i). ✓
- **Division:** No division occurs in the statement.
- **Lacunary condition:** r · B(i) ≤ B(i+1) correctly models b_{i+1} ≥ r · b_i. ✓
- **StrictMono vs. Monotone:** Correctly uses `StrictMono` for both A and B. ✓
- **k-fold sumset encoding:** No off-by-one or encoding ambiguity in the recursive `kFoldSumset` definition.

**A3. Definitions — pass with one note**

- **kFoldSumset (lines 8–10):** Correctly defined recursively: 0S = {0}, (k+1)S = {a + b | a ∈ S, b ∈ kS}. Matches docstring exactly. No `sorry` inside the definition. ✓
- **Degenerate cases:** The definition correctly handles edge cases: `kFoldSumset 0 S = {0}` and nested applications.
- **Note:** This definition duplicates Mathlib's existing `n • S` (nsmul of a set in an additive monoid), available via `Mathlib.Algebra.Group.Pointwise.Set`. See Part C for reuse finding.

**A4. Question form and answer polarity — DEFECT (related to A1 overquantification)**

- **Original problem form:** "Does there exist r_k(d₁, d₂)?" or more generally, "Characterize the existence of r_k(d₁, d₂) for k ≥ 3." This is an open yes/no or characterization question.
- **Theorem encoding:** The statement is a bare proposition (no `answer()` wrapper), asserting the negation: "r_k does NOT exist." This is acceptable for direct-assertion form *if the claim is known*, but here the claim is unjustified as written.
- **Polarity:** Were the statement narrowed to a known case (e.g., k=3, d₁=2, d₂=3), the bare assertion of non-existence would be correct. As written for all k ≥ 3, it is not.

**A5. Solution status — DEFECT: status tag does not match formalization scope**

- The problem source status (metadata mirror, 2026-07-25): "open (Lean)" — meaning an open problem with a Lean formalization in progress.
- The theorem is presented as a direct assertion (`:= sorry`), not as an open conjecture.
- For this to be consistent: either (i) the theorem should be narrowed to a known case and tagged solved, or (ii) the theorem should acknowledge its claim as conjecture (e.g., via a docstring flag or a `conjecture` keyword in the statement, if Lean supports it).

## C. Craftsmanship

**C1. Readability — pass**

- **Names:** `kFoldSumset`, `StrictMono`, gap constraints are clear and standard. ✓
- **Docstrings:** The module docstring (lines 12–34) is detailed, well-structured, and accurately surveys known results. ✓

**C2. Reuse — DEFECT (duplicates Mathlib)**

- **kFoldSumset duplication:** The custom definition computes exactly the same value as Mathlib's `k • (Set.range A)` (scalar multiplication of a set in an additive monoid), available via `Mathlib.Algebra.Group.Pointwise.Set`. The docstring's recursive definition "0S = {0}, (k+1)S = S + kS" matches the Lean 4 `Nat.smul_def`.
- **Recommendation:** Replace `kFoldSumset k (Set.range A)` with `k • (Set.range A)` and remove the custom definition. This leverages Mathlib lemmas about `nsmul` and improves maintainability.
- **Broader context (from prior review):** At least 6 other Erdős problems (31, 35, 37, 337, 869, 871) define similar sumset operations locally. A codebase-wide effort to migrate to Mathlib's pointwise operations would be valuable but is outside the scope of this single review.
